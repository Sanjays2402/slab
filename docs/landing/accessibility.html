Why this matters

Section 508 (United States)

Every US federal agency must publish documents that conform to WCAG 2.1 AA. PDFs delivered to the public — forms, regulations, reports, RFPs — are required to be tagged. Untagged PDFs are an enforcement risk under the 2018 refresh.

European Accessibility Act

In force since 2025-06-28. Banking, transport, e-commerce, and ICT vendors selling to EU customers must publish accessible documents. The market is estimated at $400M/yr for PDF accessibility tooling alone.

EN 301 549 v3.2.1

EU public-sector procurement standard. References PDF/UA. A single non-conformant PDF on a government website can trigger a complaint to the national equality body and force a remediation contract.

AODA 2025 (Canada)

Ontario's deadline for WCAG 2.1 AA conformance on private-sector websites and documents passed in 2025. Slab's offline pipeline lets you tag a backlog of thousands of historical PDFs without sending any of them to a vendor cloud.

How Loom tags a PDF

The pipeline is seven ordered passes. Each is independently testable; all run locally with no network calls.

  1. extract — parse content streams, build a LayoutTree of text runs and image placements with font sizes and bounding boxes.
  2. classify — heuristic node typing: H1–H6 by font-size rank, P by body run, L/LI by bullet detection, Table by aligned columns, Figure by Do-XObject without text.
  3. reading_order — column detection (vertical strip clustering), then top-down left-to-right serpentine traversal.
  4. alt_text — for every Figure, optionally invoke local Ollama llava for a one-sentence alt description. Cached per image hash. Editable in the Review tab.
  5. structure_tree — emit PDF StructTreeRoot, ParentTree, RoleMap, and point StructParents from every page.
  6. metadata — set /Lang, /MarkInfo<<Marked true>>, /ViewerPreferences<<DisplayDocTitle true>>, XMP pdfuaid:part = 1, and document title.
  7. validate — run the Matterhorn Protocol 1.1 Auto subset and emit a structured LoomReport with PASS / WARN / FAIL per checkpoint.

Matterhorn coverage

The Matterhorn Protocol (PDF Association, 2021) is the industry-standard PDF/UA-1 ruleset. It defines 136 failure conditions across 31 sections. We classify each:

Auto · projected ≈ 68 / 136

Decidable from the PDF object model alone. Slab runs the check during the validate pass and emits PASS / FAIL without human review.

Human · projected ≈ 38 / 136

Requires judgement — e.g. "is this image decorative or does it carry meaning?" Surfaced in the Review tab with the offending node highlighted, so a reviewer can confirm or flag.

Out of scope (v3.1.0) · ≈ 30 / 136

Depends on Slab features not yet shipped — multimedia, complex form fields, signature subset. Each lands in a follow-on release; the checkpoint registry tracks them.

Slice 0 of Loom (committed today) transcribed 91 of 136 failure conditions into our canonical JSON registry. The remaining 45 will land as each validate section is implemented. Verdict assignments will be reviewed by an external accessibility consultant before v3.1.0 GA.

Why offline matters for accessibility

  • Confidential documents stay confidential. Legal filings, medical records, internal HR docs, and pre-publication research never leave the machine they were authored on. No cloud upload, no vendor data-processing agreement, no GDPR Article 28 paperwork.
  • Local alt-text via Ollama llava. Beacon's vision model runs in ~/.ollama. The figures in your PDFs are never sent to OpenAI, Anthropic, Google, or Adobe.
  • No outbound network traffic at all. tcpdump-verifiable on a fresh machine. Audit-friendly for environments where outbound traffic is firewalled.
  • Air-gapped friendly. Pull the installer once, install on isolated networks, run forever. SCIF-grade environments can use Slab where Acrobat's Document Cloud is a non-starter.

FAQ

When does v3.1.0 Loom ship?

Slice 0 (this ADR + the Matterhorn JSON registry) shipped today. The Rust pipeline (Slices 1–7) and Svelte UI (Slice 8) will land progressively across the next six weeks. The release-ready GA is planned for June 2026. Star the repo or subscribe to releases to get notified.

Will Slab pass Adobe's Accessibility Checker?

Yes — that is an explicit acceptance criterion. We validate during tagging (not just at the end) against the same Matterhorn Protocol that PAC 2024 and Adobe's checker derive from. A document Slab marks as PDF/UA-1 ✓ will pass both checkers on the first try, or the bug is in Slab.

What about PDF/UA-2?

PDF/UA-2 (ISO 14289-2:2024) just shipped and tooling is immature. Every procurement RFP from FY2024–FY2026 cites PDF/UA-1, not -2. We will add -2 in a follow-on release once the validator ecosystem catches up. -2 is a strict superset on the structure side, so the work is incremental.

Do I have to use the local AI for alt-text?

No. Beacon's Ollama llava is the default for unattended bulk tagging, but every alt-text is editable in the Review tab, and you can disable AI alt-text generation entirely in Settings → Accessibility. The Review tab will still flag every figure without alt-text so a human can type one.

Can Slab tag a backlog of thousands of historical PDFs?

Yes. Drag a folder onto Slab and the pipeline runs across every file. Output is written to a sibling folder so originals stay untouched. Performance budget: roughly 1.5–3 seconds per 20-page document on a 2024 laptop. A 5,000-document backlog takes a workday of background runtime.

Is Slab approved for federal use?

Slab is AGPL-3.0 source-available and reproducibly built. Your security team can review and self-build every release. Slab itself is not a FedRAMP/ATO product (it does not connect to government clouds), but its offline-first architecture means it does not require an ATO for most desktop deployments.
