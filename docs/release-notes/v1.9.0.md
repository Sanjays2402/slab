# Slab v1.9.0 "Voice Mode" 🔊

Release date: 2026-05-18

## Overview

**Voice Mode** brings text-to-speech to Slab Beacon. Highlight any answer,
selection, or summary, hit speak, and your platform's native TTS engine
reads it aloud — no cloud round-trip, no telemetry, no audio leaves your
machine.

This is the **TTS-first** half of Slice 15. Mic-input (STT) lands in
v1.9.1 once we've validated a cross-platform recording path.

## What's new

### Cross-platform TTS via native engines

Slab shells out to the right engine for your OS:

- **macOS** — `say` (Core Audio, ships with the system)
- **Linux** — `espeak-ng` (install via `apt`/`brew`/`dnf`)
- **Windows** — PowerShell `System.Speech.Synthesis.SpeechSynthesizer`

No bundled audio libraries, no extra runtime, no ffmpeg dependency. If
your platform default isn't available, Slab tells you exactly which
binary to install.

### Voice + rate selection

Every engine exposes its installed voices. Slab calls `say -v ?` /
`espeak-ng --voices` / PowerShell `GetInstalledVoices()` once at
capability-probe time and renders them in a dropdown. Speech rate is a
words-per-minute slider (engines clamp out-of-range values).

### Single-slot voice session

Press speak twice in a row and the second call kills the in-flight
utterance before starting. No queueing, no buffering, no "wait for the
robot to finish your last paragraph." Predictable, instant.

### Persisted voice settings

Your engine + voice + rate + auto-speak preference round-trip through
`~/.slab/config.toml` under `[beacon.voice]`. The section is **omitted
entirely** until you actually configure something — existing users see
zero churn in their configs after upgrading.

### Beacon Voice panel

New detachable panel (🔊 nav entry). Pop it into its own window like any
other Slab panel. Hosts:

- Engine selector + availability indicator
- Voice dropdown (populated per engine)
- Rate WPM slider
- "Test phrase" button (speaks a known-good sentence)
- Custom text speak box (for ad-hoc speakthrough)
- Apply (persist) button

### Tauri command surface

Six new commands for any panel/skill that wants to drive voice:

- `slab_beacon_voice_capabilities` — probe what's installed
- `slab_beacon_voice_list_voices` — enumerate voices for an engine
- `slab_beacon_voice_speak` — speak text (cancels prev)
- `slab_beacon_voice_stop` — hard stop current utterance
- `slab_beacon_voice_is_speaking` — UI state poll
- `slab_beacon_voice_test` — one-shot sanity check

## Under the hood

- `src-tauri/src/ai/voice.rs` — `TtsEngine` enum, capability probe,
  command builder, text sanitiser, error type. 20 unit tests, all
  exercising the command-builder rather than spawning processes (CI-safe).
- `src-tauri/src/ai/voice_session.rs` — `VoiceSession { current:
  Mutex<Option<Child>> }`, with kill-prev-on-speak. 5 unit tests.
- `src-tauri/src/ai/config.rs` — `VoiceConfig` with
  `skip_serializing_if = "VoiceConfig::is_empty"`. 5 new config tests
  pin the serde behaviour.

## Security

Text destined for shell-out is run through `sanitise_text`, which
replaces ASCII control chars (incl. `\x1b`) with spaces and caps length.
Belt-and-braces against LLM output that contains weird bytes.

## Known limitations

- **No STT yet** — landing in v1.9.1
- macOS-only Slab installer still lacks an `espeak-ng` bootstrap; Linux
  users currently install the engine themselves
- Voice list is cached per-app-launch (restart Slab if you install a new
  voice mid-session)
