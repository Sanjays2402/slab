# v0.9.0 "Toolkit"

**Theme:** The three utilities `pdftk`/`qpdf` users reach for most — flatten, sanitize, repair — native to Slab, pure Rust, zero external binaries.

## What's new

### `slab flatten` — bake interactivity into the page

Form fields and annotations get rasterized into each page's content stream so the output PDF has no editable layers. Pixel-identical visual output; interactivity gone. Standard pdftk `flatten` semantics, but done in-process via `lopdf` instead of shelling out.

How it works under the hood:
- For each page's `/Annots`, walk entries with an `/AP /N` Form XObject.
- Build a CTM mapping the Form's `/BBox` onto the annotation's `/Rect`.
- Register the form under a unique name in the page's `/Resources /XObject`, then append `q <ctm> cm /<name> Do Q` to the content stream.
- Drop `/Annots` on every page and remove `/AcroForm` from the catalog.

Edge cases handled: `/AP /N` may be a dict (state-keyed) instead of a stream — we pick the value matching `/AS`, else the first one. `/Annots` may be an indirect ref — we resolve before iterating. Form XObjects keep their own `/Matrix` untouched (the `Do` operator already handles it).

```bash
slab flatten editable.pdf -o flat.pdf
slab flatten editable.pdf -o flat.pdf --no-widgets   # keep form widgets
```

Tauri: `slab_flatten(input, output, opts: { include_widgets })` → `FlattenReport { pages_with_annotations, annotations_in, annotations_flattened, annotations_dropped, had_acroform }`.

### `slab sanitize` — make a PDF safe to forward

Strips:
- `/Names /JavaScript` (catalog-level JS action store)
- `/Names /EmbeddedFiles` (attachments)
- `/OpenAction` (auto-run on document open)
- `/AA` (additional-actions, on both catalog and pages)
- `/XFA` (XML Forms Architecture — scripting surface)
- Per-annot `/A` actions of type `/JavaScript`, `/Launch`, and (by default) `/URI`

Pixel-identical visual output. `--keep-links` keeps external URI annotations if you want navigation but no scripts/launches.

```bash
slab sanitize sketchy.pdf -o clean.pdf
slab sanitize sketchy.pdf -o clean.pdf --keep-links
```

Tauri: `slab_sanitize(input, output, opts: { keep_links })` → `SanitizeReport { js_removed, launch_removed, uri_removed, embedded_files_removed, open_action_removed, catalog_aa_removed, pages_aa_removed, xfa_removed }`.

### `slab repair` — rebuild xref + prune cruft

For "this PDF won't open in Reader" files and PDFs bloated by incremental edits. We load via `lopdf` (which is permissive about busted xref tables and rebuilds them by scanning the file body), prune unreachable indirect objects, compress streams, and save with a clean xref. Most of what "open in Acrobat and Save As" does, in-process.

```bash
slab repair busted.pdf -o fixed.pdf
# ✓ repaired: objects 412 → 318 (94 pruned), size 1.2 MB → 980 KB (-18.3%) → fixed.pdf
```

Tauri: `slab_repair(input, output)` → `RepairReport { objects_before, objects_after, objects_pruned, bytes_before, bytes_after }`.

Not a PDF validator. We don't fix malformed content streams or encrypted-but-no-key files. We do fix the broken-xref complaint that's actually the cause of most "won't open" failures.

## What we deliberately skipped (queued for v0.9.1+)

- **Decrypt UX** — the lib already has `pdf::encrypt::decrypt`; v0.9.1 will surface it via the Toolkit panel with a secure modal for the password.
- **Sign** — needs a PKCS#7 crate selection (lopdf-extensions vs cryptographic-message-syntax vs custom). Deferred to v0.9.2 pending human input on the dep.
- **PDF/A** — likely a Ghostscript shell-out for ICC profile embedding (same pattern as Polyglot's markitdown). Research first, ship in v0.9.3.
- **Frontend Toolkit panel** — backend + CLI + Tauri commands all ship in v0.9.0. The Svelte UI surface is queued; CLI users have everything they need today.

## Quality

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --lib` — all green.
- Test count: **90 → ~104** (9 flatten + 4 sanitize + 3 repair on top of the v0.8.1 baseline).
- Each module has dedicated unit tests covering the happy path plus the edge cases (annot/AP variants, every strip path independently, synthetic bloat with unreachable streams, missing-input rejection).
- Zero new Rust dependencies. Pure `lopdf`.
