# Slab v2.0.2 — Workshop Marketplace 🛍️

The **Workshop** release (v2.0.0) gave Slab a real plugin runtime.
**Bundled Hello Workshop** (v2.0.1) made fresh installs come with three
working example plugins out of the box.

v2.0.2 makes the **Plugin Store itself** feel like a product — not a
debug grid.

## What's new

**A real Plugin Store.** Open the Plugins panel, hit Browse, and you now
get:

- **Category chips** ("Productivity", "AI", "Developer", …) with live
  counts that filter the grid as you click.
- **Fuzzy search** with live `<mark>` highlighting across plugin name,
  description, tags, and author — type "hello" and watch "**Hello**
  Workshop" light up.
- **Sort dropdown** — Best match (default when searching), Most
  installs, Newest version, or A–Z by name.
- **Hero welcome card** on an empty Browse tab with one-click chips for
  the bundled example plugins.
- **Install-count badges** on popular plugins — only shown above the
  10-install threshold, so the store never reads "1 install" on a
  brand-new entry.

**Useful before you connect.** Slab now ships an embedded seed index.
The moment you open the Plugin Store — even with zero network access —
you see the three bundled plugins listed, categorized, and openable in
one click. A subtle banner tells you when you're looking at the embedded
seed vs. the live marketplace.

**A schema that won't lock us in.** Marketplace index `schema_version: 2`
adds four new optional fields to each entry — `categories`, `tags`,
`screenshots`, `installs` — all of which the new Browse UI surfaces
automatically. Existing v1-signed indices keep verifying unchanged. The
signing tool (`slab-sign-plugin`) accepts all four via CLI flags.

## Fixed

- **Windows installs no longer fail the bundled-plugin hash check.** The
  repo now pins line endings to LF for every byte-hashed format via a
  new `.gitattributes`, so the `include_str!` bytes match the manifest
  sha256 on every platform.
- **CI bundle resource resolution.** The embedded marketplace seed now
  lives inside `src-tauri/resources/` (tracked in git) instead of under
  the gitignored `assets/` tree, so a clean CI checkout always has the
  file Tauri's bundler expects.

## For plugin authors

If you ship a plugin, your `index.json` entry can now include:

```json
{
  "categories": ["productivity"],
  "tags": ["highlight", "annotation"],
  "screenshots": [
    "https://example.com/screenshot-1.png"
  ],
  "installs": 1247
}
```

All four are optional. The Plugin Store will surface them automatically
on every install — chips for `categories`, `#tag` pills for `tags`, an
`⬇ 1.2k`-style badge when `installs >= 10`, and (in a future point
release) a screenshot carousel inside the plugin detail drawer.
