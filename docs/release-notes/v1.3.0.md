# Slab v1.3.0 — Foundry 🛠

**Slab becomes extensible.** Foundry is a declarative plugin system that lets anyone add themes, languages, commands, AI providers, and PDF actions to Slab — without compiling Rust, without writing native code, without us re‑shipping a binary. Drop a folder into `~/.slab/plugins/`, write a `plugin.toml`, restart Slab, done.

This is the largest single architectural addition since Beacon (v0.10). 12 vertical slices, 539 tests, end‑to‑end from manifest parser to a fully wired Settings panel.

## What you can ship as a plugin

Five contribution kinds. All declarative. All loaded at boot.

| Kind | What it does | Backed by |
| --- | --- | --- |
| **Theme** | Override CSS variables to restyle Slab. Listed in the theme picker and the command palette. | Plain CSS file in `themes/`. |
| **Locale** | Add or partially override an interface language. Merged into Slab's i18n bundles at boot. | JSON file in `locales/`. |
| **Command** | Run a shell command or open a URL from the command palette. Toast feedback on success / failure. | TOML entry; shell strings go through Slab's quoting‑aware tokenizer. |
| **AI provider** | Register an OpenAI‑compatible endpoint (e.g. local Ollama, LM Studio, a remote model). Appears in Beacon's provider list. | TOML entry; talks the OpenAI Chat Completions wire format. |
| **PDF action** | A reader‑toolbar dropdown entry that pipes the open PDF through a CLI (`qpdf`, `gs`, `pdftk`, anything) with `{in}`/`{out}` placeholders. | TOML entry; Slab handles temp files + timeout. |

## How it works (the honest version)

- **Discovery.** Boot scans `~/.slab/plugins/*/plugin.toml`. Each manifest is parsed with `serde` + validated (semver version, unique IDs, contribution sanity).
- **Registry.** A `PluginRegistry` keeps a map of `plugin_id → Plugin`, plus enabled/disabled state persisted in `~/.slab/plugins.enabled.json`.
- **Tauri commands.** 13 commands: `list_plugins`, `set_plugin_enabled`, `reload_plugins`, `plugin_theme_css`, `plugin_locale_bundle`, `run_plugin_command`, `run_plugin_pdf_action`, `list_plugin_ai_providers`, plus introspection helpers.
- **Frontend wiring.** A Svelte store subscribes to the registry; themes are injected as `<style>` tags, locale bundles are merged into the i18n runtime, commands appear in `⌘K`, AI providers in Beacon, and PDF actions in the reader toolbar dropdown.

## The control surface

A new **Settings → Plugins** panel lists every discovered plugin with:
- Name, version, author, plugin id, description from manifest
- Per‑plugin enable/disable toggle (optimistic UI)
- Red **"Manifest error"** chip + collapsible raw parse error when a manifest is malformed (with the on‑disk dir)
- Contribution count chips: `3 themes · 1 locale · 2 commands`
- Expandable drilldown listing every contribution by ID + label (debugging aid)
- Toolbar: **📁 Open plugins directory** + **↻ Reload**
- Empty state with the absolute plugins‑dir path + open‑dir CTA

Plus a command palette entry — `Open Settings → Plugins` — with wide keyword coverage so you can `⌘K plug`, `⌘K theme`, `⌘K extension`, `⌘K ai` and land in the right place.

## Try it: `hello-slab`

Ship with the source: `examples/plugins/hello-slab/` — a working example exercising **all five contribution kinds**:

- A **Midnight** dark‑blue theme
- A **Japanese (jp)** locale with 40 translated keys
- A **URL command** that opens Slab's GitHub
- A **shell command** that runs `echo`
- An **Ollama AI provider** pointing at `localhost:11434`
- A **qpdf‑linearize** PDF action with `{in}`/`{out}` placeholders

A unit test (`example_hello_slab_manifest_parses`) loads the shipped manifest through Slab's own parser and asserts every contribution count. If we ever break the manifest schema, this test fires and forces us to update the example. **Docs stay honest.**

```bash
mkdir -p ~/.slab/plugins
cp -R examples/plugins/hello-slab ~/.slab/plugins/
# restart Slab — see "hello-slab" in Settings → Plugins
```

## Security model — the part no marketing copy mentions

Foundry plugins run **with Slab's permissions**, not in a sandbox. A `command` plugin can execute any shell program the user can. A `pdf_action` plugin can pipe your open PDF through any CLI on PATH. This is intentional (we don't want to ship a half‑working sandbox that lulls users into trusting random TOML files), but it means:

- **Treat plugins like you'd treat a `bash` script you downloaded.** Read the manifest before enabling.
- The Settings → Plugins panel shows you the raw on‑disk path of every plugin so you can `cat` it before flipping the toggle.
- A future Foundry minor will likely add a signed‑manifest install flow with a marketplace UI. For now: install from sources you trust.

## What's NOT in here (parked for v1.3.x)

- **Plugin marketplace UI** — discover + install signed plugins from a central registry.
- **AI provider hot‑swap** — letting Beacon switch between plugin‑contributed providers mid‑chat without a restart.
- **TypeScript plugins** (full JS API) — Foundry intentionally stays declarative for v1.3; a `script.js` contribution kind is on the table for a later major.

## Upgrading

No data migration. Drop in the new binary or reinstall from the appropriate installer below.

Plugin authors: read `docs/PLUGINS.md`, copy `examples/plugins/hello-slab/`, write your manifest. Open `~/.slab/plugins/` straight from Settings → Plugins.
