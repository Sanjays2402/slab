# v0.9.1 "Toolkit UX"

**Theme:** The v0.9.0 backend powers (flatten, sanitize, repair) get first-class Svelte panels in the sidebar, and the Reader stops choking on password-protected PDFs.

## What's new

### Toolkit panels in the sidebar
Three new entries on the left rail, each backed by the existing CLI / Tauri commands shipped in v0.9.0:

- **Flatten** — bake form fields + annotations into the page contents. Keep-widgets toggle exposed. Surfaces the full `FlattenReport` (annotations in/flattened/dropped + had-AcroForm).
- **Sanitize** — strip JavaScript, Launch actions, embedded files, OpenAction, AA, XFA, and (by default) URI annotations. `--keep-links` exposed as a checkbox. Surfaces the eight-counter `SanitizeReport`.
- **Repair** — rebuild xref + prune unreachable objects. Surfaces the `RepairReport` with object count delta, byte delta, and percent reduction.

Pattern matches the rest of the v0.8.x panels: pick file → choose output → run → toast result. No new icons; nav uses the existing icon set.

### Decrypt-on-open flow
Slab no longer falls over when you drag in a locked PDF.

The Reader's `loadBytes` now catches `pdf.js`'s `PasswordException` and pops a **DecryptModal** instead of stuffing the raw error into the load banner. The modal:

- Takes the password (with show/hide toggle), Enter to submit, Esc to cancel
- Routes through the existing `slab_decrypt` Tauri command (which itself wraps `pdf::encrypt::decrypt`)
- Writes a plaintext copy to OS temp (`{tempDir}/slab-unlocked-{name}-{stamp}.pdf`)
- Loads the unlocked copy back into the Reader on success
- Converts library "Invalid password" / "InputMissing" errors to UX-grade text

Zero new Rust code — this is purely a UX wiring tick that surfaces the v0.8.x `pdf::encrypt::decrypt` lib that's already covered by round-trip tests.

```
[locked.pdf]
     │
     ▼  pdf.js throws PasswordException
DecryptModal prompts for password
     │
     ▼  slab_decrypt(input, output, password) → CmdResult<()>
[$TMPDIR/slab-unlocked-locked-<stamp>.pdf]
     │
     ▼  loadPath()
Reader opens the plaintext copy
```

## What we deliberately skipped

- **Auto-cleaning the temp unlock copy** when the doc closes. Tradeoff: keeping it means re-opening the locked file in the same session doesn't re-prompt, which is the more common workflow. Tempdir gets garbage-collected by the OS.
- **Recents listing the original locked path instead of the unlocked-temp path.** Cosmetic; will revisit when v0.10.0 lands the document store rework.
- **Sign + PDF/A panels.** v0.9.0 deliberately deferred the backends; UX has nothing to wire yet.
