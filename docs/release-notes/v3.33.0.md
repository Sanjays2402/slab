# Slab v3.33.0 — Atlas Smart

**Smart Collections, now with a real builder.**

Build a "Recent invoices" or "Untagged scans" collection without writing a
single line of JSON. Drag any doc card onto a collection in the sidebar to
add it instantly. Watch the count badge pulse the moment a freshly-scanned
PDF lands in "Recently added."

## ✨ What's new

- **Visual Smart Collection builder** (⌘⇧N / Ctrl+Shift+N) — a side-by-side
  modal with name, icon (12 glyphs), color (8 swatches), repeating filter
  rules (Title contains / Tag is / Folder is), sort order, and a **live
  preview pane** that re-runs against your library as you type. The match
  count badge pulses every time the result set changes.
- **Drag-to-collection** — pull any doc card from the library grid and drop
  it onto a manual collection row in the left rail. The drop target lights
  up with a dashed glass outline; on release, a small toast confirms the
  add.
- **Smart collections politely refuse** drops with a rose-tinted "blocked"
  outline and a toast: _"Smart collections auto-update — edit the rules to
  change membership."_ One less footgun.
- **Right-click any smart collection** for an inline menu: Edit rules… /
  Delete. Double-click a row to jump straight into the editor.

## 🛠️ Under the hood

- New `update_smart_collection` backend in `pdf::library::collections` — a
  partial-update helper that lets the builder rename / re-icon / re-color
  / re-filter without delete-and-recreate (which used to shift `sort_order`).
- New `slab_smart_collection_update` Tauri command with a tri-state JSON
  patch (omitted / null / value) so callers can clear nullable columns
  explicitly.
- `SmartCollectionBuilder.svelte` is fully self-contained — uses the
  Liquid Glass design tokens, debounces preview reruns at 250ms, and
  hydrates from `query_json` when editing an existing collection.

## 📌 Today's scope

This release supports **AND across the three predicates we ship today**
(`title_substring`, `tag_ids`, `folder_id`). NOT and OR rules land in
v3.34.0 — the builder UI is already structured to grow without breaking
existing collections.

## 🗃️ Compatibility

No database migration needed. Existing smart collections (including the
two seeded defaults, "Recently added" and "All documents") work unchanged
and can be edited in the new builder.
