# v0.8.1 "Polyglot"

**Theme:** Slab eats more than PDFs.

## What's new

- **Polyglot input bridge.** A new `pdf::polyglot` module that converts non-PDF
  inputs into PDFs by extracting Markdown via Microsoft's
  [`markitdown`](https://github.com/microsoft/markitdown) CLI and rendering
  through the existing `md2pdf` engine.

  Supported source formats:
  - Office: `.docx` `.xlsx` `.pptx` `.xls`
  - Web / structured text: `.html` `.htm` `.csv` `.json` `.xml` `.rtf` `.odt`
  - Books: `.epub`
  - Images (EXIF + OCR text): `.png` `.jpg` `.jpeg` `.gif` `.bmp` `.tif`
    `.tiff` `.webp`
  - Audio (EXIF + transcription): `.wav` `.mp3` `.m4a` `.flac` `.ogg`

- **CLI subcommand:** `slab polyglot <file> -o <out.pdf> [--page-size A4|Letter|Legal]`.
- **Tauri command:** `slab_polyglot(input, output, opts: { page_size })` →
  `{ source_kind, pages, markdown_bytes }`.
- **Open-file UI** now accepts the full polyglot extension list (see Task 10
  rollout — frontend wiring lives in v0.8.1 too).

## How it works

```
input.{docx,xlsx,…}
        │
        ▼  markitdown <input>   (subprocess, captures stdout)
   Markdown (UTF-8 String)
        │
        ▼  pdf::md2pdf::render
     PDF on disk
```

Zero new Rust dependencies. We shell out to `markitdown` exactly the way
`pdf::ocr` shells out to `tesseract` / `pdftoppm`; the same gating pattern
(`markitdown_available()`) means live integration tests skip cleanly on dev
machines without the binary installed.

## Install hint

Install `markitdown` once per user:

```bash
pipx install 'markitdown[all]'      # recommended (isolated venv)
# or
pip install 'markitdown[all]'
```

Slab still handles PDF input out of the box without it; only the polyglot
formats require the optional dependency.

## Error model

All failures map to typed `PdfError` variants so the UI / CLI can render
friendly messages:

| Condition                       | Variant                                            |
| ------------------------------- | -------------------------------------------------- |
| Input file missing              | `PdfError::InputMissing(path)`                     |
| Unsupported extension           | `PdfError::Other("unsupported polyglot input: …")` |
| `markitdown` not on `$PATH`     | `PdfError::Other("markitdown not found … pipx …")` |
| `markitdown` non-zero exit code | `PdfError::Other("markitdown failed (<n>): <err>")`|
| Non-UTF-8 stdout                | `PdfError::Other("markitdown produced non-UTF-8 …")`|
| Empty Markdown                  | `PdfError::Other("markitdown returned empty …")`   |

The "binary not found" message names the binary, names `PATH`, and points at
the canonical install command. That's covered by a regression test.

## What we deliberately skipped

- **PDF → PDF round-tripping.** Lossy. Refused at the extension allow-list.
- **YouTube URLs / web fetches.** Out of scope for an offline-first app.
- **ZIP recursion.** UX-heavy; queued for a later release.
- **Azure Document Intelligence path.** Paid; opaque; offline-hostile.
- **Bundling `markitdown` inside the installer.** User-installed via `pipx`
  keeps the Slab bundle small and avoids Python runtime headaches.
