# v1.4.0 — Bench 🪑

> Plugins, but with provenance. v1.3 gave us the **Foundry** —
> declarative plugin manifests. v1.4 gives us the **Bench**: a curated,
> *signed* index of plugins users can discover and install in one click,
> without ever opening a terminal.

This closes the Foundry story. The hand-author path is still there for
power users, but a non-developer can now browse Slab's marketplace,
install a plugin, see "update available" badges, and uninstall safely
— all from **Settings → Plugins → Browse**.

## What's new

### 🪑 Plugin marketplace (Browse tab)

A new **Browse** tab on the Plugins panel lists every plugin in Slab's
curated index. Each entry shows icon, name, version, author,
description, and an **Install** button. Click an installed plugin to
see its detail drawer — readme, contributions, on-disk path, and an
**Uninstall** button.

### 🔐 Signed index entries (Ed25519)

Every plugin in the index is signed with the Slab maintainer's
Ed25519 key, baked into the binary. Before install, Slab:

1. Verifies the index entry's signature against the embedded public key.
2. Downloads the tarball.
3. Verifies the tarball's SHA-256 matches the signed `manifest_sha256`.
4. Extracts to `~/.slab/plugins/<id>/` and triggers a registry reload.

If any step fails, install is aborted with a clear error and nothing
is written. **Provenance** end-to-end: the bytes you get are the bytes
the maintainer signed.

> **Trust model** — we sign *index entries*, not tarball contents. The
> entry binds plugin ID + version + tarball hash to the maintainer's
> signature. There's still no sandbox *inside* a plugin (same as
> Foundry), so Bench gives you **who shipped it**, not **what it can
> do**. Treat plugins like Bash scripts from a vendor you trust.

### 🆕 Update available badges

When the index advertises a newer version of an installed plugin, the
**Installed** tab shows an "Update available" badge with the new
version. Updating is a regular install of the new version — old
contributions unregister, new ones register, no restart needed.

### ⚠️ Uninstall confirmation modal

Uninstall now opens a confirmation modal (mirrors `DecryptModal`
styling) showing plugin name, version, and on-disk path. Prevents
fat-fingered destructive clicks. If the open detail drawer is the
plugin being removed, the drawer auto-closes.

### 🌐 Offline-friendly

The fetched index is cached to `~/.slab/marketplace-cache.json`. Open
Slab on an airplane and the Browse tab still shows the last seen
marketplace (with a stale-cache indicator).

### 🛠 Maintainer tooling — `tools/sign-plugin/`

A new CLI for the marketplace maintainer (Sanjay, today; perhaps a
team tomorrow). Reads an `index.json` draft, signs each entry with a
local Ed25519 secret key, writes the signed `index.json` ready to
commit to `Sanjays2402/slab-plugins`.

```bash
cargo run -p slab-sign-plugin -- \
  --key ~/.slab-maintainer/ed25519.key \
  --in  drafts/index.json \
  --out index.json
```

### 📖 Marketplace docs

- [`docs/MARKETPLACE.md`](../MARKETPLACE.md) — 340-line guide for both
  authors (how to get your plugin listed) and maintainers (how to
  sign + publish the index).
- [`docs/marketplace-seed/`](../marketplace-seed/) — drop-in payload
  for the future `Sanjays2402/slab-plugins` GitHub repo.

## What's the same

Everything from v1.3.1 still works exactly as before. Hand-authored
plugins from `~/.slab/plugins/` still load. Foundry contribution kinds
(themes, locales, commands, AI providers, PDF actions) are unchanged.
The only difference is now there's a second way to *get* a plugin
into that folder.
