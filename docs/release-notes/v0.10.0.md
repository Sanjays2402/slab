# v0.10.0 "Beacon" 🔆

**Theme:** Slab becomes the **first AI-native local PDF editor.** Five user-visible Beacon features, all powered by a pluggable provider abstraction (Ollama default, OpenAI-compatible fallback). Local-first, private by default, free.

> **The pitch:** Stirling-PDF features locally, Liquid Glass UI, and now you can chat with your PDFs without sending them anywhere.

## What's new

### ✦ Beacon Chat — Q&A with the open PDF
A new sidebar panel: pick a PDF, ask a question, get an answer with `[pN]` page citations. Citation chips are clickable — they jump the Reader to the cited page.

- **Per-PDF context**: the open document's full text is page-bucketed and inlined into the prompt, with page-aware truncation (~30K chars by default; configurable per-call)
- **Conversational**: prior turns are preserved across questions
- **Sample prompts** on the empty state ("Summarize the main argument", "What does this say about X?", "What are the limitations?")
- **Friendly errors** — if Ollama isn't running, the panel tells you how to start it or switch provider, instead of vomiting a stack trace

Tauri command: `slab_beacon_chat`. 7 unit tests via in-memory MockProvider.

### ✦ Beacon Summary — TL;DR / Short / Long
Three quick-action chips inside the chat panel: **TL;DR** (one sentence), **Summarize** (one paragraph), **Detailed** (five bullets). Results land as assistant turns, so follow-up questions work conversationally.

Backend uses low temperature (0.1) + per-length token budgets (80 / 400 / 800) for stable, length-respecting output. The prompt explicitly forbids "this PDF" / "the document" framing — just facts.

### ⌕ Beacon Search — semantic search across opened PDFs
A new sidebar panel: index any PDF (chunks paragraph-first, embeds via `nomic-embed-text` or `text-embedding-3-small`, stores in sqlite at `~/.slab/beacon-index.sqlite`), then search by meaning across the whole library or this PDF only.

- **Idempotent re-index** by content SHA-256 — re-indexing is a no-op if nothing changed
- **Top-K cosine similarity** with brute-force in-process scoring (microseconds per query for a typical library)
- **Hit cards** showing page chip + filename + similarity % + matched chunk preview; click to jump to the page
- **Stats card**: total PDFs indexed, total chunks, on-disk size
- **Forget** button per-PDF clears its embeddings

Backend modules: `ai::chunker` (page-aware, paragraph-first, UTF-8-safe) + `ai::embedding_index` (rusqlite). 22 unit tests via in-memory MockEmbedProvider.

### 🔒 Beacon PII Redact — one-click prep for safe sharing
A new sidebar panel: scan the open PDF for personal information, review the hits, and one-click redact them with the existing `pdf::auto_redact` blackout pipeline.

- **Regex pass** for emails, SSNs, phone numbers, credit cards — reuses the v0.8.x `auto_redact` presets
- **Optional AI pass** (toggle) for names + addresses — uses the configured provider, JSON-extracts hits per page
- **Custom regex patterns** field for org-specific identifiers
- **Colored kind pills** (Email green, SSN red, Phone blue, etc.)
- **Click-to-jump** on any hit jumps the Reader to that page
- **One-click "Redact selected → save as new PDF"** — produces a black-bar redacted copy in one step

17 unit tests via in-memory MockProvider.

### ✦ Selection Actions — floating LLM bubble on text highlight
Highlight any text in the PDF Reader. A small floating bubble appears with five buttons:

- **Translate** (inline target-language picker, 15 common languages)
- **Explain** (plain-English, 2-4 sentences)
- **Define** (single-sentence dictionary definition)
- **Rewrite** (clearer phrasing, same meaning)
- **Summarize** (one-sentence TL;DR of the snippet itself)

Result appears in the same bubble with a **Copy** button. Liquid-glass dark styling, 90ms fade-in. Esc / outside-click / Back button all dismiss. No new sidebar nav — it lives inline in the Reader where it belongs.

Hard-capped at 8K-char selections (longer = use the chat panel). Per-action prompts pinned in tests, low temperature (0.2), per-action token budgets (Define=120, Translate/Rewrite=400, Explain=500, Summarize=150).

Tauri command: `slab_beacon_selection_action`. 13 unit tests via in-memory MockProvider.

### ⚙ Pluggable AI provider — Ollama default, OpenAI-compatible fallback
A new `~/.slab/config.toml` with `[beacon]` section: provider, chat_model, embed_model, base_url, api_key_env. Settings panel in the UI lets you switch providers without touching code.

- **`OllamaProvider`** — hits `http://localhost:11434/api/chat` + `/api/embeddings`. Default. Free, local, private. Models: `llama3.2:3b` (chat), `nomic-embed-text` (embed).
- **`OpenAiCompatibleProvider`** — configurable base_url + api_key. Works with OpenAI, GitHub Copilot's OAuth-gated proxy, Anthropic via proxy, any local OpenAI-compatible server (llama.cpp, vLLM, LM Studio).

4 Tauri commands: `slab_beacon_config_read`, `slab_beacon_config_write`, `slab_beacon_provider_test`, `slab_beacon_provider_kinds`.

All HTTP calls covered by `mockito` unit tests — no real Ollama in CI.

## Upgrade notes
- **No breaking changes** to existing CLI / Tauri commands. Everything new is additive under `slab_beacon_*`.
- **Optional**: install Ollama (`brew install ollama` or [ollama.com](https://ollama.com)) and pull `llama3.2:3b` + `nomic-embed-text` to use Beacon offline. The UI gracefully falls back to an "AI provider not reachable" message if Ollama isn't running.
- **Config file** (`~/.slab/config.toml`) is created on first save; defaults to local Ollama.
- **Embedding index** lives at `~/.slab/beacon-index.sqlite` and is created on first index. Safe to delete; will be rebuilt on demand.
