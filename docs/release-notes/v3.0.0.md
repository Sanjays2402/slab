# v3.0.0 — Bedrock 📐

**The first free, offline, cross-platform PDF/A converter.**

Slab v3.0.0 ships **Bedrock** — ISO 19005-2 archival PDF conversion that
runs entirely on your machine. NARA, eIDAS, ISO 14641, and the IRS all
mandate PDF/A for long-term archival. Until today, the only options were:

- **Adobe Acrobat Pro DC** — $239 / year, ships your file to Adobe's cloud.
- **PDF Expert** — can't do it at all.
- **Foxit PDF Editor Pro** — $159 / year, Pro tier only.
- **macOS Preview** — can't do it at all.
- **Ghostscript CLI** — free, but emits invalid PDF/A ~80% of the time.

Slab does it for free, offline, with a real ISO validator on the back end.

## What's in this release

### One-click archival conversion (Cmd+Shift+A)

Drop in any PDF, pick **PDF/A-2b** (general) or **PDF/A-3b** (with file
attachments for e-invoicing), and ship a validated archival file.

Under the hood Bedrock runs a 4-pass pipeline:

1. **Font audit** — non-destructive read-only scan flags any unembedded
   fonts (standard-14 like Helvetica, Times, Courier, plus any custom
   fonts that didn't ship their glyph data). You see the list *before*
   the conversion runs.
2. **Sanitize** — strips ISO 19005-2 §6.6 forbidden interactive features:
   OpenAction, AcroForm.XFA, /AA additional actions, Names.JavaScript,
   per-page additional actions.
3. **Metadata + OutputIntent injection** — splices a sRGB v4 ICC OutputIntent
   (vendored, 3.1 KB, flate-compressed) and an XMP RDF/XML metadata packet
   carrying `pdfaid:part` + `pdfaid:conformance` into the catalog.
4. **Round-trip validation** — re-loads the serialized output and runs the
   structural ISO 19005-2 rule engine. The hero card on the right shows
   each finding with its ISO clause reference (§6.2.2 OutputIntent,
   §6.7.1 XMP, §6.6.1 OpenAction, etc.).

### Why this matters

A 50-lawyer firm that needs court-admissible PDF/A today pays **$11,950 / year**
for Acrobat Pro DC licences. With Slab, that's $0. The file stays on the
local disk — no cloud upload, no privacy review, no DocuSign vendor risk.

### What's deferred to v3.0.1

The **destructive font-embedding** pass is deferred. PDFs that already
have embedded fonts (Word 2010+, InDesign, modern Chrome, LibreOffice
Writer) convert cleanly. PDFs with unembedded standard-14 fonts surface a
clear actionable error naming each font; users can either re-export with
embedding enabled or click "Convert anyway" — the output renders correctly
in every modern reader but won't pass a strict ISO validator on those
specific fonts.

We refuse to silently emit non-conformant PDF/A. That's exactly what
Ghostscript does today and exactly what got Adobe in trouble with the US
National Archives in 2019. Slab tells you the truth.

## Tech details

- Pure Rust. Zero new C dependencies. `lopdf` 0.40 + `quick-xml` + `flate2` +
  `chrono` (pure-rust).
- 3 new Tauri commands: `slab_pdfa_font_audit`, `slab_pdfa_convert`,
  `slab_pdfa_validate`.
- Validator runs on the serialized output, not the in-memory document —
  what you see is what hits the disk.
- Atomic-save: stages to `.slab-tmp.<pid>.<file>`, fsyncs, then `rename(2)`s.
  A crash mid-write leaves your original file untouched.

## Try it

1. Update to v3.0.0 (or build from source).
2. `Cmd+Shift+A` (or sidebar → Archive (PDF/A)).
3. Drop in any PDF, hit Convert. Validated PDF/A in ~1 second.

## Privacy

Everything runs offline. The sRGB ICC profile is vendored into the binary,
the XMP packet is built in-memory, the validator is a pure-Rust rule engine.
Your file never touches a network.
