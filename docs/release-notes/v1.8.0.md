# Slab v1.8.0 — "Glossary" 📖

The next Beacon AI tool in the sidebar: **Glossary**. Slab scans the document body for jargon candidates with a small set of high-precision patterns (capitalised multi-words, ALL-CAPS acronyms, *italic* term-like spans, parenthetical acronym definitions), asks the LLM to write a concise one-line definition for each, validates the result, and caches the whole thing next to the PDF as a JSON sidecar so the second open is instant. The panel renders the glossary as a filterable, copyable list — perfect for getting a quick lay of the land on a paper full of unfamiliar terms.

This is **Beacon Bonus Slice 14**, the fourth slice of the post-Bench "quick AI wins" track. Same pipeline as the rest of Beacon (extract → detect → LLM → liberal JSON → validate → cache → render) and shares all the existing infrastructure (extraction, chunking, embedding hash, LLM client, validator helpers).

## What's new

### 📖 Glossary panel in the sidebar

- New sidebar entry: **📖 Glossary** (sits with the other Beacon AI tools)
- Pick a PDF (or inherit from the Reader via `slab:open-recent`), click **Build glossary**
- Cache-first UX — if a sidecar already exists for this PDF, it loads instantly; otherwise the build pipeline runs
- LLM definitions are one line, source-faithful, and per-term capped so a 200-page paper doesn't produce a 5000-term wall
- Filter chips (`All`, `Acronyms`, `Phrases`, `Italics`) plus a free-text filter input
- Copy-to-clipboard on each row (`term — definition`) and a **Copy all** affordance
- **Clear cache** button rebuilds from scratch — useful after edits to the source PDF

### Architecture

- **`ai::glossary`** — full pipeline: candidate detection (4 regex patterns) → cap → LLM definition → liberal JSON parse → validate → dedupe → return. 13 tests covering each detection pattern, the validator, dedupe, and the cap.
- **`ai::glossary_cache`** — JSON sidecar cache at `~/.slab/glossary/<pdf-hash>.json`, schema-versioned. 5 tests covering load / save / clear / round-trip / corrupted-cache fall-through.
- **3 Tauri commands**: `slab_beacon_build_glossary`, `slab_beacon_load_glossary_cache`, `slab_beacon_clear_glossary_cache` — all hashed per-PDF via the reused `EmbeddingIndex::hash_file`.
- **`BeaconGlossaryPanel.svelte`** — Svelte 5 ($state runes), pick PDF + cache-first load + build + filterable list UI with chips, copy actions, and jump-to-page click events.
- Detach-window support: added to `DETACHABLE_PANELS` so you can pull Glossary into a separate window.

## Why this matters

A 60-page paper full of unfamiliar jargon is a wall the moment you open it. Glossary turns that wall into a checklist: every domain term + acronym gets a one-line gloss the LLM writes from context, the result is cached so re-opens are instant, and you can scan or filter the whole vocabulary before you start reading. Combined with Study Mode and Citations from earlier Beacon slices, the Beacon sidebar is now a pretty serious reading toolkit — extract → understand → remember, all without leaving Slab.
