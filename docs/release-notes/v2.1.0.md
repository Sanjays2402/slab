# Slab v2.1.0 — Slab Server 🐳

**The same Rust core, now Docker-deployable.**

Slab has always been a desktop app. v2.1.0 cracks it open: the same PDF
operations that drive merge, split, compress, watermark, encrypt, and
the rest are now exposed over a small HTTP API and a drag-drop web UI,
distributed as a `~80 MB` Docker image. Run it on a NAS, in a
docker-compose stack, in front of a reverse proxy on your homelab — your
PDFs still never leave your machine.

## Why

Users on the desktop installers asked for two things over the last
month: a way to script Slab from cron jobs and CI pipelines, and a way
to run it on a headless homelab box and share it across a household
without spinning up a Windows VM. v2.1.0 answers both with one binary:
`slab-server`.

> **The desktop app is unchanged.** v2.1.0 desktop installers ship the
> same eight-pillar PDF toolkit you already use. The server is a
> separate opt-in image (`ghcr.io/sanjays2402/slab`); the desktop
> installers don't bundle it, and the server image doesn't bundle the
> GUI.

## What's in the box

### `slab-server` HTTP daemon (new)

Single Rust binary, statically linked, axum-powered. 14 operations
under `/api/v1/*`:

```
POST /api/v1/merge
POST /api/v1/split-every
POST /api/v1/split-ranges
POST /api/v1/rotate
POST /api/v1/delete-pages
POST /api/v1/reorder-pages
POST /api/v1/compress
POST /api/v1/encrypt
POST /api/v1/decrypt
POST /api/v1/watermark
POST /api/v1/extract-text
POST /api/v1/info
POST /api/v1/page-count
POST /api/v1/strip-metadata
GET  /api/v1/ops
GET  /healthz
```

Every operation takes `multipart/form-data`, returns either
`application/pdf`, `application/zip`, `application/json`, or
`text/plain`. No auth (run it behind a reverse proxy), no rate
limiting, no per-tenant isolation — designed for trusted networks.

### Embedded drag-drop UI

`GET /` returns a self-contained dark-themed HTML page. Pick an
operation, drop a PDF, run. No build step, no separate frontend
container, no JavaScript runtime needed in the image.

### Docker + Compose

```bash
docker run --rm -p 8080:8080 ghcr.io/sanjays2402/slab:latest
```

The repo ships a hardened [`docker-compose.yml`](https://github.com/Sanjays2402/slab/blob/main/docker-compose.yml)
with read-only root FS, dropped Linux capabilities, healthcheck wired
up, and a named volume for persistent data.

### Multi-arch story

v2.1.0 ships **`linux/amd64`** only. `linux/arm64` is held back behind
QEMU cross-compile times (~12 min per arch on free GitHub runners);
it'll land in v2.1.1 once a self-hosted aarch64 builder comes online.

## What's NOT in v2.1.0 (and why)

Honest list — these were considered and deliberately deferred:

- **OCR over HTTP.** Tesseract needs a +150 MB bundle. Coming as an
  opt-in `ghcr.io/sanjays2402/slab:ocr` variant in v2.2.0.
- **AuthN/AuthZ in-binary.** A built-in password would make people
  think it's safe to expose to the internet. The right answer is a
  reverse proxy with OIDC/basic-auth, and the docs say so loudly.
- **Persistent job queue.** Every request is currently synchronous.
  Long compresses hold the connection. Async + polling lands in v2.2.0.

## Compatibility

- **Desktop installers:** identical UX, identical features, identical
  data layout to v2.0.2. Drop-in upgrade.
- **Plugins / Workshop API:** no changes. v2.0.0 plugins continue to
  work unmodified.
- **Marketplace index:** signing key unchanged; existing entries
  continue to verify.

## Install / upgrade

### Desktop (unchanged from v2.0.2)

Grab the installer for your platform from the assets below — DMG for
macOS (Intel + Apple Silicon), DEB / AppImage for Linux, MSI / EXE for
Windows.

> macOS Gatekeeper note: builds are still ad-hoc signed. After the
> first launch, right-click → Open to bypass the unknown-developer
> warning. Developer-ID notarization infrastructure is in
> [`.github/workflows/build.yml`](https://github.com/Sanjays2402/slab/blob/main/.github/workflows/build.yml)
> and gated on six Apple secrets; enroll the project in the Apple
> Developer Program ($99/year) to flip it on. Tracked separately.

### Server

```bash
# One-shot
docker run --rm -p 8080:8080 ghcr.io/sanjays2402/slab:v2.1.0

# Persistent + restart policy
docker run -d --name slab \
  --restart unless-stopped \
  -p 8080:8080 \
  -v slab_data:/var/lib/slab \
  ghcr.io/sanjays2402/slab:v2.1.0
```

Open <http://localhost:8080>. Full configuration reference, security
model, and curl examples in [docs/server.md](https://github.com/Sanjays2402/slab/blob/main/docs/server.md).

## Verifying installers

SHA256 sums for every installer asset are listed inline below. To verify

```bash
shasum -a 256 -c <(grep <installer-name> SHASUMS256.txt)
```
