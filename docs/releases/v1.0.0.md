# Slab v1.0.0 — Glass 🪟

**Released:** 2026-05-17

This is **Slab 1.0** — the first stable release. The version pill in the
sidebar finally drops the `v0.x` prefix that's been there since day one,
and the API surface (Tauri commands, config schema, on-disk formats)
freezes. Anything you build against 1.0.0 keeps working.

This release isn't a big new feature pack — those were v0.10 through
v0.15 (Beacon, Lathe, Atlas, Lens, Stack, Theater). **Glass is the polish
release** that turns a bag-of-features into a product: a coherent
settings system, a memorable command palette, customisable keyboard
shortcuts down to the keypress, toast notifications instead of silent
failures, pinned recents, a first-launch tour, and an onboarding-aware
shortcuts overlay you can summon with `?`.

Slab is now the open-source PDF tool that:

- **Stays on your machine.** No cloud anything. Beacon AI defaults to a
  local Ollama daemon; if you don't have one running, AI is just off.
- **Looks like a real app.** Linear/Raycast-class chrome, light + dark,
  five accents, two densities, every panel keyboard-driven.
- **Does the whole PDF job.** Read, edit text, split, merge, rotate,
  compress, OCR, ask questions, diff two versions, present, redact,
  watermark, sanitise, batch-process — across macOS, Linux, Windows.

If you've been on the v0.x train: thanks for putting up with the weekly
churn. From now on, breaking changes get a major bump.

## What ships in v1.0.0 (Glass — 7 polish slices)

### 🎨 Slice 1 — Settings system (theme · accent · density)

A real `~/.slab/config.toml [ui]` section now backs every visual
preference. Pick `light` / `dark` (system default), one of five accents
(emerald, sky, violet, amber, rose), and `comfortable` or `compact`
density. Settings live in a new sidebar panel and surface as Command
Palette actions ("Set accent → violet", "Compact density", etc.). The
runtime store hot-applies changes — no reload — and `app.css` is now
fully token-driven (data-attribute selectors instead of CSS variable
overrides) so every component picks the new tokens up automatically.

### ⌨ Slice 2 — Keyboard Shortcuts overlay (`?` to open)

Press `?` anywhere in the app (outside a text field) and a five-group
overlay flies in: Global, Tabs, Reading, Beacon, Settings. Pills render
the platform mod key correctly (`⌘` on macOS, `Ctrl` elsewhere). Also
discoverable via Command Palette → "Show keyboard shortcuts". This is
how Slab finally tells you what it can do without you reading the source.

### 🍞 Slice 3 — Global toast notifications

The `$lib/notify` API (`notify.success`, `notify.error`, `notify.info`)
mounts a `ToastStack.svelte` in `+layout.svelte` so every panel can speak
without throwing modals or silently failing. Toasts auto-dismiss, stack,
and respect `prefers-reduced-motion`. Used by Settings, Recent file
actions, the Shortcuts customiser, and a dozen other spots.

### 📌 Slice 4 — Pinned recent files (+ remove)

Recents grew from 8 → 12 with a `pinned` flag. Hover any recent card →
📌 / ✕ overlay buttons appear. Pinned cards get a sticky badge and
survive `clearRecent()` ("Clear unpinned recents" semantics). Pin your
working set; nuke the rest.

### 🎯 Slice 5 — Command Palette MRU

Most-used actions float to the top. New `$lib/cmdMru` module stores
action IDs in localStorage; empty-query view becomes a synthetic
"Recently used" group (top 6). Search-mode ties on fuzzy score break in
MRU order — so once you've used `Split by chapter pattern` three times,
typing `s` puts it before `Set accent`. "Clear command history" is the
one action that doesn't record itself (escape hatch).

### 👋 Slice 6 — First-launch Onboarding tour

A 5-step welcome walkthrough on first run: Slab → Open a PDF → Beacon →
Command Palette → Settings. Dismissal flips `ui.onboarded = true` in
`~/.slab/config.toml` so it never re-appears. Re-triggerable any time
via Command Palette → "Show onboarding tour", or from Settings →
Onboarding row.

### ⌨ Slice 7 — Customisable keyboard shortcuts ⭐

The big Glass shipment: **every shortcut in the app is now remappable**.

New `~/.slab/config.toml [keymap]` section stores sparse overrides
(default bindings live in code, so the on-disk file only contains the
keys you changed — and the file stays empty on a default config). The
backend `keymap` module exposes 19 bindable actions across 4 groups
(Global / Tabs / Reading / Beacon) with a `Binding` parser that
round-trips `Mod+Shift+K` strings to `ModifierSet + key`. `Mod` resolves
to `meta` on macOS, `ctrl` everywhere else — your shortcuts move
correctly when you switch platforms. Unknown action ids in incoming TOML
are silently dropped (forward-compat); malformed bindings error loudly.

Three Tauri commands wire it up (`slab_keymap_read` / `write` / `reset`)
with **collision detection against the materialised map** — try to bind
"Open command palette" to `?` and the backend rejects with a friendly
"Shortcut already in use → shortcuts.show" toast instead of leaving you
with two shortcuts firing on the same key.

The frontend is a Settings → ⌨ Shortcuts panel, also reachable via
Command Palette → "Customize keyboard shortcuts". Click any pill, press
a new combo, done — rebinds appear in the `?` overlay immediately
without a reload. `Esc` cancels, `Backspace` resets that one row,
toolbar shows a "Reset all to defaults" button with an active count
badge. The `BeaconChatPanel` still honours `Enter` to send AND your
customised `beacon.send` binding (muscle memory preserved).

**Default keymap is byte-identical to v0.15.0** — nothing changes
unless you customise.

## Stable API promise

Starting with v1.0.0, the following are versioned semantically:

- **Tauri command names + signatures** (`slab_*` invocations).
  Removing or breaking-changing one requires a major bump.
- **`~/.slab/config.toml` schema.** Adding fields = minor. Removing or
  renaming = major. Legacy files always parse with `#[serde(default)]`.
- **`~/.slab/library.sqlite` schema.** Migrations carry the version
  forward; existing data survives every update.
- **CLI subcommand surface** (`slab lens preflight`, `slab compress`,
  etc.). Same rules.

Internal Rust APIs (`pdf::*`, `ai::*`, `library::*` modules) are NOT
part of this contract — Slab isn't a library, it's an app.

## Deferred to v1.0.1 / v1.1.0

The Glass spec listed 10 slices; we shipped 7. Two of the remaining
three need real engineering and ship as their own minor release:

- **Floating panels** — multi-window detachable Beacon + Library so you
  can keep chat open on a second monitor while reading. Requires Tauri
  multi-window plumbing; 2–3 ticks of work.
- **Performance pass** — page-render worker pool, 100-page open under
  500ms target. Pure backend optimisation, doable in 2–3 commits but
  needs benchmarking infrastructure.
- **Vim bindings + a11y/i18n** — punted to v1.2.0 ("Glass II") when we
  have a community asking for them.

## Upgrade notes

**From v0.15.0:** zero-config. Your existing `~/.slab/config.toml`,
`~/.slab/library.sqlite`, `~/.slab/chats.db`, and pinned-recents all
upgrade in place. The first launch on v1.0.0 will add the new `[ui]`
fields (idempotently) and leave `[keymap]` empty until you customise.

**From v0.10.0 or earlier:** every release between you and v1.0.0 has
forward-compat parsing for its predecessors. You'll skip straight through
without manual migration. Re-index your library after upgrading (Settings →
Library → "Rescan all folders") to pick up the v0.13 OCR-state and v0.14
diff metadata.
