# v2.9.0 "Vault" — PKCS#11 Hardware Signing Implementation Plan

> **Version note:** Renumbered from v2.8.0 → v2.9.0 after a sibling cron
> tick promoted v2.8.0 "Forge" (batch recipes) during the same tick window.
> Forge was committed first; Vault slots one slice later. All references
> below to "v2.8.0 Vault" should be read as "v2.9.0 Vault".

> **For Hermes:** Use `subagent-driven-development` skill to implement this plan task-by-task. Fresh subagent per task, spec-compliance review then code-quality review, proceed only on dual green.
>
> **Prerequisite:** v2.7.0 Signet must be shipped and on `main`. This plan extends it; do not start until Signet is merged.

**Goal:** Let enterprise users sign PDFs with private keys that live on hardware tokens (YubiKey 5 PIV, Nitrokey HSM 2, SoftHSM 2 for CI, Thales Luna, AWS CloudHSM via PKCS#11 proxy) — keys never leave the token, every sign requires PIN + touch, the resulting PAdES-B-B signature is byte-identical in structure to v2.7.0's software-key output so Adobe / Foxit / Preview validate the same way.

**Why this is the buy-button feature:** Software-key signing (v2.7.0) is fine for individual contributors but legally insufficient for law firms, notaries, and CAs — court-admissible electronic signatures under eIDAS (EU) and ESIGN+UETA (US, when challenged) require "sole control" of the signing key, which only hardware tokens can prove. Adobe Sign charges $240/user/yr **and** still needs you to buy DocuSign or GlobalSign on top for hardware-rooted signatures. Slab + a $50 YubiKey + a $0 self-signed cert (or a $99/yr Sectigo cert) gives a 200-lawyer firm the same compliance posture for free.

**Architecture:**
- New crate-graph branch: `pkcs11 = "0.5"` (pure-Rust bindings to the C PKCS#11 v2.40 ABI) + `cryptoki = "0.7"` (high-level safe wrapper). Both crates are MIT/Apache, zero new C deps — they `dlopen` the user's PKCS#11 provider library at runtime (`/usr/lib/libykcs11.dylib`, `/usr/lib/softhsm/libsofthsm2.so`, `C:\Program Files\Yubico\Yubico PIV Tool\bin\libykcs11.dll`, etc.).
- New module `src-tauri/src/signet/pkcs11.rs` implements a `Signer` trait that v2.7.0's CMS builder already consumes. The hardware signer presents the same `sign_digest(&[u8; 32]) -> Result<Vec<u8>>` interface as the software signer; everything downstream (CMS SignerInfo assembly, byte-range patching, embedded cert chain) is shared with v2.7.0.
- Provider discovery: a registry of well-known PKCS#11 library paths per-OS, plus a user-configurable "Custom provider path" in Settings. We probe on first open and on Settings save, never on every sign.
- PIN handling: prompt via a dedicated Tauri command that pushes a modal in the main window (no PIN ever logged, no PIN in process args, zeroized after use via `zeroize` crate).
- Touch handling: YubiKey PIV slots can require physical touch. We surface a "Touch your YubiKey now" overlay with a 15-second timeout and a cancel button.
- New nav entry: **Vault** (key icon, slot under Signet in the chrome). Three tabs: **Devices** (list providers + tokens + slots), **Keys** (objects on the selected slot), **Sign** (pick key + PDF + visible widget config — reuses v2.7.0's SignWidget component).

**Tech Stack:** Rust 1.86 / Tauri v2 / Svelte 5 runes / cryptoki 0.7 + pkcs11 0.5 / zeroize 1.8 / dirs 5 (for OS-specific provider paths) / existing `signet::cms` from v2.7.0.

**Out of scope (deferred):**
- Smart-card key generation on-device (`C_GenerateKeyPair`) — v2.8.1.
- PKCS#11 over network / proxy (Thales Luna Cloud HSM REST adapter) — v2.8.2.
- CAdES (non-PDF CMS signing of arbitrary files) — v2.9.0.
- Encrypted-document signing — Vault's signer works on Slab's existing decrypt-on-open flow; signing a still-encrypted file is not supported, by design.

> **Decision:** v2.8.0 Vault uses `cryptoki 0.7` (high-level safe wrapper) over `pkcs11 0.5` (raw FFI), both pure-Rust, MIT/Apache. //! PKCS#11 hardware-token signer (v2.8.0 Vault).
```rust
//!
//! Implements the [`crate::signet::Signer`] trait by delegating sign-digest
//! to a hardware token loaded via a runtime-dlopen'd PKCS#11 provider library.

use std::path::PathBuf;
use zeroize::Zeroizing;

use crate::signet::error::SignetError;

/// Identifies one provider library (`ykcs11`, `opensc-pkcs11`, `softhsm2`, …).
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct ProviderRef {
    pub label: String,
    pub library_path: PathBuf,
}

/// Identifies one key object on one slot of one provider.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct KeyRef {
    pub provider: ProviderRef,
    pub slot_id: u64,
    pub key_label: String,
    pub key_id: Vec<u8>,
}

/// Holds an open PKCS#11 session; constructed from a [`KeyRef`] + PIN.
pub struct Pkcs11Signer {
    pub(crate) key: KeyRef,
    pub(crate) _pin: Zeroizing<String>, // never logged, never serialized
    // session + functions handle stored here once we open in Task 3
}

impl Pkcs11Signer {
    pub fn placeholder(key: KeyRef, pin: String) -> Result<Self, SignetError> {
        Ok(Self {
            key,
            _pin: Zeroizing::new(pin),
        })
    }
}
```

```rust
use std::path::{Path, PathBuf};

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Os { Macos, Linux, Windows }

pub fn current_os() -> Os {
    #[cfg(target_os = "macos")] return Os::Macos;
    #[cfg(target_os = "linux")] return Os::Linux;
    #[cfg(target_os = "windows")] return Os::Windows;
    #[allow(unreachable_code)]
    Os::Linux
}

pub fn well_known_paths_for(os: Os) -> Vec<PathBuf> {
    match os {
        Os::Macos => vec![
            "/opt/homebrew/lib/libykcs11.dylib".into(),
            "/usr/local/lib/libykcs11.dylib".into(),
            "/Library/OpenSC/lib/opensc-pkcs11.so".into(),
            "/opt/homebrew/lib/softhsm/libsofthsm2.so".into(),
        ],
        Os::Linux => vec![
            "/usr/lib/x86_64-linux-gnu/libykcs11.so".into(),
            "/usr/lib/x86_64-linux-gnu/opensc-pkcs11.so".into(),
            "/usr/lib/softhsm/libsofthsm2.so".into(),
            "/usr/lib64/pkcs11/libykcs11.so".into(),
        ],
        Os::Windows => vec![
            r"C:\Program Files\Yubico\Yubico PIV Tool\bin\libykcs11-2.dll".into(),
            r"C:\Program Files\OpenSC Project\OpenSC\pkcs11\opensc-pkcs11.dll".into(),
            r"C:\SoftHSM2\lib\softhsm2-x64.dll".into(),
        ],
    }
}

pub fn existing(paths: &[PathBuf]) -> Vec<PathBuf> {
    paths.iter().filter(|p| Path::new(p).exists()).cloned().collect()
}

pub fn discover() -> Vec<PathBuf> {
    existing(&well_known_paths_for(current_os()))
}
```

```rust
// src-tauri/src/signet/pkcs11.rs — append below scaffolding
use cryptoki::{
    context::{CInitializeArgs, Pkcs11},
    object::{Attribute, AttributeType, ObjectClass, KeyType},
    session::UserType,
    slot::Slot,
};
use cryptoki::types::AuthPin;

pub fn enumerate_keys(provider: &ProviderRef) -> Result<Vec<KeyRef>, SignetError> {
    let ctx = Pkcs11::new(&provider.library_path)
        .map_err(|e| SignetError::Asn1(format!("load provider: {e}")))?;
    ctx.initialize(CInitializeArgs::OsThreads)
        .map_err(|e| SignetError::Asn1(format!("C_Initialize: {e}")))?;

    let mut out = Vec::new();
    for slot in ctx.get_slots_with_token().map_err(|e| SignetError::Asn1(e.to_string()))? {
        let session = ctx.open_ro_session(slot)
            .map_err(|e| SignetError::Asn1(e.to_string()))?;
        let template = vec![
            Attribute::Class(ObjectClass::PRIVATE_KEY),
            Attribute::Sign(true),
        ];
        for handle in session.find_objects(&template)
            .map_err(|e| SignetError::Asn1(e.to_string()))?
        {
            let attrs = session.get_attributes(handle, &[
                AttributeType::Label,
                AttributeType::Id,
            ]).map_err(|e| SignetError::Asn1(e.to_string()))?;
            let mut label = String::new();
            let mut id = Vec::new();
            for a in attrs {
                match a {
                    Attribute::Label(l) => label = String::from_utf8_lossy(&l).into_owned(),
                    Attribute::Id(i) => id = i,
                    _ => {}
                }
            }
            out.push(KeyRef {
                provider: provider.clone(),
                slot_id: u64::from(slot.id()),
                key_label: label,
                key_id: id,
            });
        }
    }
    Ok(out)
}
```

**Step 2: Implement**

```rust
use cryptoki::mechanism::Mechanism;

impl crate::signet::Signer for Pkcs11Signer {
    fn algorithm(&self) -> crate::signet::SignAlgorithm {
        // Inspected during open_session and stored in self.algorithm —
        // see field added in step 3 below.
        self.algorithm
    }

    fn certificate_der(&self) -> &[u8] {
        &self.cert_der
    }

    fn sign_digest(&self, digest: &[u8]) -> Result<Vec<u8>, SignetError> {
        // session + private_key handle are stored from open(); both
        // are non-Send so we keep this method &self (cryptoki sessions
        // are Send+Sync since 0.7).
        let mech = match self.algorithm {
            crate::signet::SignAlgorithm::RsaSha256 => Mechanism::Sha256RsaPkcs,
            crate::signet::SignAlgorithm::EcdsaP256Sha256 => Mechanism::EcdsaSha256,
        };
        self.session
            .sign(&mech, self.private_key, digest)
            .map_err(|e| SignetError::Asn1(format!("C_Sign: {e}")))
    }
}
```

**Step 3: Flesh out `Pkcs11Signer` constructor**

Replace the `placeholder` constructor with a real `open()` that:
1. Loads provider, initializes, opens RW session.
2. `session.login(UserType::User, &AuthPin::new(pin))` — PIN zeroized after.
3. Finds the private key by `CKA_LABEL` + `CKA_ID` from the `KeyRef`.
4. Finds the matching public certificate (`CKO_CERTIFICATE` with same `CKA_ID`), extracts `CKA_VALUE` as DER.
5. Determines algorithm from cert's SubjectPublicKeyInfo OID.
6. Stores `session`, `private_key`, `cert_der`, `algorithm` on `self`.

Full implementation (~80 lines) follows the cryptoki 0.7 docs example for "sign with a hardware key" verbatim, with two changes: (a) we accept `KeyRef` instead of hard-coding a label, and (b) we extract the cert so v2.7.0 can embed it in the SignedAttributes.

**`softhsm-init.sh`** — single shell script that:
1. Initializes SoftHSM token with label `slab-ci`, PIN `1234`.
2. Generates RSA-2048 key pair via `pkcs11-tool --keypairgen`.
3. Generates self-signed cert via `openssl req` reading the public key.
4. Imports cert into SoftHSM via `pkcs11-tool --write-object`.
5. Echoes `SLAB_TEST_PKCS11_LIB=...` to `$GITHUB_ENV`.

**`vault_e2e.rs`** — single integration test:

```rust
#[test]
fn end_to_end_hardware_sign_and_verify() {
    let provider = ProviderRef {
        label: "softhsm-ci".into(),
        library_path: std::env::var("SLAB_TEST_PKCS11_LIB").unwrap().into(),
    };
    let keys = enumerate_keys(&provider).unwrap();
    let key = keys.iter().find(|k| k.key_label == "slab-ci-rsa").unwrap().clone();
    let signer = Pkcs11Signer::open(key, "1234".into()).unwrap();
    let pdf_in = std::fs::read("tests/fixtures/hello.pdf").unwrap();
    let pdf_out = crate::signet::sign_pdf(&pdf_in, &signer, None).unwrap();
    let report = crate::signet::verify_pdf(&pdf_out).unwrap();
    assert_eq!(report.signatures.len(), 1);
    assert!(report.signatures[0].digest_matches);
}
```
