# v3.1.0 "Loom" — PDF/UA Accessibility Tagging Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task. ~1900 net LOC + ~600 test LOC across 9 slices + release. ~11 commits.

**Goal:** Convert any PDF — born-digital or scanned — into an **ISO 14289-1 (PDF/UA-1)** compliant accessible document. Synthesize a logical structure tree (headings, paragraphs, lists, tables, figures) from text layout heuristics, attach alt-text for figures (Beacon-generated, user-editable), tag reading order, set document language + title, mark artifacts (page numbers, headers/footers) so screen readers skip them, and validate with the PAC 2024 ruleset (offline, ported subset).

This is the single feature that unlocks government, education, healthcare, and Fortune-500 procurement — **Section 508 (US), EN 301 549 (EU), AODA (Canada)** all mandate PDF/UA for public-facing documents. No free tool does this end-to-end. Adobe Acrobat Pro charges $239/yr; CommonLook costs $1,800/seat; axesPDF is €390. Slab will do it free, offline, in one click.

**Architecture:** New `pdf::loom` Rust module owns the tagging pipeline as 7 ordered passes over a `lopdf::Document`:

1. **`extract`** — parse content streams + text matrices to build a `LayoutTree` (lines, blocks, font sizes, positions).
2. **`classify`** — heuristic node typing (H1-H6 by font-size rank, P by body run, L/LI by bullet detection, Table by aligned columns, Figure by Do-XObject without text).
3. **`reading_order`** — column detection (vertical strip clustering) → top-down, left-to-right serpentine traversal.
4. **`alt_text`** — for every Figure node, optionally invoke Beacon (Ollama llava) for a 1-sentence alt description; cached per image hash.
5. **`structure_tree`** — emit PDF `StructTreeRoot` + `ParentTree` + `RoleMap`, point `StructParents` from every page.
6. **`metadata`** — set `/Lang`, `/MarkInfo<<Marked true>>`, `/ViewerPreferences<</DisplayDocTitle true>>`, XMP `pdfuaid:part = 1`, document title.
7. **`validate`** — Matterhorn Protocol subset (51 of 136 checkpoints automatable without human judgement) — emits structured `LoomReport` with PASS / WARN / FAIL per checkpoint.

Each pass is a pure function on `&mut Document` (or pure transform on `LayoutTree`) so they're independently testable. Frontend gets a `LoomPanel.svelte` with three tabs: **Inspect** (current accessibility score + violations) → **Tag** (one-click full pipeline with progress) → **Review** (tree editor: rename nodes, edit alt-text, mark artifacts). Reuses 100% of v3.0.0 Bedrock's XMP packet writer, sanitize pass, and metadata injection infrastructure.

**Tech Stack:** lopdf 0.36 (workspace), `quick-xml 0.36` (XMP — reuse Bedrock's writer), `lopdf::content::Content` (operator parsing — already in tree), Beacon's existing Ollama llava integration (`crates/beacon/src/vision.rs` — already shipped in v0.10.0). Zero new dependencies.
