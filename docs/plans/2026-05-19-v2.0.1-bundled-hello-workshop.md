# v2.0.1 "Bundled Hello Workshop" Implementation Plan

> **For Hermes:** Use subagent-driven-development to implement this plan
> task-by-task. Branch already exists: `feature/v2.0.1-bundled-hello-workshop`.
> Most of Slice 1's code is already on disk (untracked / unstaged); the first
> tick must turn that WIP into a clean, tested, committed slice.

**Goal:** Every fresh Slab install ships with three working runtime plugins
already on disk — so a user who opens the Plugins panel for the first time
sees something interesting, not an empty state. This is the "0 → 1" moment
the v2.0.0 Workshop release left unfinished: the platform exists, but a
brand-new user has no plugins to play with unless they hand-bundle one.

**Architecture:** A tiny boot-time seeder (`plugins::bundled`) `include_str!`s
the three reference plugins from `sdk/slab-plugin-sdk/examples/*` directly
into the binary and writes them into `~/.slab/plugins/<id>/` on first launch.
Subsequent launches are idempotent: untouched plugins are no-ops, plugins
whose embedded `version` advanced are overwritten, plugins the user deleted
stay deleted for the current install lifetime. The seeder runs *before*
`PluginRegistry::discover` in the Tauri `setup` closure so discovery picks
up the freshly-seeded plugins on the same boot. A "Bundled" pill in the
PluginsPanel makes the provenance obvious, and a one-time "Try a plugin"
spotlight onboarding step (added to the existing `OnboardingTour`) makes
sure the user notices.

**Tech Stack:** Rust (`std::fs`, `include_str!`, `tempfile` for tests),
Svelte 5 (PluginsPanel pill + OnboardingTour step), TOML (manifest format).

**Buy-Button verdict:**
- **Pick-us test (PASS)** — Adobe and PDF Expert ship zero plugins. Foxit
  ships zero plugins for end users (enterprise-only). A fresh-install Slab
  with three working plugins is a Pick-us moment.
- **Tell-a-friend test (PASS)** — "Look, I downloaded a PDF reader and it
  came with a working plugin SDK + three example plugins I can read and
  modify" is genuinely screenshot-worthy for the developer audience that
  reads HN.
- **Notice-it test (PASS)** — Users who already updated v2.0.0 will open
  the panel after v2.0.1 and see 3 new plugins where there were 0.

**WOW moment for this release:** The Cabinet quick-action bar populates
itself with "Say Hi" (hello-workshop), "Counter +1" (storage-counter), and
"Fetch URL…" (url-fetch) before the user has done anything. A first-time
user can fire a real plugin within five seconds of opening the app.

**Objective:** Defensive integration test that exercises the boot path

**Files:**
- Create: `src-tauri/tests/bundled_plugins_smoke.rs` (new integration

**Step 1: Write the test.**

```rust
//! Integration smoke test for the v2.0.1 bundled-plugins feature.
//!
//! This is *not* a unit test — it exercises `seed_bundled_plugins`
//! against the real `PluginRegistry::discover` path, which means a
//! regression in either the seeder, the discovery code, or the
//! hash-pin verification will break this build.

use slab_lib::plugins::{
    default_plugins_root, seed_bundled_plugins,
    registry::{EnabledState, PluginRegistry},
};
use std::collections::HashSet;
use tempfile::tempdir;

/// All three bundled plugin ids. MUST match
/// `BUNDLED_PLUGIN_IDS` in `src/lib/plugins.ts` and the
/// `BUNDLED` slice in `src-tauri/src/plugins/bundled.rs`.
const EXPECTED_IDS: &[&str] = &[
    "com.slab.examples.hello-workshop",
    "com.slab.examples.storage-counter",
    "com.slab.examples.url-fetch",
];

#[test]
fn bundled_plugins_seed_and_discover_cleanly() {
    let tmp = tempdir().unwrap();
    let seeded = seed_bundled_plugins(tmp.path());
    assert_eq!(
```

## Risk register

1. **sha256 mismatch on bundle.** If `script.js` is rebuilt without
   updating `manifest.toml`'s `sha256`, the registry will reject the
   plugin. Mitigation: the integration smoke test in Slice 5 catches
   this with an actionable error message. The README in each example
   directory documents the rebuild recipe.

2. **First-run seed races with user setup.** The seeder runs inside
   Tauri's `setup` closure, *before* discovery, so there's no race
   window. The only failure mode is "HOME unset" → `default_plugins_root`
   returns `None` → silent skip → user sees empty panel. Acceptable
   degradation.

3. **User edits a bundled script and expects updates.** The seeder's
   version-equality short-circuit means a user who tweaks their copy
   gets to keep it — even if Slab ships a newer version of that plugin.
   This is the right default (don't clobber user work) but might
   surprise some users. Documented in the bundled.rs module docs.

4. **Bundle size cost.** Three `include_str!`s for ~5 KB scripts and
   ~1 KB manifests each = ~18 KB of static data baked into the binary.
   Negligible.

5. **Cross-OS path handling.** `~/.slab/` is resolved via the existing
   `default_plugins_root()`, which already handles Win/Mac/Linux. No new
   path code in this release.
