# v3.1.0 Loom — Slice 6: XMP Metadata + Post-tag Validator

> **For Hermes:** Single-tick implementation by Cake (cron). Feature branch
> `feature/v3.1.0-loom-slice-3` (lagging name, holds slices 3-6).

**Goal:** Ship the final two pieces required to call Slab's tagged-PDF output
a *real* PDF/UA-1 file: (a) the XMP packet + ViewerPreferences metadata that
ISO 14289-1 §7.1 mandates, and (b) a post-tag validator that re-loads the
output and runs the 8 auto-decidable Matterhorn conditions, so the success
badge becomes evidence instead of a claim.

**Architecture:**
- `metadata.rs` — `apply_pdfua_metadata(doc, opts)` mutates a tagged doc to
  add `/Metadata` (XMP stream with `pdfuaid:part=1`), set
  `/ViewerPreferences /DisplayDocTitle true`, ensure `/Lang`, and sync the
  Info-dict `/Title` into the XMP `dc:title`. Pure lopdf, no XML lib needed
  (we emit a hand-templated XMP packet — already canonical in the spec).
- `validate.rs` — `validate(doc) -> ValidateReport` parses the catalog and
  decides 8 well-scoped Matterhorn auto-conditions: 01-006 (structure tree
  present + non-empty), 06-001 (Document title in info dict), 06-002 (XMP
  present), 06-003 (`pdfuaid:part=1` in XMP), 07-001 (Lang on catalog or
  every elem), 09-001/002 (RoleMap if non-standard tags used), 11-001
  (MarkInfo /Marked true), 17 (Figure has /Alt for every Figure elem).
- Wired into `slab_loom_tag_document`: call `apply_pdfua_metadata` after
  `weave`. New Tauri command `slab_loom_validate(input)` runs validate on
  any PDF (the user can validate Acrobat output and brag, or sanity-check
  Slab output).
- UI: a new "Validate" tab in `LoomPanel.svelte`, plus auto-run validate on
  the freshly-tagged PDF right after `slab_loom_tag_document` finishes, so
  the success card on the "Tag PDF" tab gets an "Validated ✓ ISO 14289-1"
  sub-badge with per-condition green checkmarks. Cmd+Shift+V global shortcut
  to run validate on the loaded PDF.

**Tech stack:** Rust + lopdf, Svelte 4 + Tauri 2.

**Files:**
- Create: `src-tauri/src/pdf/loom/metadata.rs`
- Modify: `src-tauri/src/pdf/loom/mod.rs` (add `pub mod metadata;` + re-exports)

**Step 1:** Write `metadata.rs` with `MetadataOptions`, `MetadataStats`, `apply_pdfua_metadata(doc, &opts)`. **Step 2:** 5 unit tests:
- xmp packet contains `pdfuaid:part=\"1\"`
- catalog has `/Metadata` reference after apply
- catalog has `/ViewerPreferences /DisplayDocTitle true`
- info-dict `/Title` synced into xmp `<dc:title>`

**Step 3:** `cargo test --lib loom::metadata` → 5 passed.

## Task 2 — `validate.rs` + 8 Matterhorn auto-conditions

**Files:**
- Create: `src-tauri/src/pdf/loom/validate.rs`
- Modify: `src-tauri/src/pdf/loom/mod.rs` (re-exports)

**Step 1:** Define
```rust
pub struct CheckResult { pub id: &'static str, pub title: &'static str, pub passed: bool, pub detail: Option<String> }
pub struct ValidateReport { pub checks: Vec<CheckResult>, pub passed: usize, pub failed: usize, pub overall: bool }
pub fn validate(doc: &Document) -> ValidateReport
```

**Step 2:** Implement 8 checks reading the catalog/info/Metadata. Each returns a `CheckResult`. Ids drawn from `matterhorn.rs` titles (01-006, 06-001, 06-002, 06-003, 07-001, 09-001, 11-001, 17-rolled-up "every Figure has Alt").

**Step 3:** 6 unit tests using small synthetic docs (blank doc + apply tag/metadata; assert pass), plus one negative (raw blank doc → all fail).

**Step 4:** `cargo test --lib loom::validate` → 6 passed.

**Commit:** `feat(loom): validate() — 8 Matterhorn auto-conditions on tagged PDFs (Slice 6)`
