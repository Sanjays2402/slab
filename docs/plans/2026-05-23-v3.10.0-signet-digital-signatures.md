# v3.10.0 "Signet" — PKCS#7 Digital Signatures Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.
> Plan author: Cake (cron, 2026-05-23 12:48 PT). Sized for 4–6 off-hours ticks.

**Goal:** Add PKCS#7-detached digital signatures to PDFs (sign + verify), offline,
cross-platform, with a UI that competes head-on with Adobe Acrobat Pro's "Certificates"
panel — for free.

**Architecture:**
- New crate module `src-tauri/src/pdf/signet/` (siblings to `forms.rs`, `pdfa/`, `loom/`, `press/`).
- Three internal stages: **plan** (find/create the Signature field + ByteRange placeholder),
  **bake** (write the PDF with /ByteRange + zero-padded /Contents hex window),
  **seal** (compute message digest over the un-/Contents bytes, build PKCS#7 detached
  signature with `cms` crate over `rsa`/`p256`, splice hex back into the placeholder).
- Verify is the inverse: parse Sig dict → recompute digest over ByteRange → verify CMS
  signature → optionally validate certificate chain against a user-trust store.
- Crypto via the pure-Rust `cms` + `x509-cert` + `rsa`/`p256`/`p384`/`signature` crates
  (RustCrypto). **No OpenSSL / native deps** — keeps cross-platform parity.
- Signature appearance (the visible stamp) reuses the legal-stamp drawing pipeline
  in `legal_stamp.rs`; we just add the `/AP` stream pointing to it.
- Trust store lives at `~/.local/share/slab/signet/trusted/*.pem` (XDG on Linux, equivalent
  paths on macOS/Windows via `directories` crate). Defaults to empty; user imports CAs.

**Tech Stack:**
- Rust: `cms = "0.2"`, `x509-cert = "0.2"`, `rsa = "0.9"`, `p256 = "0.13"`, `p384 = "0.13"`,
  `sha2 = "0.10"`, `der = "0.7"`, `pkcs8 = "0.10"`, `pem = "3"`, plus existing `lopdf`.
- Frontend: Svelte 5 `SignetPanel.svelte` + new keymap action `signet.open`
  (Cmd/Ctrl+Shift+S) + command-palette entry.

## Pre-flight context every implementer needs

**PDF signature spec we target:** ISO 32000-1 §12.8, signature subfilter
`adbe.pkcs7.detached`. We do **not** ship CAdES (PAdES-B-LT/LTV) in v3.10.0 — call
that out in the UI and roadmap follow-up `v3.10.1 Signet-LTV`.

**Critical PDF bytes pattern.** The `/Contents` value in a signature dict is a
hex string with a fixed-length window of zeros, sized BEFORE the hash is computed:

```
... /ByteRange [0 X Y Z] /Contents <00000000...00000000> ...
```

where `[0 X Y Z]` excludes exactly the hex window. The flow:
1. Write the PDF with a placeholder `/Contents <0000...>` (default 16384 bytes hex
   = 8192 binary bytes, headroom for a typical 4–6 KiB PKCS#7 blob).
2. Locate the byte offsets of the hex window in the serialized PDF.
3. Compute `ByteRange = [0, hex_start_minus_1, hex_end_plus_1, file_end - (hex_end+1)]`.
4. Rewrite the `/ByteRange` array in-place with the real numbers (still must NOT
   change file length — pad numbers with spaces to a fixed-width tuple).
5. Hash the file with the hex window EXCLUDED → sign that hash → PKCS#7 detached blob.
6. Hex-encode the blob, splice into the window, zero-pad the remainder.

This sequence MUST happen at the raw-bytes layer, not via lopdf re-serialization,
because re-serializing after step 4 would shift offsets. lopdf is fine for the
**placeholder** write in step 1; after that we operate on bytes.

**Existing related code to read before starting:**

## Task 3: PKCS#7 detached CMS builder

**Objective:** Given a SHA-256 digest + a SigningIdentity, produce a
`adbe.pkcs7.detached` CMS blob bytes. Stand-alone, no PDF involvement.

**Files:**
- Create: `src-tauri/src/pdf/signet/cms_blob.rs`

**Step 1: Implement `build_pkcs7_detached(digest_sha256: &[u8; 32], identity: &SigningIdentity, signing_time: SystemTime) -> Result<Vec<u8>, SignetError>`** (~240 LOC).

Required structure (RFC 5652 + Adobe's profile):
- ContentInfo OID `1.2.840.113549.1.7.2` (signedData)
- SignedData version 1, digestAlgorithm SHA-256 (OID 2.16.840.1.101.3.4.2.1)
- EncapsulatedContentInfo with `eContentType = id-data (1.2.840.113549.1.7.1)` and
  **no eContent** (this is what "detached" means)
- Certificates SET: signer cert + chain
- SignerInfos with one SignerInfo:
  - signed attributes: contentType, messageDigest (the SHA-256), signingTime
  - signature over DER-encoded signed attributes
  - signatureAlgorithm matching identity (rsaEncryption / ecdsa-with-SHA256 / -SHA384)

Use the `cms` crate's `SignedDataBuilder`. Path of least resistance:

```rust
let sd = SignedDataBuilder::new(&encap_content_info)
    .add_digest_algorithm(AlgorithmIdentifierOwned { ... sha256 ... })?
    .add_certificate(cert)?
    .add_signer_info(signer_info_builder)?
    .build()?;
```

Wrap into a top-level ContentInfo and DER-encode to bytes.

## Task 4: Sign pipeline — placeholder write + byte-range splice

**Objective:** End-to-end `sign(input_pdf, identity, options)` returning a signed PDF.

**Files:**
- Create: `src-tauri/src/pdf/signet/sign.rs`

**Step 1: Implement `prepare_signature_field(doc: &mut Document, opts: &SignOptions) -> Result<ObjectId, SignetError>`** (~120 LOC).

Walk `/Catalog /AcroForm /Fields` looking for an existing empty Sig field
(matches `opts.field_name` if specified). If not found, create one with widget
annotation at `opts.rect` on `opts.page` (defaults: page 0, lower-right
200×60 box).

Field dict template:
```
<<
  /FT /Sig
  /T (Signature1)
  /F 4
  /Type /Annot /Subtype /Widget
  /Rect [x y w h]
  /P <page-ref>
  /V <sig-dict-ref>            <- new indirect obj
  /AP << /N <appearance-ref> >> <- optional, from legal_stamp
>>
```

Sig dict template (the placeholder):
```
<<
  /Type /Sig
  /Filter /Adobe.PPKLite
  /SubFilter /adbe.pkcs7.detached
  /Name (Signer CN)
  /M (D:20260523124800Z)
  /Reason (...)
  /Location (...)
  /ByteRange [0 ********** ********** **********]    <- 10-digit padded placeholders
  /Contents <0000...0000>                              <- 16384 hex chars = 8192 bytes
>>
```

Use a fixed 10-digit zero-padded width for the four ByteRange ints so the
serialized length doesn't change when we rewrite it. The hex-window size is a
const `SIGNATURE_HEX_PLACEHOLDER_BYTES = 16_384`.

**Step 2: Implement `sign_pdf(input: &Path, output: &Path, identity: &SigningIdentity, opts: &SignOptions) -> Result<SignReport, SignetError>`** (~180 LOC):

```
1. Load PDF with lopdf.
2. prepare_signature_field(...).
3. Serialize PDF to a Vec<u8> via lopdf (writes file).
4. Re-read those bytes.
5. Locate the hex window: find b"/Contents <" then scan to b">". Validate
   length == SIGNATURE_HEX_PLACEHOLDER_BYTES.
6. Locate the ByteRange placeholder: find b"/ByteRange [0 **********" pattern.
7. Compute ByteRange = [0, hex_open_offset, hex_close_offset + 1, len - (hex_close_offset + 1)].
   (hex_open_offset = index of the '<' itself; hex_close_offset = index of '>'.)
8. Rewrite ByteRange in-place — format!("[{:<10} {:<10} {:<10} {:<10}]", ...) padded with spaces.
9. SHA-256 the file with the hex window (inclusive of '<' and '>'? — no: per spec the
   bytes UNDER /Contents are excluded but the brackets are part of the included tail.
   Concretely: hash bytes [0..hex_open_offset) ++ [hex_close_offset+1..len)).
10. build_pkcs7_detached(digest, identity, now).
11. Hex-encode the CMS blob (uppercase per Adobe convention); pad with '0' to fill
    hex window; splice into file bytes between the angle brackets.
12. atomic_save(output, &final_bytes).
```

## Task 5: Verify pipeline + trust store

**Objective:** Inverse operation — parse signed PDF, verify each Sig dict.

**Files:**
- Create: `src-tauri/src/pdf/signet/verify.rs`
- Create: `src-tauri/src/pdf/signet/trust.rs`

**Step 1: `trust.rs` (~120 LOC).** Load PEM certificates from a configurable
trust directory (default `~/.local/share/slab/signet/trusted/`, fallback to
embedded zero CAs — i.e. nothing trusted by default). API:

```rust
pub struct TrustStore { roots: Vec<x509_cert::Certificate> }
pub fn load_default() -> Result<TrustStore, SignetError>;
pub fn add_pem(&mut self, pem_bytes: &[u8]) -> Result<(), SignetError>;
pub fn verify_chain(&self, leaf_der: &[u8], chain_der: &[Vec<u8>], now: SystemTime) -> ChainStatus;
pub enum ChainStatus { Trusted, Untrusted, Expired, ChainBroken, SelfSigned }
```

Chain verification is intentionally simple in v3.10.0: walk Issuer→Subject DN matches,
verify each link's signature using the issuer's public key, terminate when we hit a
root in the store. No CRL/OCSP this release (note in UI: "revocation: not checked").

**Step 2: `verify.rs` (~220 LOC).** API:

```rust
pub struct VerifiedSignature {
    pub field_name: String,
    pub signer_cn: String,
    pub signed_at_unix: i64,
    pub byte_range: [u64; 4],
    pub coverage: Coverage,     // FullDocument | PartialDocument
    pub digest_status: DigestStatus,  // Match | Mismatch
    pub crypto_status: CryptoStatus,  // Valid | Invalid | UnsupportedAlgorithm
    pub chain_status: ChainStatus,
    pub cert_subject: String,
    pub cert_issuer: String,
    pub cert_not_before: i64,
    pub cert_not_after: i64,
}

pub fn verify(input: &Path, trust: &TrustStore) -> Result<Vec<VerifiedSignature>, SignetError>;
```

Algorithm:
1. Walk AcroForm.Fields, collect /FT /Sig fields.
2. For each, read /V → Sig dict → /ByteRange + /Contents.
3. Hex-decode /Contents, strip trailing zero padding (track real length).
4. Hash the file across the ByteRange.
5. Parse CMS, extract messageDigest signed-attr, compare to step 4 → DigestStatus.
6. Verify CMS signature using the signing cert's public key → CryptoStatus.
7. Coverage = FullDocument if `byte_range[0]+byte_range[1] == hex_start` and
   `byte_range[2]+byte_range[3] == file_len`. Otherwise Partial (incremental update
   added after signing — Adobe Acrobat does the same check).
8. Run TrustStore.verify_chain → ChainStatus.

**Step 3: Round-trip integration test** in `signet/mod.rs#tests`:

- `sign_then_verify_same_file_passes_all_checks` — generate self-signed cert,
  sign a fixture PDF, verify, assert every status field is Valid/Match (chain
  is SelfSigned which is expected with empty trust store).
- `tampering_invalidates_signature` — sign, then flip one byte inside the
  ByteRange, verify → DigestStatus::Mismatch.
- `signature_after_incremental_update_reports_partial_coverage` — sign, append
  a trailing incremental update, verify → Coverage::PartialDocument.

## Risks + open questions

1. **`cms` crate maturity.** It's RustCrypto so it's reasonable, but coverage of
   the SignerInfo signed-attribute construction may need manual ASN.1 assembly.
   Mitigation: prototype Task 3 first, fall back to `rasn` or hand-rolled DER if blocked.
2. **`adbe.pkcs7.detached` vs `ETSI.CAdES.detached`.** We pick Adobe's flavor for
   v3.10.0 (broader reader compat). PAdES comes in v3.10.1.
3. **Signature appearance.** We can ship without `/AP` (Acrobat renders a default
   stamp). Bonus polish in Task 7 step 6: render a Liquid-Glass wax-seal stamp into the
   widget rect using the same drawing primitives as `legal_stamp.rs`.
4. **Trust store UX.** v3.10.0 trusts nothing by default; users import PEMs into
   `~/.local/share/slab/signet/trusted/`. v3.10.2 candidate: bundle Mozilla's
   common-CA bundle behind an opt-in toggle.
