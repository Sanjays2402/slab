# v2.0.0 "Workshop" — TypeScript Plugins Implementation Plan

> **For Hermes:** This is the active plan for `feature/v2.0.0-workshop`.
> Spec proposal lives at `.cron-state/proposals/v2.0.0-workshop.md`; this
> file is the implementation arc — sliced into shippable chunks.

**Goal:** Promote Slab from a config-driven plugin platform to a true scripting platform by embedding a sandboxed QuickJS runtime that plugin authors can extend via `script.js` + a `@slab/plugin-sdk`-typed host API.

**Architecture:** New `plugins::runtime` module wraps `rquickjs` 0.10. Plugin manifests gain an optional `[runtime]` section pinning `entry` + `sha256` + capability declarations. Loader verifies the script hash at discovery time (TOFU + pin). Capabilities are user-granted on first enable, persisted to `~/.slab/plugin-grants.toml`, and enforced at every host-API boundary. The host API is exposed inside the VM as the `slab` global with sections for `beacon`, `ui`, `document`, `storage`, `fetch`.

**Tech Stack:** Rust (`rquickjs 0.10`, `sha2 0.10`, `tokio` runtime), Svelte 5 frontend (capability prompt modal, plugin panel renderer), TypeScript SDK (`@slab/plugin-sdk` npm).

## Slice 2 — Manifest schema bump + script load + sha256 pinning

**Objective:** Manifests gain an optional `[runtime]` section. The loader, when present, reads `script.js` bytes from the plugin directory and verifies the file's SHA-256 against `manifest.runtime.sha256`. Mismatches are hard failures — the plugin loads in error state with a clear message. Backward compat: manifests without `[runtime]` continue to load as v1.x declarative-only (no script bytes attached, no hash check).

**Files:**
- Modify: `src-tauri/src/plugins/manifest.rs` (add `RuntimeManifest`, `Capabilities`, validation)
- Modify: `src-tauri/src/plugins/registry.rs` (`Plugin` gains `script_bytes: Option<Vec<u8>>`; loader hashes + verifies)
- Modify: `src-tauri/src/plugins/mod.rs` (re-export new types)
- Test: extend existing test modules in both files.

### Step 1: Add `RuntimeManifest` + `Capabilities` types to `manifest.rs`

```rust
/// v2.0.0 runtime section. Optional — when absent the plugin is
/// declarative-only (v1.x behavior preserved).
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct RuntimeManifest {
    /// Path to the JS entry file, relative to the plugin directory.
    /// Conventionally `script.js`.
    pub entry: String,
    /// Lowercase hex SHA-256 of the entry file. Verified at load time.
    pub sha256: String,
    #[serde(default)]
    pub capabilities: Capabilities,
}

/// Plugin-declared capabilities. User must grant on first enable.
#[derive(Debug, Clone, Default, Serialize, Deserialize, PartialEq)]
pub struct Capabilities {
    #[serde(default)]
    pub fs: FsCap,
    #[serde(default)]
    pub net: NetCap,
    #[serde(default)]
    pub ui: UiCap,
    #[serde(default)]
    pub beacon: BeaconCap,
}

#[derive(Debug, Clone, Default, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "kebab-case")]
pub enum FsCap { #[default] None, Read, ReadWrite }

#[derive(Debug, Clone, Default, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "kebab-case")]
pub enum NetCap { #[default] None, Specific, Any }

// ... UiCap, BeaconCap similar
```

Add field on `Manifest`:
```rust
#[serde(default)]
pub runtime: Option<RuntimeManifest>,
```

Validation:
- `runtime.entry` must not be empty and must end with `.js`.
- `runtime.sha256` must be 64 lowercase hex chars.

### Step 2: Loader hash check in `registry.rs`

In `load_one`:
1. Parse manifest.
2. If `manifest.runtime` is `Some`:
   a. Read `dir.join(&rt.entry)` bytes.
   b. Compute SHA-256 with `sha2::Sha256`.
   c. Compare to `rt.sha256` (case-insensitive). Mismatch → `error: Some("runtime.sha256 mismatch: ...")` and `manifest: None`.
   d. On match, store bytes on `Plugin.script_bytes`.
3. Otherwise, leave `script_bytes = None`.

### Step 3: Tests
- `manifest.rs`:
  - `runtime_section_parses_with_capabilities`
  - `runtime_rejects_non_js_entry`
  - `runtime_rejects_short_sha256`
