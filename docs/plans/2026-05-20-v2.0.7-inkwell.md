**Goal:** Add freehand **ink / drawing annotations** as Slab's third
annotation primitive (after highlights and notes), persisted to the same
sidecar JSON v2.0.6 introduced, and burnable into the PDF via a new
`Annotation::Ink` enum variant.

**Codename:** Inkwell 🖊️

**Architecture:** Pure-frontend pointer-event capture in a new
`<DrawLayer/>` Svelte component overlaid on each pdfjs page. Strokes are
captured as polyline points in CSS-pixel space, simplified via
**Ramer-Douglas-Peucker** (ε ≈ 0.5 px) at pointer-up, then converted to
PDF user-space via the page's `viewport.convertToPdfPoint()`. Stored in
the v2.0.6 sidecar JSON via a new `kind: "ink"` discriminator. A new Rust
`Annotation::Ink` variant emits a PDF `/Subtype /Ink` dictionary with
`/InkList` (per spec §12.5.6.13) when the user clicks "🖨 Burn into PDF".

**Tech Stack:** Svelte 5 runes, pdfjs-dist, Tauri 2 commands, lopdf,
serde, vitest.

**Approximate size:** ~1080 LOC of non-test code across **8 commits**:
- 1 commit per slice × 6 slices
- 1 commit MODE A merge (`v2.0.7-inkwell` → `main` --no-ff + tag)
- 1 commit STATE.md + session log + RELEASE_PENDING queue

## Why v2.0.7 next?

v2.0.6's plan (`docs/plans/2026-05-20-v2.0.6-margin.md`) flagged this
explicitly in its open-questions block:

> **"Drawing annotations (ink / shapes) in v2.0.6 or defer to v2.0.7?
> Plan defers — adds ~400 LOC and a new Rust enum variant."**

That deferral is now redeemed as a real plan. Three concrete reasons it
slots in here:

1. **Sidecar pattern is fresh.** v2.0.6 just introduced
   `src/lib/annotations.ts` (~330 LOC) and the persistent sidecar JSON
   keyed by file path. v2.0.7's ink strokes are *the same store with a
   new discriminator* — `kind: "ink"` joins `"highlight"` and `"note"`.
   Writing the store extension now, while patterns are fresh in context,
   is ~30% cheaper than later.
2. **Backend surgery is minimal.** The PDF `/Annot` writing pipeline
   (`src-tauri/src/pdf/annotations.rs`) already accepts a tagged-union
   `Annotation` enum. Adding the third variant `Ink` is ~120 LOC including
   2 unit tests. No new modules; no new Tauri commands; the existing
   `slab_append_annotations` command serializes the new variant for free.
3. **Reviewers expect it.** Three of four reference competitors (Acrobat,
   PDF Expert, Foxit) ship freehand drawing as a *core* annotation tool —
   it's the first tool people reach for on a tablet/touchscreen. Slab on
   an iPad Pro with Apple Pencil today does nothing on stylus contact;
   that single demo failure costs the entire v1.0.0 launch narrative.

```ts
/** A single freehand stroke captured in PDF user-space coordinates.
 *  Each point is [x, y] in PDF points (origin bottom-left, Y up). */
export type InkAnnotation = {
  kind: "ink";
  id: string;
  path: string;
  pageIndex: number;
  /** One unbroken pen stroke. PDF Ink supports multiple paths per
   *  annotation but we keep one stroke per annotation for simpler
   *  edit/undo. */
  points: InkPoint[];
  /** Stroke width in PDF points (= pixels at scale 1.0). */
  width: number;
  /** RGB 0..1. Defaults applied at render time, never stored as null. */
  color: [number, number, number];
  /** Optional opacity 0..1; defaults to 1 if absent. */
  opacity?: number;
  author: string;
  createdAt: number;
};

export type Annotation =
  | HighlightAnnotation
  | NoteAnnotation
  | InkAnnotation;
```

### Step 2 — RDP simplifier

Append to `annotations.ts`:

```ts
/** Ramer–Douglas–Peucker polyline simplification.
 *
 *  Reduces N input points to ≤ N output points such that no removed
 *  point was further than ε from the polyline connecting its
 *  neighbours. Pure, no globals.
 *
 *  Used to shrink raw pointer-event streams (200+ pts/sec on Apple
 *  Pencil) down to ~10–60 points per stroke before persisting. Visually
 *  indistinguishable at ε = 0.5 px on a 144-dpi screen.
 *
 *  Complexity: O(n log n) average, O(n²) worst case.
 */
export function simplifyRdp(
  points: readonly InkPoint[],
  epsilon: number,
): InkPoint[] {
  if (points.length < 3) return points.slice() as InkPoint[];
  // ... full implementation: 35 LOC including helper perpDist().
}
```

(Complete implementation included in slice's commit; pseudocode above is
the API contract.)

### Step 3 — CSS→PDF batch convert

```ts
/** Convert a polyline from CSS-pixel space at the current viewport
 *  to PDF user-space, via `pageViewport.convertToPdfPoint(x, y)`.
 *  Caller passes the pdfjs PageViewport; we don't import pdfjs here
 *  to keep this module pure-TS-testable. */
export function cssPolylineToPdf(
  points: readonly InkPoint[],
  viewport: { convertToPdfPoint(x: number, y: number): [number, number] },
): InkPoint[] {
  return points.map(([x, y]) => {
    const [px, py] = viewport.convertToPdfPoint(x, y);
    return [px, py] as InkPoint;
  });
}
```

### Step 4 — `addInkAnnotation()` helper

Mirror v2.0.6's `addAnnotation(path, annot)` but with ink-specific
validation:

```ts
export function addInkAnnotation(
  path: string,
  pageIndex: number,
  pointsPdf: InkPoint[],
  opts: { width: number; color: [number, number, number];
          opacity?: number; author?: string } = {} as any,
): InkAnnotation | null {
  if (pointsPdf.length < 2) return null; // no zero-length strokes
  const annot: InkAnnotation = {
    kind: "ink",
    id: cryptoRandomId(),
    path,
    pageIndex,
    points: pointsPdf,
    width: Math.max(0.5, Math.min(20, opts.width ?? 1.5)),
    color: opts.color,
    opacity: opts.opacity,
    author: (opts.author ?? "Slab").slice(0, 64),
    createdAt: Date.now(),
  };
  pushAnnotation(path, annot); // re-uses v2.0.6's internal push
  return annot;
}
```

### Step 3 — `/Ink` dict builder

Add a third match arm to `build_annotation_dict()` (after the `Note`
arm):

```rust
Annotation::Ink {
    points,
    width,
    color,
    opacity,
    author,
    ..
} => {
    let w = width.clamp(0.25, 24.0);
    let rgb = color.unwrap_or([0.95, 0.20, 0.30]); // accent red
    let ca = opacity.unwrap_or(1.0).clamp(0.05, 1.0);

    // Compute bounding /Rect from points, inflated by w/2 + 1.
    let mut min_x = f32::MAX; let mut min_y = f32::MAX;
    let mut max_x = f32::MIN; let mut max_y = f32::MIN;
    let mut i = 0;
    while i + 1 < points.len() {
        let x = points[i]; let y = points[i + 1];
        if x < min_x { min_x = x; }
        if y < min_y { min_y = y; }
        if x > max_x { max_x = x; }
        if y > max_y { max_y = y; }
        i += 2;
    }
    let pad = w / 2.0 + 1.0;
    if points.is_empty() {
        min_x = 0.0; min_y = 0.0; max_x = 0.0; max_y = 0.0;
    } else {
        min_x -= pad; min_y -= pad; max_x += pad; max_y += pad;
    }

    // /InkList: array of arrays of numbers. We emit a single sub-path.
    let inklist: Vec<Object> = points.iter().map(|n| Object::Real(*n)).collect();

    // /BS (border style): width + solid dash.
    let bs = dictionary! {
        "Type" => "Border",
        "W" => Object::Real(w),
        "S" => "S",
    };

    let user = if author.is_empty() { "Slab" } else { author.as_str() };

    dictionary! {
        "Type" => "Annot",
        "Subtype" => "Ink",
        "Rect" => Object::Array(vec![
            Object::Real(min_x), Object::Real(min_y),
            Object::Real(max_x), Object::Real(max_y),
        ]),
        "InkList" => Object::Array(vec![Object::Array(inklist)]),
        "BS" => Object::Dictionary(bs),
        "C" => Object::Array(rgb.iter().map(|c| Object::Real(*c)).collect()),
        "CA" => Object::Real(ca),
        "F" => Object::Integer(4), // print
        "T" => Object::string_literal(user),
        "P" => Object::Integer(0), // placeholder; page-link is set by caller
    }
}
```

## Slice 3 — `DrawLayer.svelte` pointer-capture overlay

**Objective:** New component that captures pointer events on each page
overlay, accumulates points, and persists on pointer-up via
`addInkAnnotation`. Includes apple-pencil pressure/tilt as best-effort.

**Files:**
- Create: `src/lib/DrawLayer.svelte` (+~280 LOC)
- Modify: `src/lib/AnnotateLayer.svelte` (+~25 LOC) — add `"draw"` mode
- Modify: `src/lib/panels/ReaderPanel.svelte` (+~40 LOC) — render
  `<DrawLayer/>` alongside `<AnnotateLayer/>` and register Mod+I

### Component shape

```svelte
<script lang="ts">
  /** Capture freehand strokes on every visible pdfjs page and persist
   *  them as `kind: "ink"` annotations. */
  import {
    addInkAnnotation,
    simplifyRdp,
    cssPolylineToPdf,
    type InkPoint,
  } from "./annotations";

  type Props = {
    path: string;
    viewer: any; // pdfjs PDFViewer
    viewerEl: HTMLElement | null;
    mode: "off" | "draw" | "erase";
    color: [number, number, number];
    width: number; // CSS px at scale 1.0
    eraserRadius: number; // CSS px
    onmodechange?: (m: "off") => void;
    onstrokecommitted?: (annotId: string) => void;
  };

  const { path, viewer, viewerEl, mode, color, width, eraserRadius,
          onmodechange, onstrokecommitted }: Props = $props();

  // State per active stroke
  let activePage = $state<number | null>(null);
  let raw: InkPoint[] = $state([]);     // raw pointer points (CSS px)
  let isDrawing = $state(false);
  let previewSvg: SVGSVGElement | null = $state(null);

  // ... pointerdown / pointermove / pointerup handlers ...
  // ... apple-pencil tilt/pressure best-effort capture via event.pressure ...
  // ... mouseup → simplify → cssPolylineToPdf → addInkAnnotation ...
</script>

<svelte:window
  onpointermove={onMove}
  onpointerup={onUp}
  onpointercancel={onCancel}
/>

{#if isDrawing && previewPathD}
  <svg class="draw-preview" bind:this={previewSvg}
       style:left="{previewLeft}px" style:top="{previewTop}px"
       width={previewW} height={previewH}>
    <path d={previewPathD}
          stroke="rgb({color[0]*255},{color[1]*255},{color[2]*255})"
          stroke-width={width} fill="none"
          stroke-linecap="round" stroke-linejoin="round" />
  </svg>
{/if}

<style>
  .draw-preview {
    position: absolute;
    pointer-events: none;
    z-index: 5;
  }
</style>
```

Key behaviors:
- **Mode gate**: pointer handlers no-op unless `mode === "draw"`.
- **Page detection**: on `pointerdown`, walk `target.closest(".page")`
  and read `data-page-number` (mirrors AnnotateLayer's pattern).
- **Stroke commit**: `pointerup` → run `simplifyRdp(raw, 0.5)` →
  `cssPolylineToPdf(simplified, viewport)` → `addInkAnnotation(...)`.
- **Cancel**: `pointercancel` or ESC drops the in-flight stroke; clears
  preview.
- **Eraser**: optional sub-mode (`mode === "erase"`) hit-tests pointer
  against every ink annotation on the page using a per-segment distance
  check; deletes via `removeAnnotation(annot.id)` (re-uses v2.0.6's
  removal API).

### B. 220ms ink-trail-shimmer on stroke commit

When `addInkAnnotation` returns a new annotation, the parent gets
notified via `onstrokecommitted(annot.id)`. Render a one-shot SVG

over 220ms.

```svelte

      <stop offset="0" stop-color="rgba(255,255,255,0)"/>
      <stop offset="0.5" stop-color="rgba(255,255,255,0.95)"/>
      <stop offset="1" stop-color="rgba(255,255,255,0)"/>
      <animate attributeName="x1" from="-0.5" to="1.5" dur="220ms"
               repeatCount="1" fill="freeze"/>
      <animate attributeName="x2" from="0" to="2.0" dur="220ms"
               repeatCount="1" fill="freeze"/>
```

## Codebase-discovery decisions baked in

- **`Annotation` Rust enum** already tagged-union (`serde(tag = "kind",
  rename_all = "snake_case")`) — adding `Ink` is a straight enum-variant
  extension, no struct redesign. Confirmed at
  `src-tauri/src/pdf/annotations.rs:27-29`.
- **`build_annotation_dict()`** is a single match expression — the new
  arm slots in next to `Highlight` and `Note` arms without restructure.
- **`AnnotateLayer.svelte`** already handles a mode union
  `"off" | "highlight" | "note"` (line 19). Extending to `"draw"` is a
  pure type extension; existing mode-gate code generalizes.
- **`slab_append_annotations`** Tauri command takes
  `Vec<Annotation>` directly — *zero* command-signature changes
  needed. The new variant serializes through the existing pipeline.
- **pdfjs `eventBus.pagerendered`** is the right hook for painting
  persisted strokes on render and zoom changes (same hook v2.0.6 uses
  for highlight overlay). Confirmed in `ReaderPanel.svelte:677-688`.
- **Vim-style single-letter `d`** mirrors v2.0.6's `h` mode entry, which
  mirrors `src/lib/vim/keymap.ts`.
- **Onboarding step math**: 6 today → 7 (v2.0.3) → 8 (v2.0.4) → 9
  (v2.0.5) → 10 (v2.0.6) → **11 (v2.0.7)**. Strict-order requirement;

- **i18n namespace `annotations.draw.*` / `palette.draw.*` /
