# v2.0.6 "Margin" 📝 — Persistent Annotations

> **For Hermes:** Use `subagent-driven-development` to implement this plan
> task-by-task. Strict order — do not start any Slice 1+ work until v2.0.5
> ships and is tagged. See *Scheduling note* at the end.

**Goal:** Close the launch-blocker gap where every highlight and sticky-note
the user creates today vanishes the moment they close the document. After
v2.0.6, annotations auto-persist to a sidecar JSON store keyed by file path,
re-render on every reopen, and gain edit/delete/comment affordances — without
ever rewriting the underlying PDF.

**Architecture:**
- Pure-TS `src/lib/annotations.ts` localStorage store under
  `slab.annotations.v1` — per-path bucket of `StoredAnnotation` records
  (uuid + page_index + quads/xy + contents + color + author + createdAt
  + updatedAt). Same eviction policy as `readingPosition.ts` and
  `bookmarks.ts` (oldest-doc-first on quota crash). 200 annotations/doc
  cap, 3 000 total cap.
- `AnnotateLayer.svelte` upgraded from in-memory `pending[]` to
  store-backed `subscribeAnnotations(path)`. Highlights/notes are committed
  the instant they're created (no Save button) and the existing "Save to
  new PDF" affordance becomes an **Export**-style action ("Burn into PDF")
  that lives in the `Annotations` sidebar header.
- `ReaderPanel.svelte` mounts a new always-on **render layer** above the
  pdfjs text layer (re-rendered on every `pagerendered` event) that paints
  the persisted annotations as accent-tinted semi-transparent quads
  (highlights) and floating yellow `■` pins (notes). Pins reveal a popover
  with the note body + Edit / Delete on hover or click.
- WOW: **Quick-highlight `h` toggle** — a new single-key mode that flips
  on Highlight, and on every text selection drops a quad with a 220 ms
  "ink-bloom" CSS animation (opacity 0→0.35, scale 0.92→1.0). Feels like
  a real highlighter.
- New `ActionId::AnnotHighlight` (Mod+H) toggles highlight mode end-to-end.
  Settings-remappable.
- New Settings → Annotations section (color picker for default highlight +
  default note color, author name field, "Clear all annotations for this
  doc" button).
- New Command-Palette group "Annotations" — Toggle Highlight, Toggle Note,
  Burn into PDF, Export as Markdown, Clear all in this document.
- Onboarding tour step #11 ("📝 Annotations").

**Tech Stack:** Svelte 5 (`$state`/`$props`/`$derived`), TS for store, Rust
(no new code needed for happy path — the existing `slab_append_annotations`
and `slab_export_annotations_md` Tauri commands cover the export-to-PDF and
export-to-Markdown paths). Two **brand-new** Tauri commands wrap the store
contents for those export paths so the user can keep all their work
side-car-only OR burn to PDF on demand (their choice).

**LOC budget:** ~990 net LOC of non-test code (excluding JSON i18n and
lockfile changes); ~140 LOC of new tests. **8 commits across 6 slices + 1
pre-flight.**

```ts
// src/lib/annotations.ts
// Persistent annotations store backed by localStorage.
//
// Why a TS store and not a Rust SQLite db?
//   1. The user can move/rename a PDF; we'd then have orphaned rows. A
//      per-path bucket is simpler and survives the same way `bookmarks.ts`
//      and `readingPosition.ts` already do.
//   2. Annotations never need full-text search across documents (yet).
//   3. Switching to SQLite later is a single file swap — the public
//      function surface (addAnnotation, removeAnnotation, ...) is the
//      stable contract.
//
// Schema design choices documented next to each field.
//
// Eviction strategy: identical to readingPosition.ts and bookmarks.ts —
// per-doc cap (200 annotations) + total cap (3000) + retry-on-quota by
// dropping the oldest-doc-first bucket whole.
//
// On disk: { "slab.annotations.v1": { "<absolute-path>": StoredAnnotation[], ... } }

const KEY = "slab.annotations.v1";
const PER_DOC_LIMIT = 200;
const TOTAL_LIMIT = 3_000;

/** Stored shape — superset of `PendingAnnotation` from AnnotateLayer.svelte
 *  with timestamps + a stable id. Serde-compatible with the Rust
 *  `Annotation` enum's tagged-union JSON form so we can ship the same
 *  bytes through `slab_append_annotations` for a one-click PDF burn. */
export type StoredAnnotation =
  | {
      id: string;             // crypto.randomUUID()
      kind: "highlight";
      page_index: number;     // 0-based to match Rust
      quads: number[][];      // each is 8 floats (TL,TR,BL,BR)
      contents: string;
      author: string;
      color: [number, number, number]; // 0..1 RGB, defaults to [1.0, 0.85, 0.10]
      createdAt: number;      // unix ms
      updatedAt: number;      // unix ms
    }
  | {
      id: string;
      kind: "note";
      page_index: number;
      xy: [number, number];   // PDF user space, anchor at lower-left
      contents: string;
      author: string;
      color: [number, number, number]; // defaults to [1.0, 0.85, 0.10]
      createdAt: number;
      updatedAt: number;
    };

type AnnotationsByPath = Record<string, StoredAnnotation[]>;
type Listener = (path: string, list: StoredAnnotation[]) => void;
const listeners = new Set<Listener>();
```

### Eviction policy (matches `bookmarks.ts` line-for-line — see existing impl)

```ts
function capDoc(list: StoredAnnotation[]): StoredAnnotation[] {
  if (list.length <= PER_DOC_LIMIT) return list;
  // Drop oldest (by createdAt) until we're under the cap.
  return [...list]
    .sort((a, b) => b.createdAt - a.createdAt)
    .slice(0, PER_DOC_LIMIT);
}

function capTotal(all: AnnotationsByPath): AnnotationsByPath {
  let total = 0;
  for (const v of Object.values(all)) total += v.length;
  if (total <= TOTAL_LIMIT) return all;
  // Drop whole oldest-doc-first buckets (by max(createdAt) per bucket).
  const entries = Object.entries(all)
    .map(([p, list]) => ({
      p,
      list,
      maxAt: list.reduce((m, a) => Math.max(m, a.createdAt), 0),
    }))
    .sort((a, b) => b.maxAt - a.maxAt);
  const kept: AnnotationsByPath = {};
  let kept_total = 0;
  for (const { p, list } of entries) {
    if (kept_total + list.length > TOTAL_LIMIT) continue;
    kept[p] = list;
    kept_total += list.length;
  }
  return kept;
}
```

```ts
// inside ReaderPanel.svelte <script>
function renderAnnotationLayer(pageEl: HTMLElement, pv: any, list: StoredAnnotation[]) {
  // 1. Remove any prior overlay (idempotent re-render).
  pageEl.querySelector(".annot-overlay")?.remove();
  if (!list.length || !pv?.viewport) return;

  const overlay = document.createElement("div");
  overlay.className = "annot-overlay";
  for (const a of list) {
    if (a.page_index !== pv.id - 1) continue;
    if (a.kind === "highlight") {
      for (const q of a.quads) {
        const [tlx, tly, , , blx, bly] = q;
        // Convert PDF point to CSS px via inverse of convertToPdfPoint.
        const [x1, y1] = pv.viewport.convertToViewportPoint(tlx, tly);
        const [x2, y2] = pv.viewport.convertToViewportPoint(blx, bly);
        const div = document.createElement("div");
        div.className = "annot-highlight ink-bloom";
        div.style.cssText = `left:${Math.min(x1,x2)}px;top:${Math.min(y1,y2)}px;
          width:${Math.abs(x2-x1)}px;height:${Math.abs(y2-y1)}px;
          background: rgba(${(a.color[0]*255)|0},${(a.color[1]*255)|0},${(a.color[2]*255)|0},0.32);`;
        div.dataset.annotId = a.id;
        overlay.appendChild(div);
      }
    } else {
      const [x, y] = pv.viewport.convertToViewportPoint(a.xy[0], a.xy[1]);
      const pin = document.createElement("button");
      pin.className = "annot-note-pin";
      pin.style.cssText = `left:${x - 8}px;top:${y - 8}px;`;
      pin.title = a.contents || "(empty note)";
      pin.dataset.annotId = a.id;
      pin.onclick = (e) => { e.preventDefault(); openNotePopover(a); };
      overlay.appendChild(pin);
    }
  }
  pageEl.appendChild(overlay);
}
```

```ts
// Listen for unmodified 'h' anywhere in the reader; ignore when typing.
function isTypingTarget(t: EventTarget | null): boolean {
  const el = t as HTMLElement | null;
  if (!el) return false;
  if (el.isContentEditable) return true;
  const tag = el.tagName;
  return tag === "INPUT" || tag === "TEXTAREA" || tag === "SELECT";
}

function onGlobalKeydown(e: KeyboardEvent) {
  // ...existing handlers...
  if (e.key === "h" && !e.metaKey && !e.ctrlKey && !e.altKey && !isTypingTarget(e.target)) {
    e.preventDefault();
    annotMode = annotMode === "highlight" ? "off" : "highlight";
    document.body.classList.toggle("quick-highlight-mode", annotMode === "highlight");
  }
}
```

```ts
async function burnIntoPdf() {
  const dest = await saveDialog({
    title: "Burn annotations into PDF",
    defaultPath: path.replace(/\.pdf$/i, "-annotated.pdf"),
    filters: [{ name: "PDF", extensions: ["pdf"] }],
  });
  if (!dest) return;
  const list = listAnnotations(path);
  const cleaned = toAppendableAnnotations(list); // strips id/createdAt/updatedAt
  const count = await invoke<number>("slab_append_annotations", {
    input: path, output: dest, annotations: cleaned,
  });
  toast.success(`Burned ${count} annotation${count === 1 ? "" : "s"} into ${dest}`);
}
```

## Why v2.0.6 over v0.10.0 Beacon?

(Documenting for future ticks so we don't re-debate this.)

1. **Launch-blocker math.** Adobe / PDF Expert / Foxit / even macOS
   Preview persist annotations. Slab today does not. A reviewer who
   tries v2.0.5 expecting parity with paid products will close the app
   the moment their first highlight disappears. v0.10.0 Beacon has
   *some* of its surface area already shipped (v1.5–v1.9 brought chat,
   citations, glossary, study, voice, PII, vision); v2.0.6 closes a
   true zero-to-one gap.
2. **DRY-against-pipeline.** v2.0.6's store mirrors v2.0.4's
   `readingPosition.ts` and v2.0.5's `bookmarks.ts` line-for-line.
   Writing it now while those patterns are fresh costs ~30% less than
   writing it after v0.10.0 lands a separate AI-state store.
3. **Cross-cutting bonus.** v2.0.6 introduces the first "persistent
   side-car JSON keyed by file path" pattern that v2.0.7 (drawings),
   v2.0.8 (comments threading), and v2.0.9 (per-doc reading speed)
   can all reuse without re-discovery.
4. **Beacon is queued.** `.cron-state/proposals/v0.10.0-beacon-ai.md`
   is still on disk; it'll get its own writing-plans tick when the
   v2.0.x annotation arc concludes (probably v2.0.7 or v2.0.8).
