# v2.2.0 "Atlas" — Cross-Document Full-Text Search Implementation Plan

> **For Hermes:** Use `subagent-driven-development` to execute this plan
> task-by-task. Spec-compliance review after every task, code-quality
> review after spec passes, proceed only when both approve. Sequence is
> strict: a slice's Tauri command must exist before the slice's UI consumes it.

**Goal:** Turn Slab's existing single-doc reader + library scaffold into a
**multi-document workstation** where a paralegal can paste a folder of 200
contracts and instant-search across all of them in <100 ms, with ranked
snippets, page-jump, and highlight-on-open.

**The buyer story:** _"A 6-person law firm replaces their $1 434/yr team
Acrobat Pro bill (6 × $239/yr) with Slab. Atlas is the feature their
paralegal opens 40 times a day."_

**Architecture (4 layers):**

1. **`pdf::library::fts`** — SQLite FTS5 virtual table (`library_fts`)
   colocated with the existing `~/.slab/library.sqlite`. Tokenizer
   `unicode61 remove_diacritics 2`. Schema-versioned via `PRAGMA
   user_version` (bump 3 → 4). External-content table keyed on
   `library_documents.id` so we don't double-store text. Triggers keep
   FTS in sync on document delete.

2. **`pdf::library::indexer`** — page-text extractor invoked by the existing
   `scanner` after a doc is upserted. Reuses the already-shipped pdfium
   page-text path from `pdf::extract`. Streams page-by-page rows
   `(doc_id, page_index, text)` into FTS5. OCR-pending docs are skipped
   (the existing `ocr_queue` will re-feed them later through the same
   path).

3. **`slab_library_search` Tauri command** — accepts `{ query: String,
   limit: u32, folder_id: Option<i64>, tag_ids: Option<Vec<i64>> }`,
   returns `Vec<SearchHit>` where each hit carries `doc_id`, `path`,
   `title`, `page_index`, `snippet` (FTS5 `snippet()` w/ `<mark>` tags),
   `rank` (bm25). Cap snippet length at 280 chars.

4. **`SearchPanel.svelte` + Command Palette + Cmd-Shift-F shortcut +
   highlight-on-open** — the visible product. Live debounced query
   input, folder/tag filter chips, virtualised result list, click →
   open doc → scroll to page → highlight occurrences (reuse existing
   `pdfHighlight` helper).

**Tech Stack:** `rusqlite 0.39` (already a dep, bundled — FTS5 ships in
the bundled libsqlite), no new Rust deps. Frontend uses existing Svelte
5 + Liquid Glass classes.

**Why FTS5 not Tantivy?** (a) Already linked; bundled-sqlite ships FTS5.
(b) Same DB file → atomic delete-cascades from `library_documents`. (c)
Tantivy adds 12 MB to the binary + a separate index dir we'd have to
migrate. (d) FTS5 hits 1 ms / 200-doc query in benchmarks — fast
enough; bm25 ranking is built-in.

**Buy-Button verdict (judge plan before write):** 4/4 PASS.
- **Pay-for-it**: Acrobat Pro $239/yr "Search Multiple PDFs" is a
  paid-tier feature; legal review SaaS (Everlaw, Relativity) charges
  $50/user/mo for the same primitive. Slab ships it free + offline.
- **Pick-us**: PDF Expert, Foxit, Preview all force one-doc-at-a-time
  search. pdfgrep is CLI-only. No free GUI cross-platform ships this.
- **Notice-it**: New nav entry, new Cmd-Shift-F shortcut, new palette
  entry, prominent in onboarding tour.
- **Tell-a-friend**: "paste a folder, type 'indemnification', see every

**WOW** ⭐: **Live-typing search-as-you-type with a 180 ms cubic-bezier

```rust
//! FTS5-backed page-level full-text index, colocated with the library DB.
//!
//! Schema v4 adds the `library_fts` external-content virtual table keyed on
//! `(doc_id, page_index)`. We deliberately don't use `content=` linking
//! because page-text rows don't live in another table — they live only in
//! the FTS index.

use anyhow::{Context, Result};
use rusqlite::{params, Connection};

/// Idempotent migration from schema v3 → v4. Safe to call repeatedly.
pub fn migrate(conn: &Connection) -> Result<()> {
    let version: i64 = conn
        .pragma_query_value(None, "user_version", |r| r.get(0))
        .unwrap_or(0);
    if version >= 4 {
        return Ok(());
    }
    conn.execute_batch(
        r#"
        CREATE VIRTUAL TABLE IF NOT EXISTS library_fts USING fts5(
            doc_id UNINDEXED,
            page_index UNINDEXED,
            text,
            tokenize = 'unicode61 remove_diacritics 2'
        );

        CREATE TRIGGER IF NOT EXISTS library_fts_cascade_delete
        AFTER DELETE ON library_documents
        BEGIN
            DELETE FROM library_fts WHERE doc_id = OLD.id;
        END;

        PRAGMA user_version = 4;
        "#,
    )
    .context("apply fts5 schema v4")?;
    Ok(())
}

/// Replace all FTS rows for a document, then insert the new page set.
/// Caller is responsible for empty `pages` → noop semantics.
pub fn index_doc(conn: &Connection, doc_id: i64, pages: &[String]) -> Result<()> {
    let tx = conn.unchecked_transaction()?;
    tx.execute("DELETE FROM library_fts WHERE doc_id = ?1", params![doc_id])?;
    {
        let mut stmt = tx.prepare_cached(
            "INSERT INTO library_fts (doc_id, page_index, text) VALUES (?1, ?2, ?3)",
        )?;
        for (i, page) in pages.iter().enumerate() {
            if page.trim().is_empty() {
                continue;
            }
            stmt.execute(params![doc_id, i as i64, page])?;
        }
    }
    tx.commit()?;
    Ok(())
}
```

```rust
use anyhow::Result;
use rusqlite::{params_from_iter, Connection};
use serde::Serialize;

#[derive(Debug, Clone, Serialize)]
pub struct SearchHit {
    pub doc_id: i64,
    pub path: String,
    pub title: Option<String>,
    pub page_index: i64,
    pub snippet: String,
    pub rank: f64,
}

/// FTS5 ranked search across the entire library.
///
/// `folder_id` and `tag_ids` are optional pre-filters applied as a join
/// against `library_documents` and `library_doc_tags`.
pub fn search(
    conn: &Connection,
    query: &str,
    limit: u32,
    folder_id: Option<i64>,
    tag_ids: Option<&[i64]>,
) -> Result<Vec<SearchHit>> {
    let q = query.trim();
    if q.is_empty() {
        return Ok(Vec::new());
    }

    // FTS5 MATCH grammar: quote any token that isn't bare alphanumerics to
    // stay safe from accidental column-filter syntax.
    let safe_query = sanitize_match_query(q);

    let mut sql = String::from(
        "SELECT f.doc_id, d.path, d.title, f.page_index, \
                snippet(library_fts, 2, '<mark>', '</mark>', '…', 12) AS snip, \
                bm25(library_fts) AS r \
         FROM library_fts f \
         JOIN library_documents d ON d.id = f.doc_id ",
    );
    let mut params: Vec<Box<dyn rusqlite::ToSql>> = Vec::new();
    let mut where_clauses = vec!["library_fts MATCH ?".to_string()];
    params.push(Box::new(safe_query));

    if let Some(fid) = folder_id {
        where_clauses.push("d.folder_id = ?".to_string());
        params.push(Box::new(fid));
    }
    if let Some(tids) = tag_ids {
        if !tids.is_empty() {
            let placeholders = vec!["?"; tids.len()].join(",");
            where_clauses.push(format!(
                "d.id IN (SELECT doc_id FROM library_doc_tags WHERE tag_id IN ({}))",
                placeholders
            ));
            for t in tids {
                params.push(Box::new(*t));
            }
        }
    }

    sql.push_str("WHERE ");
    sql.push_str(&where_clauses.join(" AND "));
    sql.push_str(" ORDER BY r LIMIT ?");
    params.push(Box::new(limit as i64));

    let mut stmt = conn.prepare(&sql)?;
    let rows = stmt
        .query_map(params_from_iter(params.iter().map(|b| b.as_ref())), |row| {
            Ok(SearchHit {
                doc_id: row.get(0)?,
                path: row.get(1)?,
                title: row.get(2)?,
                page_index: row.get(3)?,
                snippet: row.get(4)?,
                rank: row.get(5)?,
            })
        })?
        .collect::<Result<Vec<_>, _>>()?;
    Ok(rows)
}

/// Strip FTS5 column-filter and special tokens. Conservative: bare
/// alphanumerics + space pass through; everything else becomes a phrase.
fn sanitize_match_query(q: &str) -> String {
    let safe = q.chars().all(|c| c.is_alphanumeric() || c.is_whitespace());
    if safe {
        q.to_string()
    } else {
        format!("\"{}\"", q.replace('"', ""))
    }
}
```

import { invoke } from "@tauri-apps/api/core";

export interface SearchHit {
  doc_id: number;
  path: string;
  title: string | null;
  page_index: number;
  snippet: string; // raw HTML — contains <mark> tags
  rank: number;
}

export async function librarySearch(args: {
  query: string;
  limit?: number;
  folder_id?: number;
  tag_ids?: number[];
}): Promise<SearchHit[]> {
  if (!args.query.trim()) return [];
  return await invoke<SearchHit[]>("slab_library_search", { args });
}

## Slice 4 — Highlight-on-open + page-jump

**Objective:** Clicking a result must scroll the reader to the matching

- Modify: `src/lib/panels/ReaderPanel.svelte` (consume `highlightQuery` prop,
  call existing pdfHighlight helper after page render)

**Step 1: Extend `openDocAtPage` signature**

```ts
export function openDocAtPage(docId: number, page: number, highlightQuery?: string) {
  // emit event with payload; ReaderPanel listens.
  window.dispatchEvent(new CustomEvent("slab:open-doc-at", {
    detail: { docId, page, highlightQuery },
  }));
}
```

**Step 2: ReaderPanel hooks the event**, requests the doc through the
existing open flow, awaits page render, then for each match (case-
insensitive) creates a yellow highlight overlay on the canvas, scrolling
the first match into view.

import { describe, it, expect, vi } from "vitest";
