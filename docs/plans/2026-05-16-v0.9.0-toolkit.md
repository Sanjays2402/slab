# v0.9.0 "Toolkit" Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add high-leverage PDF utilities that pdftk/qpdf users rely on, native to Slab — `flatten`, `sanitize`, and `repair` — as the v0.9.0 release. Decrypt / sign / pdfa pushed to v0.9.1+.

**Architecture:** Three independent modules under `src-tauri/src/pdf/`, each pure-Rust on `lopdf`, each wired to the CLI (`slab <verb>`) and Tauri (`slab_<verb>`). Each feature is one vertical slice: backend → unit tests → CLI subcommand → Tauri command → frontend toggle/panel → README + release notes.

**Tech Stack:** Existing Rust + `lopdf` + `thiserror`. Zero new Rust deps for flatten/sanitize/repair. Decrypt (v0.9.1) reuses the existing `pdf::encrypt::decrypt` path. Sign (v0.9.2) will need a PKCS#7 crate (decision deferred).

## v0.9.0 scope (3 features, ~15 sub-tasks)

### Feature A — `pdf::flatten`

**What it does:** Bake interactive overlays into page content streams so the output PDF has no editable form fields and no live annotations — just a static picture. Standard pdftk `flatten` semantics.

**How:** For each page's `/Annots` array, for each annot whose `/AP /N` references a Form XObject:
1. Compute a CTM mapping the Form's `/BBox` onto the annotation's `/Rect`.
2. Register the Form XObject in the page's `/Resources /XObject` under a unique name.
3. Append `q <ctm> cm /<name> Do Q` to the page's `/Contents`.

Then delete every page's `/Annots` and remove `/AcroForm` from the catalog. Result: visual appearance preserved, interactivity gone.

Sub-tasks:
1. Module scaffold + register in `pdf.rs`; types `FlattenOpts`, `FlattenReport`.
2. Core `flatten()` impl + 3 unit tests (annot with /AP baked, page without /Annots passes through, /AcroForm removed).
3. CLI `slab flatten <in> -o <out>`.
4. Tauri `slab_flatten`.
5. Frontend wiring (deferred — separate tick after backend lands).

### Feature B — `pdf::sanitize`

**What it does:** Strip JavaScript, embedded files, launch actions, external URI actions, and OpenAction — the "make this PDF safe to forward" pass. Reuses the metadata::strip pattern.

**How:**
- Catalog: remove `/Names /JavaScript`, `/Names /EmbeddedFiles`, `/OpenAction`, `/AA`.
- Per page: remove `/AA`, walk `/Annots` and drop entries with `/A` of type `/JavaScript`, `/Launch`, `/URI` (unless `--allow-links`).
- AcroForm: remove `/XFA` (XML forms with embedded scripts).

Sub-tasks:
1. Module scaffold + types `SanitizeOpts { keep_links: bool }`, `SanitizeReport { js_removed, embeds_removed, launch_removed, uri_removed }`.
2. Core impl + 4 unit tests (each strip path).
3. CLI `slab sanitize <in> -o <out> [--keep-links]`.
4. Tauri `slab_sanitize`.

### Feature C — `pdf::repair`

**What it does:** Rebuild the xref table and drop dangling/unreachable objects via lopdf's compress/clean pipeline. Useful for partially-corrupt PDFs that Reader fails to parse.

**How:**
1. `Document::load_filtered` with a permissive filter, then `prune_objects()` + `compress()` and save with a fresh xref.
2. Report objects-before / objects-after + bytes-before / bytes-after.

Sub-tasks:
1. Module scaffold + types `RepairReport { objects_before, objects_after, bytes_before, bytes_after }`.
2. Core impl + 2 unit tests (round-trips valid PDF; produces smaller object count for synthetic-bloated input).
3. CLI `slab repair <in> -o <out>`.
4. Tauri `slab_repair`.

## Risk + mitigation

- **Annot `/AP /N` may be a dict, not a stream** — handle both: pick value matching `/AS`, else first.
- **Form XObject may have its own `/Matrix`** — leave it alone; Do operator handles it. Our CTM only maps BBox → Rect.
- **`/Annots` may be an indirect reference, not inline** — resolve before iterating.
- **Repair against truly corrupt input may still fail** — that's OK; surface `PdfError::Lopdf` with the original message.
