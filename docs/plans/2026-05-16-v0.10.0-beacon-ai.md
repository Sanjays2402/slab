## Mission
Make Slab the **first AI-native local PDF editor**. Five user-visible sub-features, all powered by a pluggable AI provider abstraction (local-first via Ollama, fallback to OpenAI-compatible HTTP API including GitHub Copilot's OAuth-gated proxy).

## Five sub-features (each ~1-2 ticks)

### 1. **Chat Panel** — Q&A with the open PDF
- New right-rail panel `BeaconChatPanel.svelte`
- Backend extracts full text + per-page hints, builds a context window
- User asks "what does this say about X?" → AI answers with page-number citations
- Streaming responses (SSE-style line buffer)
- Conversation history pinned to PDF (sqlite at `~/.slab/chats.db`)
- Tauri command: `slab_beacon_chat(pdf_path, question, history) -> AsyncStream<ChatDelta>`

### 2. **Auto-Summary** — One-paragraph TL;DR on PDF open
- New top-of-reader strip `SummaryStrip.svelte` (collapsible, off by default for >50pp)
- Backend runs single LLM call on text extract with bounded prompt
- 3 lengths: TL;DR (1 sentence), Short (1 paragraph), Long (5 bullets)
- Cached by PDF hash at `~/.slab/summaries.db`
- Tauri command: `slab_beacon_summary(pdf_path, length) -> Summary`

### 3. **Semantic Search** — Search by meaning across all opened PDFs
- New left-rail panel `BeaconSearchPanel.svelte`
- Chunks every opened PDF by paragraph, embeds via Ollama `nomic-embed-text` (or OpenAI `text-embedding-3-small`)
- Stores embeddings in sqlite vector table at `~/.slab/embeddings.db` (use `sqlite-vec` extension)
- Query: top-K by cosine similarity, jumps to page + highlights match
- Tauri commands: `slab_beacon_index(pdf_path)`, `slab_beacon_search(query, top_k)`

### 4. **PII Highlighter** — One-click redaction prep
- Add button "🔒 Find PII" in toolbar
- Backend uses regex pre-filter (emails/phones/SSN/credit-card patterns) + LLM second-pass for names/addresses
- Returns coordinate boxes → drawn as red highlights with one-click redact-all
- Reuses existing `pdf::sanitize` flatten path to make permanent
- Tauri command: `slab_beacon_pii(pdf_path) -> Vec<PiiHit>`

### 5. **Selection Actions** — Right-click context menu on any text selection
- Frontend: extend selection handler with menu items: **Translate / Explain / Define / Tweet-rewrite / Custom prompt…**
- Backend: single Tauri command takes selection + action enum, returns text
- Result appears in floating bubble next to selection (Svelte tooltip)
- Tauri command: `slab_beacon_selection_action(text, action: SelectionAction, target_lang?) -> String`

## Architecture

### Provider abstraction (`src-tauri/src/ai/provider.rs`)
```rust
#[async_trait]
pub trait AiProvider: Send + Sync {
    async fn chat(&self, msgs: Vec<ChatMessage>, opts: ChatOpts) -> Result<ChatStream, AiError>;
    async fn embed(&self, texts: Vec<String>) -> Result<Vec<Vec<f32>>, AiError>;
    fn name(&self) -> &'static str;
}

pub enum AiError {
    ProviderUnavailable(String),
    RateLimited,
    InvalidResponse(String),
    Network(String),
}
```

### Two impls
- `OllamaProvider`: hits `http://localhost:11434/api/chat` + `/api/embeddings`. Default. Models: `llama3.2:3b` (chat), `nomic-embed-text` (embed). Free, local, private.
- `OpenAiCompatibleProvider`: configurable `base_url` + `api_key` (env or settings panel). Supports OpenAI, Copilot (after OAuth), Anthropic via proxy, any local OpenAI-compat server.

### Provider selection
- New `~/.slab/config.toml` with `[beacon]` section: `provider = "ollama" | "openai"`, `chat_model`, `embed_model`, `base_url`, `api_key_env`
- Settings panel in UI lets user switch (no code change)
- Friendly error if Ollama not running: "Install Ollama at ollama.com, or switch provider in Settings"

### Storage
- New crate dep: `rusqlite` with `sqlite-vec` extension for embedding search
- Tables: `pdfs(hash, path, indexed_at)`, `chunks(pdf_hash, page, text, embedding BLOB)`, `chats(pdf_hash, ts, role, content)`, `summaries(pdf_hash, length, content)`
