# v1.4.0 "Bench" — Slices 9 + 10 Implementation Plan

> **For Hermes:** Execute on `feature/v1.4.0-bench-slices-9-10`. Merge
> back into `feature/v1.4.0-bench` (the rollup branch) at end of tick.

**Goal:** Close out the Bench feature so it's release-ready. Slice 9
adds a destructive-action confirmation step to plugin uninstall.
Slice 10 ships the maintainer docs + a seed `slab-plugins` repo
payload so the marketplace has something to point at on day one.

**Architecture:** Slice 9 is a Svelte presentational component
(`UninstallConfirmModal.svelte`) wired into `PluginsPanel.svelte` and
`PluginDetailDrawer.svelte`. The current uninstall path fires
immediately on click — bad UX for a destructive op. After this slice
the click pops a confirmation modal that lists what's being removed
(plugin id, version, plugin dir under `~/.slab/plugins/`) and requires
an explicit "Uninstall" press. Esc / backdrop click / Cancel all
abort.

Slice 10 is pure docs. Two new markdown files:
- `docs/MARKETPLACE.md` — how Slab's marketplace works + how to submit
  a plugin to the curated index.
- `docs/marketplace-seed/` — a drop-in payload for the future
  `slab-plugins` GitHub repo (README + example `index.json`).

Plus a small update to `docs/PLUGINS.md` so plugin authors discover the
marketplace from inside the existing plugin docs.

**Tech Stack:** Svelte 5, TypeScript, JSON (i18n), Markdown.

## Slice 9 — Uninstall confirmation modal

### Task 9.1: Create `UninstallConfirmModal.svelte`

**Objective:** New modal component, parallel to `DecryptModal.svelte`,
that asks the user to confirm destruction of a plugin install.

**Files:**
- Create: `src/lib/components/UninstallConfirmModal.svelte`

**Surface:**
- Props: `{ name, version, id, busy, onConfirm, onCancel }`.
- Renders a centered modal with a warning glyph, the plugin name +
  version, the install path (`~/.slab/plugins/<id>/`), a confirmation
  question, and two buttons (Cancel / Uninstall).
- Esc cancels, Enter confirms, backdrop click cancels.
- All strings via `$tStore("plugins.uninstallConfirm.*")` keys —
  i18n-clean from the start.

### Task 9.2: Add `plugins.uninstallConfirm.*` keys to en.json

**Objective:** Source-of-truth keys for the new modal.

**Files:**
- Modify: `src/lib/i18n/en.json`

New keys (append to plugins block):
```json
"plugins.uninstallConfirm.title": "Uninstall {name}?",
"plugins.uninstallConfirm.body": "This removes the plugin files from your machine. You can reinstall it from the marketplace at any time.",
"plugins.uninstallConfirm.path": "Installed at",
"plugins.uninstallConfirm.version": "Version",
"plugins.uninstallConfirm.cancel": "Cancel",
"plugins.uninstallConfirm.confirm": "Uninstall",
"plugins.uninstallConfirm.working": "Uninstalling…"
```

### Task 9.3: Mirror keys into es.json, fr.json, ar.json

**Objective:** Stay i18n-complete (Slab ships 4 locales since v1.2).

**Files:**
- Modify: `src/lib/i18n/es.json`
- Modify: `src/lib/i18n/fr.json`
- Modify: `src/lib/i18n/ar.json`

Translations done by hand (short strings, high-school competent).

### Task 9.4: Wire modal into `PluginsPanel.svelte`

**Objective:** Replace the direct `onUninstall(entry)` call with a
modal-mediated flow.

**Files:**
- Modify: `src/lib/panels/PluginsPanel.svelte`

Add `pendingUninstall: { entry, busy } | null` state. The marketplace
card's Uninstall button now sets `pendingUninstall`. The modal's
confirm handler runs the existing uninstall path. The cancel handler
clears state. Modal is rendered at the bottom of the panel like
`installModal`.

### Task 9.5: Wire modal into `PluginDetailDrawer.svelte`

**Objective:** Same flow from the drawer's Uninstall button.

**Files:**
- Modify: `src/lib/components/PluginDetailDrawer.svelte` (or, simpler,
  let the drawer fire `onAction` which the parent already intercepts —
  in which case the parent already gets the chance to show the modal).

After reading the drawer, the cleanest fix is in the **parent**: the
drawer fires `onAction(entry)` which today bypasses the modal flow.
Update the parent's `onAction` handler to route to the modal when
`status === "installed"`.

## Slice 10 — Marketplace docs + seed `slab-plugins` repo

### Task 10.1: Create `docs/MARKETPLACE.md`

**Objective:** The maintainer-facing doc that explains:
- What the marketplace is + how Slab fetches it
- Trust model (Ed25519 signature over each index entry, hardcoded key
  in the binary)
- Step-by-step submission guide for plugin authors
- `slab-sign-plugin` CLI walkthrough
- Index schema reference
- Update workflow

### Task 10.2: Update `docs/PLUGINS.md`

**Objective:** Add a "Distribute via the marketplace" section near the
top, pointing readers to `docs/MARKETPLACE.md`.

### Task 10.3: Create `docs/marketplace-seed/README.md`

**Objective:** A drop-in README for the future `Sanjays2402/slab-plugins`
repo. Explains the repo's purpose, links back to `docs/MARKETPLACE.md`
in the main repo, lists the example plugins.

### Task 10.4: Create `docs/marketplace-seed/index.json.example`

**Objective:** A working example `index.json` with 1-3 stub entries
demonstrating the schema. Includes placeholder signature + sha256 so
authors see the structure even if the values aren't valid.

### Task 10.5: Quality gates + commit

Run `pnpm check`. Markdown changes don't affect the build but
svelte-check confirms nothing broke.

Commit: `docs(marketplace): submission guide + seed slab-plugins repo (Slice 10)`
