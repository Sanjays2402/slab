# v3.11.0 "Signet Pro" Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Close the remaining Acrobat Pro signing gap with three enterprise-grade
capabilities — RFC 3161 timestamping (long-term validation), visible signature
appearances (name/date/reason rendered into a form-field widget), and batch
sign-many across a folder — all 100% offline.

**Architecture:** Extends `pdf/signet/` (v3.10.0) with three new submodules:
`tsa` (RFC 3161 timestamp-token client + offline-token-bag fallback), `appearance`
(builds the AP/N XObject rendered into a Widget annotation for the signature
field), and `batch` (parallel `sign_pdf` over an input folder with a shared
`SigningIdentity`). All three plug into `SignOptions` and `sign_pdf` without
changing the existing public API for callers that don't want them.

**Tech Stack:** Rust (RustCrypto: `cms`, `rsa`, `der`, `x509-cert`; reqwest in
`rustls-tls`-only mode for TSA, gated behind an offline-default flag),
lopdf for PDF object splicing, rayon for batch parallelism, Svelte 5 for UI
(BatchSignPanel + AppearancePreview + TSA settings section).

**Buy-button test passes:** Pay-for-it (TSA + batch are Acrobat Pro $239/yr
features), Pick-us (no Linux signing tool does RFC 3161 offline), Tell-a-friend
(drop-folder-batch-sign demo screenshot).

## Task 2: RFC 3161 TimeStampReq encoder

**Objective:** Encode a `TimeStampReq` ASN.1 structure (RFC 3161 §2.4.1) given
the SHA-256 hash of a CMS SignerInfo's `signature` field. Pure encoding, no
network.

**Files:**
- Modify: `src-tauri/src/pdf/signet_pro/tsa.rs`
- Test: same file (inline `#[cfg(test)] mod tests`)

**Step 1: Write failing test**

```rust
#[test]
fn timestamp_req_encodes_sha256_imprint() {
    let digest = [0x42u8; 32];
    let req = build_timestamp_req(&digest, /*nonce*/ Some(0xDEADBEEF))
        .expect("encode");
    // RFC 3161 TimeStampReq is a SEQUENCE; first byte = 0x30.
    assert_eq!(req[0], 0x30);
    // Imprint OID for SHA-256 is 2.16.840.1.101.3.4.2.1 — appears in DER.
    let sha256_oid = [0x60, 0x86, 0x48, 0x01, 0x65, 0x03, 0x04, 0x02, 0x01];
    assert!(req.windows(sha256_oid.len()).any(|w| w == sha256_oid),
            "SHA-256 OID missing from TimeStampReq DER");
    assert!(req.windows(32).any(|w| w == digest),
            "digest bytes missing from TimeStampReq DER");
}
```

**Step 2: Run — expect compile failure** (`build_timestamp_req` undefined).

**Step 3: Implement using `der` + `cms` crates**

```rust
use der::{asn1::OctetString, Encode, Sequence};
use cms::content_info::CmsVersion;
use spki::ObjectIdentifier;

const SHA256_OID: ObjectIdentifier = ObjectIdentifier::new_unwrap("2.16.840.1.101.3.4.2.1");

#[derive(Sequence)]
struct MessageImprint {
    hash_algorithm: spki::AlgorithmIdentifierOwned,
    hashed_message: OctetString,
}

#[derive(Sequence)]
struct TimeStampReq {
    version: i32,
    message_imprint: MessageImprint,
    #[asn1(optional = "true")]
    nonce: Option<i64>,
    #[asn1(optional = "true", default = "default_true")]
    cert_req: bool,
}

fn default_true() -> bool { true }

pub fn build_timestamp_req(digest: &[u8; 32], nonce: Option<i64>) -> Result<Vec<u8>, der::Error> {
    let req = TimeStampReq {
        version: 1,
        message_imprint: MessageImprint {
            hash_algorithm: spki::AlgorithmIdentifierOwned {
                oid: SHA256_OID,
                parameters: None,
            },
            hashed_message: OctetString::new(digest.to_vec())?,
        },
        nonce,
        cert_req: true,
    };
    req.to_der()
}
```

**Step 4:** `cargo test -p slab-app tsa::tests` — PASS.

**Step 5:** Commit `feat(signet_pro): RFC 3161 TimeStampReq encoder`.
