# v2.0.3 "Beacon Settings" Implementation Plan

> **For Hermes (Cake / cron):** Execute via subagent-driven-development —
> one fresh subagent per slice, two-stage review (spec compliance → code
> quality), proceed only when both pass.
>
> **Branch:** `feature/v2.0.3-beacon-settings` (cut from `main` AFTER v2.0.2
> ships; see scheduling note at the end of this plan).

**Goal:** Ship a first-class, no-config-file-editing Beacon AI Settings UI —
provider picker (Ollama / OpenAI-compatible), live model dropdown that
introspects a running Ollama daemon, connection-test button with friendly
errors, and a Beacon onboarding step that gets users from "0 → AI is
working" in under 60 seconds.

**Architecture (3 sentences):**
- Add a thin `ai::introspect` Rust module that talks to provider HTTP
  surfaces to list available models. For Ollama that's `GET /api/tags`;
  for OpenAI-compatible it's `GET /v1/models`. Failures map to typed
  `IntrospectError` variants the frontend translates into UI states.
- Expose three new Tauri commands: `slab_beacon_provider_test`,
  `slab_beacon_list_models`, and `slab_beacon_default_config` (the last
  is a pure helper so the Settings UI can offer a one-click "reset to
  defaults" without duplicating defaults across two languages).
- Frontend: a new `BeaconSettingsSection` rendered inside
  `SettingsPanel.svelte` directly below "Language", plus an Onboarding
  step that calls the same Tauri commands.

**Tech Stack:**
- Rust: `reqwest` (already a workspace dep), `serde`, `tokio`, existing
  `ai::config::SlabConfig` for read/write.
- Frontend: Svelte 5 runes, existing `notify.ts`, existing `t()` i18n.
- No new runtime dependencies in either tree.

**Buy-Button verdict (release level):**
- **Pick-us PASS** — Adobe ships a single-model cloud-only AI experience
  ($$ subscription required). PDF Expert has no AI. We let users pick
  *their* model from a dropdown of locally-installed ones with zero
  config-file editing. Open-source product giving away the same surface
  Acrobat charges for.
- **Notice-it PASS** — Any returning user sees a new "Beacon AI" section
  in Settings the moment they upgrade. Today there is zero AI surface
  in Settings, even though Beacon has been shipping since v1.5.
- **Tell-a-friend PASS** — "Look, my PDF reader lets me pick which
  llama3 size to use, all local, all free." Screenshot-worthy for
  /r/LocalLLaMA, HN, and the privacy-tech audience.

**WOW moment (Slice 4):** Open Settings → Beacon → the model dropdown
**auto-populates from a live `ollama list`-style query against the
running daemon**. Users with `llama3.2:3b` + `mistral:7b` + `phi3:mini`
on disk see all three in the dropdown in <200ms, with their disk-size
badges (3.0 GB / 4.4 GB / 2.3 GB). No model installed? The dropdown
shows a friendly "No models found — pull one with `ollama pull
llama3.2:3b`" with a one-click copy button.

```rust
//! Provider introspection — list available models, ping for liveness.
//!
//! Each `AiProvider` impl has a different HTTP surface for listing
//! installed/available models. Rather than baking another method into
//! the trait (which would force every alt-provider plugin to implement
//! it), this module owns the introspection logic as pure functions
//! that take a `ProviderKind` + base URL and return a typed result.

use serde::{Deserialize, Serialize};
use std::time::Duration;
use thiserror::Error;

use crate::ai::config::ProviderKind;

/// One model the provider reports as available.
///
/// Field ordering and naming match what the Beacon Settings UI
/// renders — no transformation layer in the frontend.
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct ModelDescriptor {
    /// Provider-specific model id, suitable for `ChatOpts::model`.
    pub id: String,
    /// Human-friendly label. For Ollama, same as `id`. For OpenAI,
    /// the API doesn't differentiate — id and label are the same.
    pub label: String,
    /// Bytes on disk (Ollama only — OpenAI cloud models report `None`).
    pub size_bytes: Option<u64>,
    /// `true` if the model can produce embeddings (best-effort heuristic).
    pub embedding_capable: bool,
}

/// Errors `models()` and `ping()` can return.
#[derive(Debug, Error)]
pub enum IntrospectError {
    /// The provider HTTP surface is unreachable. The frontend uses this
    /// to render the "Install Ollama at ollama.com" hint card.
    #[error("provider unreachable: {0}")]
    Unreachable(String),

    /// The provider responded but the response wasn't valid JSON of the
    /// expected shape. Likely a version mismatch (e.g. Ollama < 0.1.x).
    #[error("invalid response from provider: {0}")]
    InvalidResponse(String),

    /// HTTP error with a status code (4xx, 5xx). Authentication failures
    /// land here (e.g. OpenAI without an API key returns 401).
    #[error("provider error {status}: {body}")]
    HttpError { status: u16, body: String },

    /// Wrapped reqwest error for anything not classified above.
    #[error("transport error: {0}")]
    Transport(String),
}

/// List available models from the given provider.
///
/// `base_url` is the same string the user enters in Settings (e.g.
/// `http://localhost:11434` for Ollama). For OpenAI, append `/v1` if
/// the URL doesn't already end with it.
pub async fn models(
    kind: ProviderKind,
    base_url: &str,
    api_key: Option<&str>,
) -> Result<Vec<ModelDescriptor>, IntrospectError> {
    match kind {
        ProviderKind::Ollama => ollama_models(base_url).await,
        ProviderKind::Openai => openai_models(base_url, api_key).await,
    }
}

/// Ping the provider — same call as models() but discards the body and
/// converts any non-Unreachable result into Ok(()).
pub async fn ping(
    kind: ProviderKind,
    base_url: &str,
    api_key: Option<&str>,
) -> Result<(), IntrospectError> {
    match models(kind, base_url, api_key).await {
        Ok(_) => Ok(()),
        Err(IntrospectError::HttpError { .. }) => Ok(()), // reachable but rejecting
        Err(IntrospectError::InvalidResponse(_)) => Ok(()), // reachable but weird
        Err(e) => Err(e),
    }
}

// --- Ollama (GET /api/tags) -------------------------------------------------

#[derive(Deserialize)]
struct OllamaTagsResponse {
    models: Vec<OllamaModelEntry>,
}

#[derive(Deserialize)]
struct OllamaModelEntry {
    name: String,
    #[serde(default)]
    size: Option<u64>,
}

async fn ollama_models(base_url: &str) -> Result<Vec<ModelDescriptor>, IntrospectError> {
    let url = format!("{}/api/tags", base_url.trim_end_matches('/'));
    let client = reqwest::Client::builder()
        .timeout(Duration::from_secs(3))
        .build()
        .map_err(|e| IntrospectError::Transport(e.to_string()))?;
    let resp = client
        .get(&url)
        .send()
        .await
        .map_err(|e| {
            if e.is_connect() || e.is_timeout() {
                IntrospectError::Unreachable(e.to_string())
            } else {
                IntrospectError::Transport(e.to_string())
            }
        })?;
    if !resp.status().is_success() {
        let status = resp.status().as_u16();
        let body = resp.text().await.unwrap_or_default();
        return Err(IntrospectError::HttpError { status, body });
    }
    let parsed: OllamaTagsResponse = resp
        .json()
        .await
        .map_err(|e| IntrospectError::InvalidResponse(e.to_string()))?;
    Ok(parsed
        .models
        .into_iter()
        .map(|m| ModelDescriptor {
            embedding_capable: is_embedding_model(&m.name),
            label: m.name.clone(),
            id: m.name,
            size_bytes: m.size,
        })
        .collect())
}

// --- OpenAI (GET /v1/models) ------------------------------------------------

#[derive(Deserialize)]
struct OpenAiModelsResponse {
    data: Vec<OpenAiModelEntry>,
}

#[derive(Deserialize)]
struct OpenAiModelEntry {
    id: String,
}

async fn openai_models(
    base_url: &str,
    api_key: Option<&str>,
) -> Result<Vec<ModelDescriptor>, IntrospectError> {
    let trimmed = base_url.trim_end_matches('/');
    let url = if trimmed.ends_with("/v1") {
        format!("{trimmed}/models")
    } else {
        format!("{trimmed}/v1/models")
    };
    let client = reqwest::Client::builder()
        .timeout(Duration::from_secs(5))
        .build()
        .map_err(|e| IntrospectError::Transport(e.to_string()))?;
    let mut req = client.get(&url);
    if let Some(key) = api_key {
        req = req.bearer_auth(key);
    }
    let resp = req
        .send()
        .await
        .map_err(|e| {
            if e.is_connect() || e.is_timeout() {
                IntrospectError::Unreachable(e.to_string())
            } else {
                IntrospectError::Transport(e.to_string())
            }
        })?;
    if !resp.status().is_success() {
        let status = resp.status().as_u16();
        let body = resp.text().await.unwrap_or_default();
        return Err(IntrospectError::HttpError { status, body });
    }
    let parsed: OpenAiModelsResponse = resp
        .json()
        .await
        .map_err(|e| IntrospectError::InvalidResponse(e.to_string()))?;
    Ok(parsed
        .data
        .into_iter()
        .map(|m| ModelDescriptor {
            embedding_capable: is_embedding_model(&m.id),
            label: m.id.clone(),
            id: m.id,
            size_bytes: None,
        })
        .collect())
}

// --- Heuristics -------------------------------------------------------------

/// Returns true if the model name looks like an embedding model.
/// Best-effort heuristic — Ollama doesn't expose capabilities in /api/tags
/// and OpenAI's /v1/models doesn't either. Used to gate the embed-model
/// dropdown so users can't pick `llama3.2:3b` as their embedder.
fn is_embedding_model(name: &str) -> bool {
    let n = name.to_ascii_lowercase();
    n.contains("embed")
        || n.contains("nomic")
        || n.contains("bge-")
        || n.contains("e5-")
        || n.contains("text-embedding-")
}
```

```typescript
import { invoke } from "@tauri-apps/api/core";
import type { CmdResult } from "$lib/types";

/** Provider variant — mirrors `ai::config::ProviderKind`. */
export type ProviderKind = "ollama" | "openai";

/** Voice config — copied from src/lib/voice.ts shapes to avoid a circular import. */
export interface VoiceConfig {
  engine?: string | null;
  voice?: string | null;
  rate_wpm?: number | null;
  auto_speak_replies?: boolean;
  stt_engine?: string | null;
  stt_model?: string | null;
  stt_trigger_word?: string | null;
  stt_send_on_trigger?: boolean;
}

/** Beacon config — mirrors `ai::config::BeaconConfig`. */
export interface BeaconConfig {
  provider: ProviderKind;
  chat_model?: string | null;
  embed_model?: string | null;
  base_url?: string | null;
  api_key_env?: string | null;
  voice: VoiceConfig;
}

/** Wrapper struct — mirrors `ai::config::SlabConfig` (partial). */
export interface SlabConfigBeacon {
  beacon: BeaconConfig;
  // Other top-level sections (ui, keymap) intentionally unmodeled —
  // settings panel touches `beacon` only and round-trips the rest
  // verbatim through the SlabConfig blob.
}

/** Mirrors `ai::introspect::ModelDescriptor`. */
export interface ModelDescriptor {
  id: string;
  label: string;
  size_bytes: number | null;
  embedding_capable: boolean;
}

/** List models the configured provider offers. */
export async function listModels(
  kind: ProviderKind,
  baseUrl: string,
  apiKeyEnv?: string | null,
): Promise<ModelDescriptor[]> {
  const res = await invoke<CmdResult<ModelDescriptor[]>>(
    "slab_beacon_list_models",
    {
      kind,
      baseUrl,
      apiKeyEnv: apiKeyEnv ?? null,
    },
  );
  if (res.kind === "ok") return res.value;
  throw new Error(res.message);
}

/** Ping the provider — used by the green-dot status indicator. */
export async function pingProvider(
  kind: ProviderKind,
  baseUrl: string,
  apiKeyEnv?: string | null,
): Promise<void> {
  const res = await invoke<CmdResult<null>>(
    "slab_beacon_provider_test",
    {
      kind,
      baseUrl,
      apiKeyEnv: apiKeyEnv ?? null,
    },
  );
  if (res.kind === "ok") return;
  throw new Error(res.message);
}

/** Default Beacon config (server-authoritative). */
export async function defaultBeaconConfig(): Promise<BeaconConfig> {
  const res = await invoke<CmdResult<BeaconConfig>>(
    "slab_beacon_default_config",
  );
  if (res.kind === "ok") return res.value;
  throw new Error(res.message);
}

/** Format a byte count as a short label ("3.0 GB" / "274 MB"). */
export function formatSize(bytes: number | null): string {
  if (bytes === null || bytes === undefined) return "";
  const GB = 1024 ** 3;
  const MB = 1024 ** 2;
  if (bytes >= GB) return `${(bytes / GB).toFixed(1)} GB`;
  if (bytes >= MB) return `${(bytes / MB).toFixed(0)} MB`;
  return `${bytes} B`;
}
```

```svelte
  // BeaconSettingsSection — v2.0.3 Slice 4.

  // The first user-facing surface for configuring Beacon (Slab's AI
  // layer). Lives inside SettingsPanel.svelte; could be hoisted to a
  // standalone route later.

  //   3. API key env name (only when provider=openai)
  //   4. Chat model dropdown (live-fetched from provider)
  //   5. Embed model dropdown (filtered to embedding-capable models)
  //   6. Status + Test button row
  //   7. Reset to defaults link

  // Live-fetch model lists run on every base-URL change (debounced
  // 300ms) and on every provider switch. Failures fall back to "Type
  // a model name manually" with the dropdown becoming a text input.

  import { invoke } from "@tauri-apps/api/core";
  import { onMount } from "svelte";
  import type { CmdResult } from "$lib/types";
  import { notify } from "$lib/notify";
  import { tStore, t } from "$lib/i18n";

    type ProviderKind,

    provider: "ollama",

  let status = $state<Status>("unchecked");
  let testing = $state(false);
  let debounceTimer: ReturnType<typeof setTimeout> | null = null;

  const chatModels = $derived(models.filter((m) => !m.embedding_capable));

      ? "ollama pull llama3.2:3b && ollama pull nomic-embed-text"
      : "(set OPENAI_API_KEY in your shell and try again)"
  );

  // --- Lifecycle -------------------------------------------------------
  onMount(async () => {
    await loadConfig();
    void refreshModels();
  });

  async function loadConfig() {
    try {
      const res = await invoke<CmdResult<{ beacon: BeaconConfig }>>(
        "slab_beacon_config_read",
      );
      if (res.kind !== "ok") return;
      fullConfig = res.value;
      beacon = {
        ...res.value.beacon,
        // Ensure non-null defaults so the form inputs are controlled.
        base_url: res.value.beacon.base_url ?? "http://localhost:11434",
        chat_model: res.value.beacon.chat_model ?? "llama3.2:3b",
        embed_model: res.value.beacon.embed_model ?? "nomic-embed-text",
      };
    } catch (e) {
      console.warn("BeaconSettings: failed to load config", e);
    }
  }

  async function saveConfig() {
    try {
      const merged = { ...(fullConfig as Record<string, unknown>), beacon };
      await invoke<CmdResult<null>>("slab_beacon_config_write", {
        config: merged,
      });
    } catch (e) {
      notify.error(`Failed to save: ${e}`);
    }
  }

  async function refreshModels() {
    modelsLoading = true;
    modelsError = null;
    try {
      const list = await listModels(
        beacon.provider,
        beacon.base_url ?? "",
        beacon.api_key_env ?? null,
      );
      models = list;
    } catch (e) {
      models = [];
      modelsError = `${e}`;
    } finally {
      modelsLoading = false;
    }
  }

  function scheduleRefresh() {
    if (debounceTimer) clearTimeout(debounceTimer);
    debounceTimer = setTimeout(() => void refreshModels(), 300);
  }

  async function testConnection() {
    testing = true;
    try {
      await pingProvider(
        beacon.provider,
        beacon.base_url ?? "",
        beacon.api_key_env ?? null,
      );
      status = "connected";
      // Also refresh models on a successful test.
      await refreshModels();
      notify.success(
        t("settings.beacon.test.success", { count: models.length }),
      );
    } catch (e) {
      const msg = `${e}`;
      if (msg.toLowerCase().includes("unreachable")) {
        status = "disconnected";
        notify.error(
          t("settings.beacon.test.unreachable", {
            baseUrl: beacon.base_url ?? "",
          }),
        );
      } else {
        status = "error";
        notify.error(
          t("settings.beacon.test.error", { detail: msg }),
        );
      }
    } finally {
      testing = false;
    }
  }

  async function resetToDefaults() {
    try {
      const defaults = await defaultBeaconConfig();
      beacon = { ...defaults, voice: beacon.voice };
      await saveConfig();
      await refreshModels();
      notify.success(t("toast.resetToDefaults") ?? "Reset to defaults");
    } catch (e) {
      notify.error(`Reset failed: ${e}`);
    }
  }

  function copyPullCommand() {
    navigator.clipboard.writeText(pullCommand);
    notify.success(t("toast.copied") ?? "Copied to clipboard");
  }

  // --- Effects ---------------------------------------------------------
  // Auto-save 500ms after any change.
  let saveTimer: ReturnType<typeof setTimeout> | null = null;
  $effect(() => {
    // Touch every persisted field so the effect runs on any change.
    const _ = JSON.stringify(beacon);
    if (saveTimer) clearTimeout(saveTimer);
    saveTimer = setTimeout(() => void saveConfig(), 500);
  });
</script>
```

## Risks + mitigations

1. **Ollama API surface shifts.** Tests use mockito with the v0.1.x
   shape. If Ollama bumps to /api/v2/tags, the live dropdown breaks.
   *Mitigation:* `InvalidResponse` variant exists; UI falls back to a
   text input so users aren't blocked.
2. **OpenAI base URLs vary wildly.** Some have `/v1`, some don't.
   *Mitigation:* The plan canonicalizes to "always has `/v1` before
   `/models`". Slice 1 tests both shapes.
3. **Settings panel layout conflicts.** Inserting between Language
   and Theme is the cleanest spot, but if another feature lands a new
   section there first, the subagent should pick the nearest stable
   surrounding line. The plan does not depend on absolute line
   numbers.
4. **`fullConfig` round-tripping.** The component reads the *whole*
   SlabConfig blob, modifies only `.beacon`, and writes the blob
   back. This is correct only if `slab_beacon_config_write` accepts a
   `SlabConfig` (not just a `BeaconConfig`). Verify by reading lib.rs
   line 521 before writing Slice 4.
