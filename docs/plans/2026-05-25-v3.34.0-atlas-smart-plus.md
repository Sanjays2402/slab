# v3.34.0 "Atlas Smart+" Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task. CI is currently billing-blocked, so this branch may accumulate multiple ticks before the eventual merge + tagged release.

**Goal:** Extend the Smart Collection filter language with NOT and OR semantics and a nested group builder, so users can express rules like *"(tag:tax 2026 OR tag:tax 2025) AND NOT tag:archived"* — the table-stakes feature that Smart Mailboxes / Smart Folders have shipped for a decade and that Adobe / PDF Expert still don't.

**Architecture:**
- Extend `LibraryFilter` with an optional `clauses: Option<FilterGroup>` field. When present, it overrides the legacy flat `tag_ids`/`folder_id`/`title_substring` fields. When absent, current behavior is preserved exactly — old persisted `query_json` payloads keep working unchanged (backward compat is non-negotiable, users have v3.32+ smart collections in production).
- A `FilterGroup` is `{ combinator: And|Or, clauses: Vec<FilterClause> }` where `FilterClause` is the sum of `Tag(i64)`, `NotTag(i64)`, `Folder(i64)`, `NotFolder(i64)`, `TitleContains(String)`, `TitleNotContains(String)`, `Group(FilterGroup)`. Recursive — supports arbitrary nesting.
- SQL is generated by a single recursive `build_clause_sql` function returning `(sql_fragment, params_to_push)`. Tag NOT semantics use `NOT IN (SELECT doc_id FROM library_doc_tags WHERE tag_id = ?)`. AND/OR joins with the matching keyword.
- Frontend: extend `SmartCollectionBuilder.svelte` with a recursive `<ClauseGroup>` component that renders nested groups, with "+ Add rule" / "+ Add group" / "Switch to OR" / "Negate" affordances. Live preview pane (already in place) re-runs against the new clause tree.

**Tech Stack:** Rust + rusqlite (backend), Svelte 5 + TypeScript (frontend), Tauri commands (IPC). No new dependencies.

fn nested_or_and_not_query() {
    let db = seed();
    let tags = db.list_tags().unwrap();
    let research = tags.iter().find(|t| t.name == "research").unwrap().id;

            combinator: FilterCombinator::Or,
            clauses: vec![

                FilterClause::Tag { id: done },

    };
    let rows = query_documents(&db, &f).unwrap();
    assert_eq!(rows.len(), 2);

**Step 2:** `cargo test … nested_or_and_not_query` → FAIL.

**Step 3: Implement `build_group_sql`**

Recursive function that returns `(String, Vec<Box<dyn ToSql>>)`. For each clause type:
- `Tag { id }` → `id IN (SELECT doc_id FROM library_doc_tags WHERE tag_id = ?)`
- `NotTag { id }` → `id NOT IN (SELECT doc_id FROM library_doc_tags WHERE tag_id = ?)`
- `Folder { id }` → `folder_id = ?`
- `NotFolder { id }` → `(folder_id IS NULL OR folder_id <> ?)`
- `TitleContains { value }` → `(LOWER(COALESCE(title, '')) LIKE LOWER(?) OR LOWER(path) LIKE LOWER(?))` with `%v%`
- `TitleNotContains { value }` → wrap above with `NOT (...)`
- `Group(g)` → recurse, wrap result in parens
- Empty group → `1=1` (and-identity) or `0=1` (or-identity), depending on combinator
- Join fragments with ` AND ` or ` OR ` based on `combinator`

In `query_documents`, when `filter.clauses` is `Some`, use ONLY the recursive builder (legacy fields ignored). When `None`, current behavior.

```typescript
function migrateFlatFilter(f: LibraryFilter): FilterGroup {
  if (f.clauses) return f.clauses;
  const clauses: FilterClause[] = [];
  if (f.folder_id != null) clauses.push({ type: "folder", id: f.folder_id });
  for (const id of f.tag_ids ?? []) clauses.push({ type: "tag", id });
  if (f.title_substring) clauses.push({ type: "title_contains", value: f.title_substring });
  return { combinator: "and", clauses };
}
```
