# v0.12.0 "Atlas" — Slice 3 Implementation Plan (LibraryPanel UI + Wire-up)

> **For Hermes:** This slice makes the Atlas library backend user-visible.
> Slice 1 already shipped the registry + scanner + query + 8 IPC commands
> but a user opening Slab today cannot see any of it. This tick fixes that.

**Goal:** Ship a Linear-quality `LibraryPanel.svelte` that lets a user add
folders, browse indexed docs in a grid with folder + tag filters, manage
tags, and open any doc into a Reader tab — then merge the entire v0.12.0
work-in-progress to `main` so users have a Library button.

**Architecture:**

- **Backend additions** (3 new Tauri commands, ~50 LOC): `slab_library_remove_document`, `slab_library_remove_tag`, `slab_library_rescan_all`. Required by the UI's right-click context menu and the "Rescan all" toolbar button. Each thin-wraps existing registry/scanner methods.
- **Frontend** (`src/lib/panels/LibraryPanel.svelte`): two-pane layout — left rail with **Folders** section + **Tags** section + counts, main pane with toolbar (Add Folder, Rescan All, search box, sort dropdown) above a responsive cards grid. Each card shows title + relative folder path + page count + tag chips + relative last-seen time. Click opens in new Reader tab via existing `slab:open-recent` event. Right-click context menu offers Open, Add Tag, Remove from Library. Empty state CTA: "Add a folder to start indexing." Loading state, error toast.
- **Sidebar wire-up** in `src/routes/+page.svelte`: nav entry `Library` with icon `❐` slotted under Reader/Beacon, opens the panel. Library cards delegate to a `openInNewTab(path)` helper exposed on the page (reusing the existing tab machinery).
- **No new TS deps. No new Rust deps.** All UI uses the existing `@tauri-apps/plugin-dialog` (already imported by every other panel) and the typed `src/lib/library.ts` IPC client shipped in Slice 1.

**Tech Stack:** Svelte 5 (`$state`, `$derived`, `$effect`), Tauri 2 plugin-dialog for the folder picker, the existing `slab:open-recent` window-event seam ReaderPanel already listens for, CSS grid for the card layout.

**Why merge to main this tick?** Backend was invisible. After Slice 3 the user can add folders, see their library, tag and filter, and open into Reader tabs. That's a shippable user-facing feature. Slice 2 (watch daemon), Slice 4 (cross-doc Beacon), and Slice 5+ (saved searches, smart bookmarks) layer on top in subsequent ticks.

```rust
// registry.rs additions
pub fn remove_document(&mut self, doc_id: i64) -> Result<(), LibraryError> {
    self.conn.execute("DELETE FROM library_documents WHERE id = ?1", params![doc_id])?;
    Ok(())
}

pub fn remove_tag(&mut self, tag_id: i64) -> Result<(), LibraryError> {
    self.conn.execute("DELETE FROM library_tags WHERE id = ?1", params![tag_id])?;
    Ok(())
}
```

## Task 3: `LibraryPanel.svelte`

**Objective:** The user-facing Library experience. Linear-quality, two-pane, dark, calm.

**Files:**
- Create: `src/lib/panels/LibraryPanel.svelte` (~600 LOC including scoped styles)

**Layout:**

```
┌─────────────────────────────────────────────────────────────────┐
│ Library                                                          │
│ Index folders of PDFs. Click any doc to open it in a Reader tab.│
├─────────────────────────────────────────────────────────────────┤
│ [+ Add Folder]  [↻ Rescan All]   ⌕ Search…    Sort: Added ▼     │
├────────────┬────────────────────────────────────────────────────┤
│ Folders 3  │   ┌─────────┐ ┌─────────┐ ┌─────────┐              │
│  All  42   │   │  card   │ │  card   │ │  card   │              │
│  ~/Papers  │   │         │ │         │ │         │              │
│  ~/Reading │   └─────────┘ └─────────┘ └─────────┘              │
│  ~/Books   │   ┌─────────┐ ┌─────────┐ …                        │
│            │                                                     │
│ Tags  5    │                                                     │
│  paper     │                                                     │
│  read      │                                                     │
│  + Add tag │                                                     │
└────────────┴────────────────────────────────────────────────────┘
```

**State (Svelte 5 runes):**

```typescript
let folders = $state<FolderRecord[]>([]);
let tags = $state<TagRecord[]>([]);
let docs = $state<DocumentRecord[]>([]);
let activeFolder = $state<number | "all">("all");
let activeTagIds = $state<Set<number>>(new Set());
let query = $state("");
let sort = $state<LibrarySortBy>("added_desc");
let loading = $state(false);
let scanning = $state(false);
let error = $state<string | null>(null);
let menuFor = $state<number | null>(null);  // doc id of open context menu
```

**Derived filter:** rebuilds when activeFolder / activeTagIds / query / sort change → calls `listDocuments(filter)` (debounced 150ms on query).

**Cards:** `title || basename(path)`, folder relpath, page count, tag chips (max 3 visible + "+N more"), `formatRelTime(last_seen_at * 1000)`. Hover → "Open" + "⋯" buttons.

**Context menu (right-click or "⋯"):**
- Open in Reader tab
- Add Tag → submenu with existing tags + "New tag"
- Remove from Library

**Add Folder:** plugin-dialog `open({ directory: true })` → `addFolder(path)` → automatically kick off `scanFolder(folder.id)` → refresh.

**Empty state:** centered dropzone-style card with `+` icon, headline "Build your library", subtitle "Add a folder of PDFs to index. Slab will track them, tag them, and let you search across the whole collection.", primary button "+ Add Folder".

**Tabid handoff:** card click dispatches a `CustomEvent("slab:open-library-doc", { detail: { path } })` on `window`. The page-level handler in `+page.svelte` listens, calls `openNewTab(path)` and flips `active = "reader"`. (Re-use of the existing tab machinery; no per-card hard-coding of openNewTab.)

**Styling:** dark palette using existing `--bg`, `--bg-2`, `--bg-3`, `--border`, `--text`, `--text-2`, `--text-3`, `--accent` CSS vars. Cards are flat with 1px border + subtle hover state lifting the border + bg-3. Tag chips are pill-shaped with the tag color (if set) as a 2px left border.

## Risks / Open questions

1. **Folder picker UX on Windows/Linux** — plugin-dialog's `open({directory: true})` returns absolute paths everywhere we support, no special-casing needed.
2. **Context menu z-index** — make sure it sits above tag chips. Use `position: fixed` with computed coords from the right-click event, not absolute under the card.
3. **Tag color palette** — Slice 1 backend already supports `color TEXT`. UI in this slice exposes a tiny preset palette (8 colors) on "New tag" rather than a full color picker.
4. **Document count overflow** — if a user adds a 5000-doc folder, the grid will render 5000 cards. For Slice 3 we accept this; virtualization is a Slice 7 concern when we know the real use pattern.
