# v3.1.0 Loom — Slice 4: Beacon-generated alt-text

> **For Hermes:** Self-executed by Cake (cron) on 2026-05-23. This document
> records the plan; the code lands in the same tick.

**Goal:** For every `Figure` node in the `StructTree`, generate a one-sentence
screen-reader alt-text using the local Beacon vision model (llava via Ollama),
cached on disk so re-runs are instant.

**Architecture:** Pure rasterize-then-ask. We don't crack PDF XObject byte
streams (fragile across filters: DCT/Flate/JPX/JBIG2/CCITTFax). Instead, for
each Figure, we rasterize the page at 150 DPI, crop to the figure bbox, hash
the cropped PNG with SHA-256, look it up in
`~/Library/Application Support/Slab/cache/alt-text/<sha>.txt` — on miss, we
ask Beacon and persist. Result: deterministic cache key tied to the rendered
pixels, identical across reruns of the same PDF.

**Tech stack:** `image` (already wired), `sha2` (already wired), `dirs`
(already wired), existing `ai::vision::render_page_image`, existing
`AiProvider::chat_with_images`.

**Privacy wedge:** Adobe Acrobat Pro generates alt-text by shipping the image
to Adobe's servers (Adobe Sensei). Slab does it 100% offline via Ollama. Same
feature, none of the data exposure. Direct buyer-magnet for legal / healthcare
/ government compliance buyers.

## Task 1: `pdf::loom::alt_text` module + cache + provider call

**Objective:** Build the alt-text generator as a pure(-ish) module taking a
PDF path, a `&mut StructTree`, an `Arc<dyn AiProvider>`, and a cache dir;
mutate every Figure node in place with `alt_text = Some(...)`.

**Files:**
- Create: `src-tauri/src/pdf/loom/alt_text.rs` (~280 lines incl. tests)
- Modify: `src-tauri/src/pdf/loom/mod.rs` — add `pub mod alt_text;` + re-export

**Public surface:**

```rust
pub struct AltTextOptions {
    pub dpi: u32,         // default 150
    pub max_edge_px: u32, // default 1568
    pub prompt: String,   // default screen-reader prompt
    pub min_area_pt: f32, // skip tiny figures (default 200 pt²)
}

pub struct AltTextStats {
    pub figures_total: usize,
    pub generated: usize,
    pub cache_hits: usize,
    pub skipped_tiny: usize,
    pub errors: usize,
}

pub async fn enrich_with_alt_text(
    pdf_path: &Path,
    tree: &mut StructTree,
    provider: Arc<dyn AiProvider>,
    opts: &AltTextOptions,
    cache_dir: &Path,
) -> Result<AltTextStats, AiError>
```

**Key invariants:**
- Pure cache miss vs hit determined by SHA-256 of the rendered PNG bytes — same
  Figure on the same PDF always lands on the same cache entry across reboots.
- Cache file format: plain UTF-8 text, one line. We never want JSON ceremony
  for a single string.
- Errors per-figure are swallowed into `stats.errors` — a failed llava call
  must NOT abort enrichment of the remaining 200 figures.
- `min_area_pt` skips logos / bullets / 8×8 icons that aren't worth a vision
  round-trip.

**Tests (all `#[tokio::test]`):**
1. `cache_hit_skips_provider_call` — MockProvider that panics if called twice,
   run enrich_with_alt_text twice on same tree.
2. `cache_miss_writes_file_and_returns_alt_text` — temp cache dir, MockProvider
   that returns "A red square.", verify file exists and tree updated.
3. `errors_isolated_per_figure` — MockProvider that fails on figure 2 of 3,
   verify figures 1 & 3 still got alt-text and stats.errors == 1.
4. `tiny_figures_skipped` — Figure with 50×50pt bbox, verify
   `stats.skipped_tiny == 1` and provider never called.
5. `existing_alt_text_preserved` — Figure already has `alt_text = Some(...)`,
   verify provider not called and existing text untouched.
