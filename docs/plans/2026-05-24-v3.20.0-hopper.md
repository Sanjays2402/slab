## Goal

One sentence: **Drop a PDF into a folder; Slab auto-runs your Atelier
recipe on it, AI-renames it, files it, and notifies you — without you
opening the app.**

This is the "Hazel for PDFs" feature. Hazel + Adobe AutoAction + an AI
paralegal in one box. Adobe charges enterprise licensing for AutoActions.
PDF Expert doesn't have folder automation at all. Hazel ($42 one-time)
has no PDF-aware steps. **Slab v3.20.0 will be the only consumer product
that ships drop-folder PDF automation with local AI rename.**

## Buy-Button test — passes all four

1. **Pay-for-it**: A paralegal saves 30 min/day if every scanned contract
   auto-OCRs, auto-flattens, auto-renames `2026-05-24_NDA_Acme.pdf` the
   moment it lands in `~/Inbox/`. Worth $49.
2. **Notice-it**: New "Hopper" sidebar entry with a big "Add watch" CTA
   and a live tail of "Last 10 automations." Returning users see it
   immediately.
3. **Pick-us**: Adobe ships file-based AutoActions only in Acrobat Pro
   enterprise editions. Hazel has no PDF-native steps. **Nobody else
   does this locally + free.**
4. **Tell-a-friend**: Demo video = drag PDF into Inbox → 3 seconds
   later it's in `~/Cases/Acme/` named `2026-05-24_NDA_Acme.pdf`.
   That's the screenshot.

## Architecture

```
                   ┌─────────────────────────────────────┐
                   │  HopperPanel.svelte  (sidebar)      │
                   │  ┌─Watches─┐  ┌─Live log────────┐   │
                   │  │ Inbox → │  │ ✓ NDA_Acme.pdf  │   │
                   │  │ recipe  │  │ ✓ Lease_2026..  │   │
                   │  └─────────┘  └─────────────────┘   │
                   └────────────┬────────────────────────┘
                                │ Tauri events
                                ▼
   ┌─────────────────────────────────────────────────────┐
   │ src-tauri/src/pdf/hopper/                           │
   │   registry.rs   — sqlite store of Watch configs     │
   │   watcher.rs    — notify::RecommendedWatcher        │
   │   pipeline.rs   — Atelier::run + Beacon rename     │
   │   rename.rs     — slab_beacon_rename_suggest       │
   │   log.rs        — append-only history table        │
   │   cmds.rs       — Tauri command surface             │
   └──────────────────┬──────────────────────────────────┘
                      │ reuses
                      ▼
   pdf::atelier::run::run_recipe()    ai::ollama::chat()
```

**Data model (sqlite at `~/.slab/hopper.db`):**

```sql
CREATE TABLE watches (
  id INTEGER PRIMARY KEY,
  source_dir TEXT NOT NULL,
  recipe_id TEXT,                    -- references atelier recipe
  output_dir TEXT NOT NULL,
  rename_pattern TEXT,               -- e.g. "{date}_{ai_title}.pdf" or NULL
  ai_rename BOOLEAN NOT NULL,        -- whether to call Beacon
  enabled BOOLEAN NOT NULL,
  created_at TEXT NOT NULL
);

CREATE TABLE runs (
  id INTEGER PRIMARY KEY,
  watch_id INTEGER NOT NULL,
  input_path TEXT NOT NULL,
  output_path TEXT,
  status TEXT NOT NULL,              -- 'success' | 'failed' | 'skipped'
  error TEXT,
  duration_ms INTEGER NOT NULL,
  ai_title TEXT,
  started_at TEXT NOT NULL,
  FOREIGN KEY (watch_id) REFERENCES watches(id)
);
```

```rust
fn pattern_substitution() {
    let out = apply_pattern(
```

### Task 4: Watcher (fs events → debounced queue)

**Objective:** `notify::RecommendedWatcher` watches each enabled
`source_dir`; coalesces rapid-fire events (file still being written);
fires `pipeline::process_one` on each settled PDF.

**Files:**
- Edit: `src-tauri/src/pdf/hopper/watcher.rs`

**Step 1:** Design: spawn one `tokio::task` per enabled watch.
Each task owns a `notify::RecommendedWatcher` + a `HashMap<PathBuf,
Instant>` debounce table (700ms quiet period).

**Step 2:** Implement `HopperService::start(registry, provider, log)`
returning a handle that owns the join-set of watcher tasks. On
`registry.list()` change, restart the relevant tasks.

**Step 3:** Skip non-PDFs (`.pdf` extension match, case-insensitive).
Skip hidden / `.tmp` files.

**Step 4:** On every settled PDF event: spawn `tokio::spawn(
pipeline::process_one(...))` so multiple files process in parallel.

**Step 5:** Emit a `tauri::Event` named `hopper://run-completed`
with the `RunRecord` JSON so the frontend live log updates.

**Step 6:** Inline integration test: create tempdir, copy a tiny PDF
in, assert run-record appears within 3 seconds.

~250 LOC.

**Step 7:** Commit:
```bash
git commit -am "feat(hopper): notify watcher + debounce + parallel pipeline"
```
