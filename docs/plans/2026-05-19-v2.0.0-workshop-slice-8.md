# v2.0.0 "Workshop" — Slice 8 Implementation Plan: `slab.storage.*`

> **For Hermes:** Use subagent-driven-development skill to implement this plan
> task-by-task. Each task is independently runnable and ships behind its own
> commit. Slices 8.1–8.5 are backend infrastructure; 8.6–8.7 are the JS
> binding + E2E; 8.8 is final gates + push.

**Goal:** Ship `slab.storage.{get, set, remove, list, clear}` — a per-plugin,
sqlite-backed key/value store. Plugin authors can persist cache, preferences,
or any small JSON-shaped state across sessions without rolling their own
SQLite or fighting localStorage (which doesn't exist in the rquickjs sandbox).

**Architecture (one paragraph):** One process-wide `~/.slab/plugin-storage.sqlite`
opened lazily via `OnceLock<Arc<Mutex<PluginStorage>>>`, schema
`kv(plugin_id, key, value, value_size, updated_at)` with `PRIMARY KEY (plugin_id, key)`.
Per-plugin operations are *synchronous* and run inside `Mutex::lock()` —
microsecond-scale, no actor round-trip needed (sqlite handles its own
serialisation). The JS binding wraps each call in `Promise.resolve(...)` /
`Promise.reject(...)` so the API matches `slab.fetch` shape ("everything
async") and gives us forward-compat headroom if we later route through the
actor for streaming reads. **No manifest capability gate** — per-plugin
scoping IS the security boundary. Quotas (8 MiB total per plugin / 1 MiB
per value / 64 KiB per key) enforced in `kv_set` to bound disk usage.

**Tech Stack:** Rust `rusqlite` (already a dep, `bundled` feature on),
`rquickjs::Promise` for the JS API surface, no new deps required.

---

## Why no manifest capability?

Slices 1–7 gate every `slab.*` surface against a manifest capability. Storage
breaks that pattern intentionally:

1. **Scoping is the only realistic threat model.** A plugin can read/write
   exclusively under its own `plugin_id` rowspace. There's nothing the
   capability gate would *prevent* that scoping doesn't already prevent —
   plugin A literally cannot see plugin B's keys, gate or no gate.
2. **UX cost.** Adding a `storage: "allow"` consent prompt for every
   plugin that wants to cache one number forever is friction theatre.
   Users would rubber-stamp it 100% of the time → the prompt is noise.
3. **Quotas are the actual concern.** A buggy plugin filling the disk
   matters more than a "denied" plugin author working around the gate
   with a remote KV store. We enforce hard caps (see Slice 8.2).

If a future Forge slice needs auditable storage ("which plugins used local
storage in the last 30 days?"), we add a *read-only* `slab.storage.usage()`
metric — not a gate.

```rust
//! Workshop (v2.0.0 Slice 8) — per-plugin key/value storage.
//!
//! Single process-wide sqlite database at `~/.slab/plugin-storage.sqlite`
//! with a flat `kv` table keyed by `(plugin_id, key)`. Per-plugin
//! scoping is enforced in code: every public method takes a
//! `plugin_id: &str` and filters all WHERE clauses against it, so
//! plugin A can never observe plugin B's keys even via crafted SQL.
//!
//! ## Why no per-plugin database file?
//!
//! - One open `Connection` per process is simpler than maintaining a
//!   pool keyed by plugin_id.
//! - Sqlite's row-level locking is plenty for the read-mostly access
//!   pattern plugins exhibit.
//! - Backup / inspection is easier ("one file under ~/.slab/").
//!
//! ## Why no manifest capability gate?
//!
//! See plan doc `docs/plans/2026-05-19-v2.0.0-workshop-slice-8.md`
//! § "Why no manifest capability?" — scoping is the security boundary,
//! quotas are the real concern.

use std::path::{Path, PathBuf};

use rusqlite::{params, Connection, OptionalExtension};

/// Schema version stamped into `PRAGMA user_version`. Bump + add a
/// migration arm in `init_schema` when changing the table shape.
const SCHEMA_VERSION: u32 = 1;

/// Storage-layer error type. Wraps `rusqlite::Error` for the common
/// case and carries explicit variants for quota / validation failures
/// the JS binding needs to differentiate when building the rejected
/// Promise message.
#[derive(Debug, thiserror::Error)]
pub enum StorageError {
    #[error("sqlite: {0}")]
    Db(#[from] rusqlite::Error),

    #[error("io: {0}")]
    Io(#[from] std::io::Error),

    #[error("key too long ({0} bytes, max {1})")]
    KeyTooLong(usize, usize),

    #[error("value too large ({0} bytes, max {1})")]
    ValueTooLarge(usize, usize),

    #[error("plugin storage quota exceeded ({current} bytes + {incoming} > {limit})")]
    QuotaExceeded {
        current: u64,
        incoming: u64,
        limit: u64,
    },
}

/// Default DB path: `~/.slab/plugin-storage.sqlite`. Mirrors the
/// pattern used by `study_store.rs` for consistency.
pub fn default_db_path() -> PathBuf {
    let home = std::env::var_os("HOME")
        .map(PathBuf::from)
        .unwrap_or_else(|| PathBuf::from("."));
    home.join(".slab").join("plugin-storage.sqlite")
}

/// Owning handle around the per-process sqlite connection.
pub struct PluginStorage {
    pub(crate) conn: Connection,
}

impl PluginStorage {
    /// Open (or create) the DB at `path`, ensuring `parent` exists and
    /// schema is initialised.
    pub fn open(path: &Path) -> Result<Self, StorageError> {
        if let Some(parent) = path.parent() {
            std::fs::create_dir_all(parent)?;
        }
        let conn = Connection::open(path)?;
        Self::init_schema(&conn)?;
        Ok(Self { conn })
    }

    /// Open an in-memory database. Used exclusively in tests.
    pub fn open_in_memory() -> Result<Self, StorageError> {
        let conn = Connection::open_in_memory()?;
        Self::init_schema(&conn)?;
        Ok(Self { conn })
    }

    fn init_schema(conn: &Connection) -> Result<(), StorageError> {
        conn.execute_batch(
            r#"
            CREATE TABLE IF NOT EXISTS kv (
              plugin_id   TEXT NOT NULL,
              key         TEXT NOT NULL,
              value       BLOB NOT NULL,
              value_size  INTEGER NOT NULL,
              updated_at  INTEGER NOT NULL,
              PRIMARY KEY (plugin_id, key)
            );
            CREATE INDEX IF NOT EXISTS idx_kv_plugin ON kv(plugin_id);
            "#,
        )?;
        conn.pragma_update(None, "user_version", SCHEMA_VERSION)?;
        Ok(())
    }
}

#[cfg(test)]

    #[test]
    fn open_in_memory_initialises_schema() { /* … */ }

    #[test]
    fn user_version_pragma_set_to_schema_version() { /* … */ }
}
```

**Objective:** Land `get` / `set` / `remove` / `list` / `clear` and the

**Files:** `src-tauri/src/plugins/storage.rs` (extend).

**Step 1: Add quota constants below `SCHEMA_VERSION`:**

```rust
/// Per-plugin storage cap. 8 MiB is generous for cache/preferences;
/// plugins needing more should ship their own host process.
pub const MAX_PLUGIN_BYTES: u64 = 8 * 1024 * 1024;

/// Per-value cap. Larger than this almost always means the plugin is
/// using storage as a blob store, which we don't support.
pub const MAX_VALUE_BYTES: usize = 1024 * 1024;

/// Key length cap. Sqlite has no inherent limit, but bounding it
/// here means index lookups stay fast and pathological keys can't
/// blow the indexed prefix.
pub const MAX_KEY_BYTES: usize = 64 * 1024;
```

**Step 2: Implement CRUD on `impl PluginStorage`:**

```rust
/// Lookup. Returns `None` when the key isn't set for this plugin.
pub fn kv_get(&self, plugin_id: &str, key: &str) -> Result<Option<String>, StorageError> {
    let row: Option<Vec<u8>> = self
        .conn
        .query_row(
            "SELECT value FROM kv WHERE plugin_id = ?1 AND key = ?2",
            params![plugin_id, key],
            |r| r.get(0),
        )
        .optional()?;
    Ok(row.map(|b| String::from_utf8_lossy(&b).into_owned()))
}

/// Insert or replace. Enforces all three quotas before writing.
pub fn kv_set(
    &self,
    plugin_id: &str,
    key: &str,
    value: &str,
) -> Result<(), StorageError> {
    if key.len() > MAX_KEY_BYTES {
        return Err(StorageError::KeyTooLong(key.len(), MAX_KEY_BYTES));
    }
    let value_bytes = value.as_bytes();
    if value_bytes.len() > MAX_VALUE_BYTES {
        return Err(StorageError::ValueTooLarge(value_bytes.len(), MAX_VALUE_BYTES));
    }

    // Total-quota check. We subtract the old value's size (if any)
    // so an update doesn't double-count.
    let current_total: i64 = self.conn.query_row(
        "SELECT COALESCE(SUM(value_size), 0) FROM kv WHERE plugin_id = ?1",
        params![plugin_id],
        |r| r.get(0),
    )?;
    let prev_size: i64 = self
        .conn
        .query_row(
            "SELECT value_size FROM kv WHERE plugin_id = ?1 AND key = ?2",
            params![plugin_id, key],
            |r| r.get(0),
        )
        .optional()?
        .unwrap_or(0);
    let projected = current_total as u64 - prev_size as u64 + value_bytes.len() as u64;
    if projected > MAX_PLUGIN_BYTES {
        return Err(StorageError::QuotaExceeded {
            current: (current_total - prev_size) as u64,
            incoming: value_bytes.len() as u64,
            limit: MAX_PLUGIN_BYTES,
        });
    }

    let now = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)
        .map(|d| d.as_secs() as i64)
        .unwrap_or(0);
    self.conn.execute(
        "INSERT INTO kv(plugin_id, key, value, value_size, updated_at) \
         VALUES (?1, ?2, ?3, ?4, ?5) \
         ON CONFLICT(plugin_id, key) DO UPDATE SET \
           value = excluded.value, value_size = excluded.value_size, updated_at = excluded.updated_at",
        params![plugin_id, key, value_bytes, value_bytes.len() as i64, now],
    )?;
    Ok(())
}

/// Delete. Returns true iff a row was actually removed.
pub fn kv_remove(&self, plugin_id: &str, key: &str) -> Result<bool, StorageError> {
    let n = self.conn.execute(
        "DELETE FROM kv WHERE plugin_id = ?1 AND key = ?2",
        params![plugin_id, key],
    )?;
    Ok(n > 0)
}

/// All keys for this plugin, lexicographic order. Caller turns this
/// into a JS string[].
pub fn kv_list(&self, plugin_id: &str) -> Result<Vec<String>, StorageError> {
    let mut stmt = self
        .conn
        .prepare("SELECT key FROM kv WHERE plugin_id = ?1 ORDER BY key")?;
    let rows = stmt.query_map(params![plugin_id], |r| r.get::<_, String>(0))?;
    let mut out = Vec::new();
    for r in rows {
        out.push(r?);
    }
    Ok(out)
}

/// Drop every key for this plugin. Used by "Reset permissions" /
/// "Uninstall" flows in later slices.
pub fn kv_clear(&self, plugin_id: &str) -> Result<usize, StorageError> {
    let n = self
        .conn
        .execute("DELETE FROM kv WHERE plugin_id = ?1", params![plugin_id])?;
    Ok(n)
}

/// Total bytes stored for `plugin_id`. Public for `slab.storage.usage()`
/// in a future slice; tests use it to assert quota arithmetic.
pub fn kv_usage_bytes(&self, plugin_id: &str) -> Result<u64, StorageError> {
    let total: i64 = self.conn.query_row(
        "SELECT COALESCE(SUM(value_size), 0) FROM kv WHERE plugin_id = ?1",
        params![plugin_id],
        |r| r.get(0),
    )?;
    Ok(total.max(0) as u64)
}
```

**Step 1: Add singleton helper.**

```rust
use std::sync::{Arc, Mutex, OnceLock};

pub type SharedPluginStorage = Arc<Mutex<PluginStorage>>;

static STORAGE: OnceLock<SharedPluginStorage> = OnceLock::new();

/// Process-wide shared store. First call opens the on-disk DB
/// (creating the parent dir if missing). Subsequent calls return
/// the same `Arc` clone.
pub fn shared_storage() -> Result<SharedPluginStorage, StorageError> {
    if let Some(s) = STORAGE.get() {
        return Ok(Arc::clone(s));
    }
    let store = PluginStorage::open(&default_db_path())?;
    let arc = Arc::new(Mutex::new(store));
    let _ = STORAGE.set(Arc::clone(&arc));
    // Race: if another thread won, return THEIRS so we don't end up
    // with two competing DB handles.
    Ok(Arc::clone(STORAGE.get().unwrap_or(&arc)))
}

/// Build a test-local shared handle over an in-memory DB. Skips the
/// global singleton so each test gets isolation.
#[cfg(test)]
pub fn shared_in_memory() -> Result<SharedPluginStorage, StorageError> {
    Ok(Arc::new(Mutex::new(PluginStorage::open_in_memory()?)))
}
```

```rust
fn make_storage_get<'js>(ctx: &Ctx<'js>, b: HostBindings) -> Result<Function<'js>> {
    Function::new(ctx.clone(), move |ctx: Ctx<'js>, key: String| -> Result<Value<'js>> {
        let Some(store) = b.storage.as_ref() else {
            return reject_now(
                &ctx,
                "slab.storage unavailable outside the per-plugin runtime (enable the plugin first)",
            );
        };
        let result = match store.lock() {
            Ok(g) => g.kv_get(&b.plugin_id, &key),
            Err(_) => return reject_now(&ctx, "slab.storage: backing store mutex poisoned"),
        };
        match result {
            Ok(Some(v)) => resolve_now(&ctx, &v),  // resolves a JS Promise with the value
            Ok(None) => resolve_null(&ctx),         // resolves with null
            Err(e) => reject_now(&ctx, &format!("slab.storage.get: {e}")),
        }
    })
}
```

Where the new helpers (drop next to `reject_now`):

```rust
fn resolve_now<'js>(ctx: &Ctx<'js>, value: &str) -> Result<Value<'js>> {
    let escaped = serde_json::to_string(value).unwrap_or_else(|_| "\"\"".to_string());
    ctx.eval::<Value<'js>, _>(format!("Promise.resolve({escaped})").as_bytes())
}

fn resolve_null<'js>(ctx: &Ctx<'js>) -> Result<Value<'js>> {
    ctx.eval::<Value<'js>, _>(b"Promise.resolve(null)")
}

fn resolve_bool<'js>(ctx: &Ctx<'js>, b: bool) -> Result<Value<'js>> {
    ctx.eval::<Value<'js>, _>(if b { b"Promise.resolve(true)" } else { b"Promise.resolve(false)" })
}

fn resolve_strings<'js>(ctx: &Ctx<'js>, items: &[String]) -> Result<Value<'js>> {
    let arr = serde_json::to_string(items).unwrap_or_else(|_| "[]".to_string());
    ctx.eval::<Value<'js>, _>(format!("Promise.resolve({arr})").as_bytes())
}

fn resolve_number<'js>(ctx: &Ctx<'js>, n: usize) -> Result<Value<'js>> {
    ctx.eval::<Value<'js>, _>(format!("Promise.resolve({n})").as_bytes())
}
```

**Important — value escaping.** `serde_json::to_string` on a `String`
produces a JSON-escaped, double-quoted string literal that's safe to
embed inside `Promise.resolve(…)`. No further escaping needed.

## Risk register

| Risk | Mitigation |
|------|------------|
| Sqlite `OnceLock` race during first call | `set` ignores the `Err`; we always re-read via `STORAGE.get()` after. |
| Plugin author confuses `value` (string) with structured data | Document that `slab.storage.set` takes string; recommend `JSON.stringify` in the SDK |
| Quota check + write not atomic → potential 1-byte overshoot under concurrent writes | Wrap quota-check + insert in a single `BEGIN IMMEDIATE` transaction (Slice 8b polish — out of scope for first ship; current behaviour is bounded race not unbounded) |
| Future migration needed | `SCHEMA_VERSION` + match arm pattern (see study_store.rs) |
| Plugins abuse `clear()` to log out users | Out of scope — that's plugin behaviour, not host concern |

## Out of scope (deferred to Slice 8b or later)

- Transactional batch writes (`slab.storage.transaction(fn)`)
- TTL-based expiry
- Encryption at rest (storage is no more sensitive than the PDFs Slab already opens)
- A `slab.storage.usage()` introspection surface (host code can compute via `kv_usage_bytes`; expose if plugins ask)
- A separate sub-namespace per plugin (e.g. `slab.storage.session` vs `slab.storage.persistent`)
- Frontend Cabinet UI showing per-plugin storage usage (probably v2.1.0 Forge)
