**Goal:** Wire the three remaining contribution kinds into runnable
backend surface area: locale bundle loader (Slice 5), command runner

## Slice 5 — Locale bundle loader

**Objective:** Provide a typed, validated way for the frontend i18n
layer to fetch the JSON bundle a plugin contributes for a given
locale, with the same `Record<string,string>` shape as
`src/lib/i18n/en.json`.

**Files:**
- Create: `src-tauri/src/plugins/locale_loader.rs`
- Modify: `src-tauri/src/plugins/mod.rs` (re-export)
- Modify: `src-tauri/src/lib.rs` (new Tauri command + registration)

**Behaviour:**
- `pub fn load_locale_bundle(plugin_dir: &Path, relative: &str)
  -> Result<HashMap<String, String>, String>`
- Reads the file via existing `read_asset` (path-traversal guard
  inherited), parses as `HashMap<String, String>`, returns flat map.
- Rejects bundles whose JSON values are not strings (nested objects,
  arrays, numbers).
- Tauri command `slab_plugins_load_locale_bundle(plugin_id, locale)`
  looks up the matching `ActiveLocale` and calls the loader.

**Commit:** `feat(plugins): locale bundle loader + Tauri cmd (Slice 5)`

## Slice 7 — Command runner (shell + url dispatch)

**Objective:** Execute a plugin-contributed command. For `shell`
commands, spawn `/bin/sh -c "<shell>"` (Windows: `cmd /C`) under a
wall-clock timeout, capture stdout/stderr. For `url` commands, return
a sentinel value so the frontend can dispatch through `tauri_plugin_opener`.

**Files:**
- Create: `src-tauri/src/plugins/command_runner.rs`
- Modify: `src-tauri/src/plugins/mod.rs` (re-export)
- Modify: `src-tauri/src/lib.rs` (new Tauri command + registration)

**Behaviour:**
- `pub enum CommandOutcome { Shell(ShellReport), Url(String) }`
- `pub fn run_command(cmd: &ActiveCommand) -> Result<CommandOutcome, CommandError>`
- Default timeout: 30_000 ms (consistent with `PdfActionContribution`
  default). No per-command override on `CommandContribution` yet
  (YAGNI — can add later if a plugin needs longer).
- Tauri command `slab_plugins_run_command(plugin_id, command_id)`.

**Commit:** `feat(plugins): command runner with shell/url dispatch (Slice 7)`

## Slice 8 — AI provider injection

**Objective:** Let plugins contribute an OpenAI-compatible AI provider
that Beacon can use just like the built-in `Ollama` / `OpenAI` choices.

**Files:**
- Modify: `src-tauri/src/ai/openai_compat.rs` (add `with_headers`,
  `with_extra_headers` builder)
- Modify: `src-tauri/src/ai/config.rs` (`make_plugin_provider`
  function that consumes an `ActiveAiProvider`)
- Modify: `src-tauri/src/lib.rs` (new Tauri command +
  `slab_plugins_provider_test`)

**Behaviour:**
- `OpenAiCompatibleProvider::with_headers(HashMap<String, String>)`
  attaches extra HTTP headers on every request (chat + embed).
- Header **values** may reference env vars via `$VAR_NAME` syntax —
  resolved at materialise time. Missing env var → error mentions the
  var name. Bare values (no `$` prefix) pass through verbatim.
- `make_plugin_provider(&ActiveAiProvider) -> Result<Arc<dyn AiProvider>, AiError>`
  builds an `OpenAiCompatibleProvider` from the contribution.
- Tauri command `slab_plugins_provider_test(plugin_id, provider_id)`
  mirrors `slab_beacon_provider_test`: round-trips one cheap chat
  call against the plugin provider and returns the model name.

**Commit:** `feat(plugins): contributed AI provider materialisation + test cmd (Slice 8)`
