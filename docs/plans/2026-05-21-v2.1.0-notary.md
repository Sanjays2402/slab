# Slab v2.1.0 "Notary" 🪶 — Cryptographic PKCS#7 Signing + Redaction Certification

> **For Hermes:** Use the `subagent-driven-development` skill to implement this
> plan task-by-task. Each slice is independently reviewable and shippable.
> Do NOT start Slice 1 until v2.0.13 "Vault" 🔒 has shipped to main and tagged.
> Strict order: v2.0.2 → v2.0.3 → v2.0.4 → v2.0.5 → v2.0.6 → v2.0.7 → v2.0.8 →
> v2.0.9 → v2.0.10 → v2.0.11 → v2.0.12 → v2.0.13 → **v2.1.0** → v2.1.1.

**Goal:** Upgrade v2.0.12's *visual* signatures into **legally-binding,
cryptographically verifiable PKCS#7 signatures** per ISO 32000-1 §12.8, and
attach a tamper-evident **Vault-Certified** seal to every v2.0.13 redaction.
After v2.1.0 ships, a Slab-signed PDF opens in Adobe Acrobat with a green
checkmark *("Signed and all signatures are valid")*, and a Slab-redacted PDF
carries a verifiable hash chain proving no glyph has been altered since the
redaction was committed.

**Architecture:** Four layers welded onto the existing sign + redact modules:

1. **Crypto core (Rust, `rsa 0.10` + `p256 0.14` + `cms 0.3` + `x509-cert 0.3`
   + `der 0.8` + `sha2 0.11`)** — a pure-Rust PKCS#7 CMS `SignedData` builder
   that takes a byte slice + a `SigningKey` and emits DER-encoded detached
   signatures. RSA-2048/3072/4096 + ECDSA-P256 supported; PSS padding for RSA;
   SHA-256/384/512 digests. Zero OpenSSL dep — keeps the bundle clean and
   cross-compiles on Linux/Windows/macOS without `libssl.so` runtime drift.
2. **Key & cert manager (Rust + Svelte)** — OS-keychain integration via
   `keyring 3.x` (macOS Keychain / Windows Credential Manager / Secret Service
   on Linux), plus PKCS#12 (`.p12`/`.pfx`) import via `p12 0.7`. Three flows:
   *Generate self-signed* (2048-RSA, 1-yr default, configurable Subject CN /
   Org / Email), *Import .p12*, *Use system keychain identity*. Private keys
   NEVER touch disk in plaintext — keychain refs only.
3. **PDF integration (Rust)** — embed the CMS blob in a `/Sig` dict with the
   ISO 32000-1 `/ByteRange [a b c d]` two-segment incremental-save layout,
   write the `/AcroForm` `/SigFlags 3`, register a `/Sig` widget annotation on
   the placement page, and (for redaction certification) emit a custom
   `/Slab_Vault` certification dict alongside the signature that hashes every
   redacted byte-range.
4. **Verify + Trust UI (Svelte + Rust)** — open-time verification pass: parse
   `/Sig` dicts, recompute hash, verify signature, walk the cert chain against
   the system trust store + Slab's own bundled "Vault Trust" CA list. Surface
   a top-of-doc **trust banner** (green / yellow / red) + a click-through
   **Notary Inspector** modal showing signer DN, signing time, algorithm,
   chain, and (for redacted docs) the per-rect SHA-256 manifest. WOW: the
   **480ms gold-ribbon Notary Seal unfurl animation** that plays once on the
   first successful verification of a doc.

**Tech Stack:** Rust 1.78 + Tauri 2 (six new commands: `slab_notary_generate_cert`,
`slab_notary_import_p12`, `slab_notary_list_identities`, `slab_notary_sign`,
`slab_notary_verify`, `slab_notary_certify_redaction`), six new crates pinned
above (all pure-Rust, MIT/Apache-2.0), Svelte 5 runes for two new panels
(`NotaryPanel.svelte`, `NotaryInspectorModal.svelte`) + the trust banner
component (`TrustBanner.svelte`), CSS `@keyframes` for the seal unfurl, no
new JS deps.

**Codename:** "Notary" 🪶 — Slab becomes the offline, free, legally-binding
alternative to Adobe Sign + DocuSign. Sign a contract, verify a counterparty's
signature, certify a redaction — all on the laptop, all offline, all
provable in court.

use sha2::{Digest, Sha256, Sha384, Sha512};

pub fn sha256(input: &[u8]) -> [u8; 32] {
    let mut h = Sha256::new();
    h.update(input);
    h.finalize().into()
}

pub fn sha384(input: &[u8]) -> [u8; 48] {
    let mut h = Sha384::new();
    h.update(input);
    h.finalize().into()
}

pub fn sha512(input: &[u8]) -> [u8; 64] {
    let mut h = Sha512::new();
    h.update(input);
    h.finalize().into()
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum DigestAlg { Sha256, Sha384, Sha512 }

    pub fn oid(self) -> &'static str {

            DigestAlg::Sha384 => "2.16.840.1.101.3.4.2.2",
            DigestAlg::Sha512 => "2.16.840.1.101.3.4.2.3",
        }

}

// src-tauri/src/notary/keys.rs
use rsa::{pkcs8::{DecodePrivateKey, EncodePrivateKey}, RsaPrivateKey, pss::SigningKey as RsaPss};
use p256::ecdsa::SigningKey as P256Sk;
use x509_cert::{builder::CertificateBuilder, name::Name, time::Validity, serial_number::SerialNumber, spki::SubjectPublicKeyInfoOwned};
use der::Encode;
use std::time::{SystemTime, UNIX_EPOCH};

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum KeyAlg { Rsa2048, Rsa3072, Rsa4096, EcdsaP256 }

#[derive(Debug, Clone)]
pub struct CertParams {
    pub common_name: String,
    pub organization: Option<String>,
    pub email: Option<String>,
    pub country: Option<String>,
    pub valid_days: u32,
}

impl CertParams {
    pub fn test_default() -> Self {
        Self {
            common_name: "Slab Test User".into(),
            organization: Some("Slab".into()),
            email: None,
            country: Some("US".into()),
            valid_days: 365,
        }
    }
}

pub enum SigningKey {
    Rsa { sk: RsaPrivateKey, cert_der: Vec<u8>, alg: KeyAlg },
    Ecdsa { sk: P256Sk, cert_der: Vec<u8> },
}

impl SigningKey {
    pub fn generate_rsa(bits: u32, params: &CertParams) -> Result<Self, NotaryError> {
        let alg = match bits {
            2048 => KeyAlg::Rsa2048,
            3072 => KeyAlg::Rsa3072,
            4096 => KeyAlg::Rsa4096,
            _ => return Err(NotaryError::UnsupportedKeyBits(bits)),
        };
        let mut rng = rand::thread_rng();
        let sk = RsaPrivateKey::new(&mut rng, bits as usize)?;
        let cert_der = build_self_signed_cert_rsa(&sk, params)?;
        Ok(Self::Rsa { sk, cert_der, alg })
    }

    pub fn generate_ecdsa_p256(params: &CertParams) -> Result<Self, NotaryError> {
        let mut rng = rand::thread_rng();
        let sk = P256Sk::random(&mut rng);
        let cert_der = build_self_signed_cert_ecdsa(&sk, params)?;
        Ok(Self::Ecdsa { sk, cert_der })
    }

    pub fn algorithm(&self) -> KeyAlg {
        match self {
            Self::Rsa { alg, .. } => *alg,
            Self::Ecdsa { .. } => KeyAlg::EcdsaP256,
        }
    }

    pub fn certificate_der(&self) -> Result<Vec<u8>, NotaryError> {
        Ok(match self {
            Self::Rsa { cert_der, .. } | Self::Ecdsa { cert_der, .. } => cert_der.clone(),
        })
    }

    pub fn sign(&self, digest: &[u8], alg: DigestAlg) -> Result<Vec<u8>, NotaryError> {
        match self {
            Self::Rsa { sk, .. } => {
                let signer: RsaPss<Sha256> = RsaPss::new(sk.clone());
                Ok(signer.sign_with_rng(&mut rand::thread_rng(), digest).to_vec())
            }
            Self::Ecdsa { sk, .. } => {
                let signature: p256::ecdsa::Signature = sk.sign(digest);
                Ok(signature.to_der().as_bytes().to_vec())
            }
        }
    }
}

fn build_self_signed_cert_rsa(sk: &RsaPrivateKey, params: &CertParams) -> Result<Vec<u8>, NotaryError> {
    use x509_cert::builder::Builder;
    let serial = SerialNumber::generate(&mut rand::thread_rng())?;
    let validity = Validity::from_now(std::time::Duration::from_secs(
        params.valid_days as u64 * 86400,
    ))?;
    let subject = Name::from_str(&format!(
        "CN={},O={},C={}",
        params.common_name,
        params.organization.as_deref().unwrap_or("Slab"),
        params.country.as_deref().unwrap_or("US"),
    ))?;
    let spki = SubjectPublicKeyInfoOwned::from_key(&sk.to_public_key())?;
    let builder = CertificateBuilder::new(
        x509_cert::builder::Profile::Root,
        serial,
        validity,
        subject,
        spki,
        sk,
    )?;
    let cert = builder.build()?;
    Ok(cert.to_der()?)
}

- Create: `src-tauri/src/notary/pdf_sign.rs` (~320 LOC — `/Sig` dict + ByteRange)
- Create: `src-tauri/src/notary/pdf_verify.rs` (~280 LOC — parse + verify)
- Create: `src-tauri/src/notary/widget.rs` (~140 LOC — `/Widget` annot for sig)
- Modify: `src-tauri/src/notary/commands.rs` — add `slab_notary_sign` +
  `slab_notary_verify` commands (~120 LOC delta)
- Modify: `src-tauri/src/lib.rs` (register 2 more commands)
- Create: `src-tauri/src/notary/tests/pdf_roundtrip_test.rs` (~280 LOC, 12 cases)
- Create: `src-tauri/src/notary/tests/fixtures/three_page.pdf` (test fixture)

**Algorithm (pdf_sign.rs):**

1. Parse the input PDF via `lopdf`.
2. Add a `/AcroForm` dict if absent; ensure `/SigFlags 3`.
3. Add a `/Sig` field dict with `/FT /Sig`, `/T (Slab Notary <UUID>)`,
   `/V` pointing to the signature dict below, `/Kids` listing one widget annot.
4. Add a `/Widget` annotation on the placement page with `/Subtype /Widget`,
   `/Rect [x y x y]` (1pt invisible by default; user-positioned if the user
   dragged a sig field), `/F 4`, `/Parent` -> sig field.
5. Build the signature dict skeleton with placeholder `/ByteRange [0 0 0 0]`
   and `/Contents <` + 8192 zero hex digits + `>` (an over-allocated buffer).
6. Serialize the PDF to bytes (incremental save preserves the original).
7. Compute the actual `/ByteRange` covering everything except the `/Contents`
   placeholder; rewrite the bytes in place.
8. SHA-256 the two byte-ranges, hand the digest to `cms::build_signed_data`.
9. Hex-encode the CMS DER blob, pad with zeros to fill the placeholder.
10. Write the final bytes to the output path.

**Algorithm (pdf_verify.rs):**

1. Parse the input PDF.
2. Walk `/AcroForm/Fields` for `/FT /Sig` entries.
3. For each: read `/ByteRange`, SHA-256 the covered ranges, hex-decode
   `/Contents`, pass to `cms::verify_signed_data`.
4. Walk the certificate chain in the CMS blob; for each cert, attempt to
   validate against (a) the system trust store via `rustls-native-certs` (we
   already depend on `rustls` transitively), (b) Slab's bundled "Vault Trust"
   list (`src-tauri/resources/vault_trust.pem`, ~5 KB curated CAs), (c) for
   self-signed certs, mark trust as "self-signed" (yellow, not red).
5. Return a `VerificationReport` per signature with: validity bool, signer
   subject, signing time, algorithm, chain trust level, covered byte count,
   tampered bool.

**Tests:** 12 cases — sign + verify round-trip, sign two times incrementally
(second sig validates BOTH), verify catches a single-byte tamper after sig,
verify reads Adobe Acrobat-produced .pdf fixture (`fixtures/acrobat_signed.pdf`),
verify reads a known-bad fixture (expired cert), verify reads a sig over a
strict subset of the file, reject sig that covers `/Contents` itself (security
check), reject sig with mismatched digest OID, default placement rect is
1×1 invisible at bottom-right, custom placement rect honored, widget annot
attached to correct page, `/SigFlags 3` set even when starting from a PDF
with no AcroForm.

**`/Slab_Vault` dict (custom, Adobe-compatible because it's just a private key):**

```pdf
<<
  /Type /Slab_Vault
  /Version 1
  /RedactedAt (D:20260521024000-07'00')
  /RedactedBy (<signer CN>)
  /Manifest [
    << /Page 1 /Rect [ 72.0 720.0 540.0 740.0 ] /BytesRemoved 142
       /OriginalSha256 <a1b2c3...> /AfterSha256 <d4e5f6...> >>
    << /Page 1 /Rect [ ... ] /BytesRemoved 38 ... >>
    << /Page 3 /Rect [ ... ] /BytesRemoved 1024 ... >>
  ]
  /ChainHash <e7f8...>   % SHA-256 of the concatenated manifest
>>
```

The `/ChainHash` is included in the CMS signed-attributes blob, so any
tampering with the manifest breaks the signature. On verify, Slab recomputes
the manifest hash from the file's current state and compares.

**Tests:** 8 cases — certify redact, verify shows manifest, tamper one
manifest entry → verify fails, tamper one redacted byte (impossible without
re-redacting since glyph is gone, but: tamper a non-redacted byte adjacent
to a redact rect → verify still passes if outside ByteRange), manifest
hash deterministic, certify a doc that has zero redactions → no `/Slab_Vault`
emitted (just a normal sig), certify a doc that was already redacted in
v2.0.13 without a cert → upgrade path adds cert in-place, certify works on
encrypted PDFs (Slice 3 of v2.0.4 — encryption pre-pass).

**Commit:** `feat(notary): Vault redaction certification — hash-chained manifest signed in /Sig dict`

## Open questions (deferred to v2.1.1 "Notary II")

1. **RFC 3161 timestamp authority** — embed a TSA timestamp in the CMS blob
   so the signing time is provable even after the signer's cert expires.
   Requires HTTP egress on demand → privacy-toggle gate. Tracked.
2. **LTV / DSS (Document Security Store)** — embed CRL + OCSP responses in
   the PDF so the chain remains verifiable decades later. Requires HTTP egress.
3. **Multiple parallel signers** — co-sign workflow where two parties sign
   the same document independently and both signatures remain valid.
4. **Visual signature appearance editor** — let users tweak the
   `/AP /N` appearance stream (logo, "Digitally signed by…" text overlay,
   reason field, location field) instead of the Slab default.
5. **Batch sign** — drop a folder of PDFs, get them all signed with the
   default identity in one operation. Pairs naturally with v0.10.0's batch
   automations.
6. **CRL / OCSP revocation check** — verify-time online check that the
   signing cert hasn't been revoked. Requires HTTP egress → privacy gate.
7. **Hardware token / YubiKey / Smartcard** — sign using a PKCS#11 device.
   Big surface (cross-platform driver matrix), defer.
8. **Mobile-friendly signature drop layout** — when v1.5.0 ships the iPad
   client, the cert picker dropdown needs a touch-first rework.
