# v3.14.0 "Reflow" — Offline PDF → Word (.docx) Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Convert a PDF into a fully-editable Microsoft Word `.docx` file —
locally, offline, free, cross-platform — preserving text, paragraph structure,
headings, lists, basic table detection, and inline images. Ship as a top-level
`Reflow` panel + Atelier step + CLI subcommand.

**Architecture:** New `src-tauri/src/pdf/reflow/` module. Three layers:

1. **Extraction (`extract.rs`)** — walk the PDF's content streams via `lopdf`,
   pull text runs with their `(x, y, font, size, weight)` metadata using
   PDF.js-style glyph positioning. Output a `Vec<TextRun>` per page.
2. **Layout reconstruction (`layout.rs`)** — group runs into lines (y-cluster),
   lines into paragraphs (gap heuristic + indent change), classify each
   paragraph as `Heading{1..3}`, `Body`, `ListItem(bullet|number)`, or
   `TableRow` (column-x clustering). Output a `Vec<Block>`.
3. **DOCX writer (`docx.rs`)** — emit OOXML inside a ZIP (`word/document.xml`,
   `word/styles.xml`, `[Content_Types].xml`, `_rels/.rels`,
   `word/_rels/document.xml.rels`). Uses the existing optional `zip` dep
   (already in `Cargo.toml` for the server feature — flip it on by default
   for the `reflow` feature flag).

Wedge: Adobe Acrobat Pro's "Export to Word" is the single most-used Acrobat
feature and is paid + cloud-trip. PDF Expert ships a cloud-only version.
Foxit charges. We ship offline, free, on every OS.

**Tech Stack:**
- `lopdf` 0.40 (already in tree) — content stream decoding.
- `zip` 2.x (already optional in Cargo.toml) — DOCX container.
- `quick-xml` (new dep, ~50 KB) — fast OOXML emission. (Optional: hand-roll if
  we want zero new deps; OOXML is structured enough.)
- `unicode-bidi` (new dep, tiny) — for RTL paragraph handling (Hebrew/Arabic).

**No new runtime deps beyond `quick-xml`.** Decision: use `quick-xml` because
OOXML escaping rules are subtle and we'd regret hand-rolling.

## DRY, YAGNI, TDD notes

- **DRY:** reuse `lopdf::Document` loading (don't re-implement). Reuse Atelier's
  batch-runner — `ConvertToDocx` is just another step.
- **YAGNI:** no font embedding in v1, no images in v1 (image extraction is Task 11
  in v3.15.0 if customers demand). Skip column detection for newspaper layouts.
- **TDD:** every task ships with at least 1 failing test first, then implementation.

- Tasks 4+5 = one tick (layout + writer go together).
