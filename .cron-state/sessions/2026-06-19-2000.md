## Slice-by-slice

### Slice 13 — Recent searches strip
Backend: QueryRow gains Serialize+Deserialize, new `clear()` helper scoped
to library_search_log (does NOT touch suggestion-dismissals — pinned by
test). Two Tauri commands: `slab_library_recent_searches(limit?: u32)` →
Vec<QueryRow> (limit clamps 1..=50, default 8); `slab_library_clear_search_history()`
→ usize (emits library-changed only when n>0 — idiomatic with other writes).
TS client (RecentSearch + recentLibrarySearches + clearLibrarySearchHistory)
bundled with backend per convention. UI: chip strip above empty-state tips
when recents>0, each chip = one-click re-run via existing runSearch path,
result-count badge surfaces "0" as a "this stopped matching" signal,
"Clear history" affordance confirms with the exact count.

### Slice 14 — Per-folder scope filter
Backend search() already accepted folder_id; pure frontend slice exposes
it via a native <select> in the search header that renders only when
folders.length > 1. onScopeChange immediately re-queries (no Enter needed)
via the existing runSearch path. A vanishing scope folder silently self-
heals back to All. Result-count line + no-matches empty-state both
surface the active scope inline.

### Slice 15 — Quoted-phrase queries
Replaced build_match_expr's bag-of-words sanitiser with a hand-written
tokenize() → Vec<Tok::Bare | Tok::Phrase> lexer so `"force majeure"`
becomes a single FTS5 phrase token (adjacent-word match). Curly-quote
support (macOS auto-correct), unterminated-phrase tolerance (Google
behaviour), metachar-scrub inside phrases. Bare-word LAST keeps the
prefix glob; phrases never get `*` (FTS5 rejects "a b"*). UI tips
help-text grows a quotes line.

### Slice 16 — Exclude-term syntax (-word)
Lexer grows Tok::Exclude; formatter emits `NOT "word"`. Exclude-only
queries return `[]` (FTS5 needs a positive anchor). co-op mid-word `-`
not a trigger; lone `- ` dropped; `-"prior draft"` exclude-a-phrase
works; scrub_word still cleans the excluded term so metachars can't
sneak into NOT. UI tips help-text grows a -prefix line. Examples-as-
code styling for `<code>` mirroring the existing `<kbd>` chrome.

### Slice 17 — Pinned index-status footer
`count_indexed_docs` promoted from test-only to pub callsite alongside
new IndexStats { docs, pages } via cheap COUNT-pair. One Tauri command.
TS client bundled with backend. UI footer pinned beneath .results
(flex-shrink:0 so it never scrolls), accent-green status dot mirrors
LibraryPanel indexed pip; refreshes on mount + after every runSearch
so a mid-session scan makes the counts grow live without a panel
remount. {#if} guard collapses the footer on a 0/0 empty index.

### Fix commit b9b7a76
Two test expectations corrected to match actual (correct) lexer
behaviour: (a) the LAST bare-word token always gets the prefix `*`
regardless of whether a phrase follows it (a user typing `dra "force
majeure"` is mid-typing `dra`); (b) scrub_phrase collapses adjacent
non-space metachars rather than synthesising word boundaries (same
heuristic `co-op -> coop` uses for bare words). Plus clippy
`-D unused-assignments` caught a dead `pending_neg = false` reset in
the whitespace branch; outer reset already covered both paths.
Behaviour identical, dead assignment removed, comment in tokenize()
pinned for future cleanup safety.

## Deferred / notes

Nothing deferred this batch — all 5 slices shipped fully. The 4-feature
"phrase OR exclude" lexer pivot landed naturally as 2 separate slices
because they extend the same `tokenize()` function with one token-kind
each; reviewing them as one mega-commit would have hidden which behaviour
belongs to which feature. Keeping them as 2 commits preserves
revertability.

## Lessons retained

- **Batch saves gate budget.** Five slices × 5 gate runs = expensive;
  one batch × one gate run = cheap. The fix commit at the end of the
  batch caught what per-slice gates would have caught after each, so
  the saving is real with zero correctness loss.
- **Clippy unused-assignments fires on whitespace-branch `=false` resets
  when the outer scope already resets.** Pin the comment so the next
  cleanup pass doesn't repeat the mistake of "be defensive, reset twice"
  — defensive is fine, but clippy is a hard gate.
- **Test expectations can be wrong even when the implementation is right.**
  Both test failures here were my own expectation errors, not lexer bugs.
  Trust the gate; debug both sides.
