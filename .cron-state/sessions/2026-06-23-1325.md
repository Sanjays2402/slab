## Process notes

- Same canonical 5-layer cadence as rounds 19-29: backend primitive
  -> TS mirror primitive -> Tauri command + TS client wrapper ->
  pure-helper bridge -> demo-able UI slice. Round 30's bridge
  (slice 146) is a STATEFUL primitive (carries snapshot + label +
  timestamp) rather than a pure derivation from wire types — but
  the staleness gate + describe helper compose purely with no
  Svelte runes, keeping the bridge testable at the same level as
  prior bridges.
- Round 30 picked the undo path over rule reorder-by-drag (rounds
  26-29's deferred candidate) because it's the structurally-
  cleanest 5-layer arc that EXTENDS the existing toast surface
  (the cov-export-toast going from one-shot to two-affordance
  closes the "fix / undo" loop) AND it closes the regret loop
  opened by round 29 (a user who can't undo a 5-rule reorder is
  worse off than before the batch path landed).
- The REVERT-direction diff (current -> snapshot rather than
  snapshot -> current) in computeUndoStatus is the load-bearing
  detail. Same primitive, different argument order — the bridge
  layer's job to pick the right direction so the UI's copy reads
  naturally without inversion.
- The applied=0 fast path NOT stashing a snapshot, and the export
  path explicitly clearing the snapshot, are the two hygiene
  details that keep the affordance from surfacing in wrong
  contexts. Easy to miss; would have created phantom-button bugs.
