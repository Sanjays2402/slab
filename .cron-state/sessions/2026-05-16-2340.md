## Decisions / deviations
- **No sidebar nav for this slice.** The original spec said "right-click menu"; I implemented it as a left-click selection bubble instead. Two reasons: (a) right-click in Tauri/Webview is finicky and conflicts with the OS-level context menu, (b) the bubble pattern is what Notion/Reflect/Granola/Highlights all use and feels native on macOS. The functional surface (5 actions on a snippet) matches the spec exactly.
- **Lightweight LLM path.** Did NOT reuse `chat::beacon_chat` — that builds a 30K-char PDF context for every call, which is total waste for a 60-char "translate this" snippet. Selection actions only ferry the snippet itself + a tightly-scoped action prompt. ~10× faster for the common case.
- **Why 8000-char cap?** Pinned in `MAX_SELECTION_CHARS`. Longer selections should use the chat panel, which already has the right UX for multi-paragraph context. Cap is enforced server-side so a malicious caller can't pass a huge prompt; the front-end never gets close to it (PDF selections are typically <500 chars).
