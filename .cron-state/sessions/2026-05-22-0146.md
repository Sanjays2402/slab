### Architecture decisions baked in

- **`PageOp` tagged-union** (Rust + TS twin) means the undo stack is a list of small, JSON-serializable deltas — not a heavyweight snapshot diff. O(1) push/undo regardless of PDF size.
- **Lazy-flush save model** — ops accumulate in memory; thumbnails update in-place; disk I/O only on explicit Save via `slab_apply_page_ops`. Avoids the "rewrite 200-page PDF on every Cmd+Z" trap.
- **`atomic_save` helper** — tempfile + `fsync` + `rename(2)` on the same filesystem. Crash mid-save → original file intact. Lives in `src-tauri/src/pdf/mod.rs` and is reusable by every other writer (Slice 1 Task 3).
- **`rotate_pages_permanent`** strips `/Rotate`, swaps `MediaBox`/`CropBox`, prepends a `q <matrix> cm` rotation to every content stream and appends ` Q`. Result re-opens identically rotated in any viewer (Slice 2 Task 4). Covers acceptance criterion #3.
- **`InsertSource::Image`** decodes via `image 0.25` (already a dep through OCR), embeds as a FlateDecode'd DeviceRGB XObject, sizes the page to `pixels / dpi` (Slice 3 Task 7). Covers acceptance criterion #2.
- **Fixture builder** generates a deterministic 5-page PDF in `$CARGO_TARGET_TMPDIR` — keeps the repo binary-free while letting every test reproduce the same multi-page input. Lives in `src-tauri/tests/fixtures/mod.rs` (Slice 2 Task 4).
- **`issue_26_acceptance.rs`** integration test exercises all 6 acceptance criteria from the issue body as one suite — single source of truth for "is #26 actually done".
