## Decisions / deviations

- **Did not start Slice 6 in the same tick.** Slice 6 (in-place text editing backend) is genuinely deep: PDF text encoding (WinAnsi/MacRoman/StandardEncoding/CID), span-indexing inside a content stream parsed via lopdf, Tf/Tm/Td matrix preservation, font fallback for missing glyphs. The plan calls for "6 tests" but those 6 cover only the easy ASCII / WinAnsi path; the hard cases need design. Better to ship Slice 5 cleanly and tackle Slice 6 with its own dedicated tick.
- **Tabs only show for Reader feature.** All other panels (Beacon, Merge, Split, Pages, Compress, etc.) are single-instance tool panels with no per-document state worth preserving across switches. Adding tabs to them would be UI clutter for no benefit.
- **Inactive tabs are `display: none`, not unmounted.** Keeping them mounted means switching tabs is instant and preserves zoom/page/find state. The cost is memory (one pdfjs viewer per tab) but Slab is a desktop app so this is fine — and `display: none` does still pause `requestAnimationFrame` so CPU is essentially zero for hidden tabs.
- **Ctrl+Tab, not ⌘+Tab.** macOS Cmd+Tab is the app switcher — hijacking it is hostile. Ctrl+Tab is the standard cross-OS browser/editor convention.
- **Closing the last tab resets to "New tab" instead of disappearing.** Empty state is friendlier than a closed window.

## Risks / follow-ups

- Cmd-click on a "recent file" in the palette currently opens it in the *active* tab, replacing the doc. Adding "open in new tab on Cmd-click" is a small follow-up (probably 5 LOC in `onSelectPanel` / `onOpenRecent`). Not blocking.
