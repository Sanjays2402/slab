## Why v2.0.6 next?

1. **Launch-blocker math.** Adobe, PDF Expert, Foxit, and even macOS
   Preview persist annotations automatically. Slab today does not — every
   highlight and sticky note vanishes the moment the doc closes unless
   the user explicitly clicks "Save to new PDF", which *destructively
   rewrites the file*. A reviewer who tries v2.0.5 expecting paid-product
   parity will close the app the moment their first highlight disappears.
2. **DRY-against-pipeline.** v2.0.6's `annotations.ts` store mirrors
   v2.0.4's `readingPosition.ts` and v2.0.5's `bookmarks.ts` line-for-line.
   Writing it now while those patterns are fresh in context is cheaper
   than re-discovering the eviction/listener/quota patterns later.
3. **Cross-cutting bonus.** This introduces the first "persistent
   sidecar JSON keyed by file path" pattern that v2.0.7 (drawing
   annotations), v2.0.8 (comment threading), and v2.0.9 (per-doc reading
   speed) will all reuse.
4. **Existing Rust surface is already there.** `slab_append_annotations`
   and `slab_export_annotations_md` Tauri commands already accept the
   exact serde shape the new TS store produces. **No new Rust modules
   needed for the happy path** — only two ActionId variants for the
   keymap.

## Codebase-discovery decisions baked into the plan:

- `Annotation` Rust enum is already a tagged union with `serde(tag =
  "kind", rename_all = "snake_case")` — the TS store's on-disk shape
  is **byte-compatible** with what `slab_append_annotations` accepts.
  Burn-into-PDF works without any backend changes.
- `AnnotateLayer.svelte` already does the hard work: text-selection →
  client-rects → PDF user-space quads via `pv.viewport.convertToPdfPoint()`.
  Slice 2 just changes the *commit step* from `pending = [...pending, ...]`
  to `addAnnotation(path, ...)`.
- pdfjs's `eventBus.pagerendered` is the right hook for the overlay
  render — it fires on initial render AND on zoom changes. (Confirmed
  by reading ReaderPanel.svelte around line 677–688 where
  PDFFindController and PDFViewer are wired.)
- `ActionId` is registered in **both** Rust (`keymap/action.rs:14-34`)
  and TS (`keymap.ts:27-46`) — Slice 2 edits both. Settings UI picks
  the new variants up automatically via `all_actions()`.
- Vim-style single-letter `h` mode mirrors the existing pattern in
  `src/lib/vim/keymap.ts` — no new pattern, no new philosophy.
- Onboarding step count math: 6 today, v2.0.3 adds 1 (Beacon AI), v2.0.4
  adds 1 (Memory), v2.0.5 adds 1 (Bookmarks), v2.0.6 adds 1
  (Annotations) — final count 10. Strict-order requirement.
- i18n namespace: `annotations.*`, `settings.annotations.*`,
  `palette.annot.*`, `onboarding.annotations.*` — all greenfield. No
  collision with v2.0.2/2.0.3/2.0.4/2.0.5.
