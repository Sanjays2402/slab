## Why the lead slice is a hotfix

CI run `26147660187` for v2.0.1 failed on Windows with:

```
bundled plugin "com.slab.examples.hello-workshop" failed manifest parse:
  runtime.sha256 mismatch for "script.js":
    manifest says ca687208c1316e39d05a02c6122fba252ac59683331412971206797e9dd0f83c
    on-disk is a095b80a5a999672ca76198ca0765bb2e12f4b2ee48a8ab404631b32818ae24b
```

Root cause: Windows checkout converts `script.js` to CRLF, `include_str!`
captures the CRLF bytes, sha256 no longer matches the LF-computed digest
in `manifest.toml`. Fix is a one-file `.gitattributes` pinning every
byte-hashed text format (`.js`, `.toml`, `.json`, ...) to `eol=lf`. Two
commits: add the file, then `git add --renormalize .`.

This lands on `main` directly because it's a release blocker, then
feature work for v2.0.2 continues on `feature/v2.0.2-workshop-marketplace`.

## Architecture decisions documented in the plan

- **Schema v2 as wrapper, not extension** — `IndexEntryV2` wraps
  `IndexEntry` via `#[serde(flatten)]` so the JSON wire format is a
  strict superset and v1-signed indices still verify.
- **`BUNDLED` signature sentinel** — bundled entries in the seed index
  use `signature: "BUNDLED"` + `download_url: "bundled://..."`. The
  verifier short-circuits Ed25519 for this pair because the bytes ship
  in-binary and don't need network-trust.
- **Fuse.js over hand-rolled fuzzy search** — 6 KB gzipped, mature lib,
  `includeMatches: true` gives us the per-character indices we need for
  the highlight `<mark>` spans. Lazy-import documented as Slice 6.5
  fallback if cold-start cost matters.
- **YAGNI: drop "Newest" sort** — no `published_at` timestamp on entries
  yet; ship only Popular + Alpha + Updates-First until a publisher emits
  timestamps.
