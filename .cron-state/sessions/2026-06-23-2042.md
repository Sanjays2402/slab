## Picks / notes

- Picked the popover path because it was the structurally-cleanest
  5-layer arc that EXTENDS round-31's chip surface (same chip
  becomes the popover trigger — no new gesture vocabulary, no new
  chrome to learn). The deferred reorder-by-drag candidate stays on
  the candidates list but is now even less urgent.
- The bridge layer (slice 156) is structurally similar to slice 151
  (round 31's pushUndoEntry/popUndoEntry/selectActiveUndo) — both
  return fresh arrays (inputs never mutated) and both preserve
  snapshot reference identity for retained entries so downstream
  consumers see the same object the user originally captured. Slice
  156 adds the summarizeRingForJump bridge between the live-ring
  shape (with snapshots) and the slice-154 planner's compact wire
  shape.
- Newest-first dropped_labels order is the load-bearing copy
  choice. The JUMP drops the newest entries (the most-recent
  actions the user is discarding), so the labels read in
  chronological order from now-backwards as the user expects.
- Active target badge for the newest-ready row (instead of a "Jump
  here" button) prevents an obvious footgun: clicking Jump-here on
  the newest entry would be identical to the cascade Undo button.
  One explicit surface per action keeps the surface count one.
