## Process notes

- DocumentRecord widening this round added TWO columns (`notes`
  and `starred`), touching the same 7 SQL SELECT call sites + 5
  row-constructor sites TWICE. Used `replace_all=true` for the
  repeated SELECT pattern in registry.rs / ocr_queue.rs to keep
  the slice clean and not have to patch each site individually.
- Slice 35's `upsert_existing_doc_preserves_starred` test is the
  guard against a regression where someone adds `starred =
  DEFAULT` to the upsert UPDATE SET clause — the scanner
  re-upserts every doc on rescan, and silently wiping a user's
  star would be a bad day for the user. The test seeds, stars,
  re-upserts with new hash/size, asserts the star survives.
- DocInspectorPanel chose drawer-not-modal explicitly because the
  inspector wants CONTEXT (look at it WHILE you scan the grid),
  not focus. OcrQueuePanel / BeaconCachePanel are maintenance
  screens where modality is correct.
- Tags are read-only in the drawer — duplicating the picker chrome
  would either confuse it with the card-menu Tags section or
  invite a second flavour of bugs. The hint sends users to the
  card menu.
- Notes save on blur because an autosave inspector has no Save
  button competing for footer real estate with Open / Reveal /
  Remove (the three terminal actions that DO deserve buttons).
- No keyboard shortcut for "open inspector" — vim-mode + the card
  menu + the right-click are sufficient discovery. Would have
  collided with App-level Cmd+I anyway.
