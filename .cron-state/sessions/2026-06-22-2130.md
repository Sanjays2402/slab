# Round 26 — Hopper Rule Coverage Export arc (2026-06-22 21:30 PT)

Shipped 5 slices closing one cohesive arc: the rule coverage panel
export path. Before this tick the drilldown popover (slices 88-94)
had CSV + JSON export but the parent coverage panel — which holds
the per-rule first_match / would_match counts plus the fall-through
count — had no export of its own. A paralegal building a 6-rule
chain who wanted to email "here's the coverage report for last 100
runs" to a partner still had to screenshot the panel. Round 26
closes that symmetry gap end-to-end: backend CSV + JSON primitives,
Tauri command surface + TS client + filename helper, a pure
chain-health classifier composing per-row diagnostics into a
chain-level summary, and the demo-able UI gluing it all together.

## Slices

- **Slice 123** (0411c36) — rule coverage CSV export primitive.
  Pure-data RFC-4180 serialiser `rule_coverage_to_csv(report,
  include_header) -> String`. 6 columns: index (blank on synth row)
  + name ("Fall-through" on synth row) + first_match + would_match
  (blank on synth) + first_match_pct (two decimals, divide-by-zero
  guarded) + diagnostic ("" / "dead" / "shadowed" / "zero" /
  "fallthrough"). One row per rule + one trailing synthetic
  fall-through row emitted even when zero (audit signal not
  silence). `RULE_COVERAGE_CSV_HEADER` pub const. 10 tests pinning
  shape + pct formatter + RFC-4180 escape + dead-wins-over-zero
  precedence + column count.

- **Slice 124** (4fc6599) — rule coverage JSON envelope primitive.
  `RuleCoverageExportEnvelope` with 10 fields including envelope-
  level chain-health totals pre-derived in ONE pass
  (`dead_rule_count` + `shadowed_rule_count` +
  `zero_coverage_rule_count`) plus `fallthrough_pct` rounded to two
  decimals matching the CSV serialiser EXACTLY (cross-checked by
  test). `RULE_COVERAGE_EXPORT_SCHEMA_VERSION = 1` PARALLEL-
  versioned with the seven sibling envelopes (install-log family
  + drilldown). 12 tests including full serde round-trip, pretty-
  print round-trip, parallel-versioning equality with drilldown,
  dead-rule-excluded-from-shadowed-count precedence, no-NaN guard.
  PartialEq only (no Eq — envelope carries an f64).

- **Slice 125** (09f286f) — Tauri commands + TS client + filename
  helper. 2 commands (`slab_hopper_export_coverage_csv` + `_json`)
  wired into invoke handler. Accept `RuleCoverageReport` directly
  (no re-fetch) so "export what's visible" matches the user's
  mental model and avoids the 600ms-debounced-recompute race
  window. TS: `slabHopperExportCoverageCsv` +
  `slabHopperExportCoverageJson` async wrappers (browser-mode safe
  no-op) + `suggestCoverageExportFilename({watchId, now, ext})`
  emitting `hopper-coverage_<watch>_<YYYY-MM-DD>.<ext>`. No
  per-bucket slot (unlike `suggestDrilldownExportFilename`) — a
  coverage export covers the WHOLE chain; pinned by a dedicated
  regression test. 9 inline tests.

- **Slice 126** (c2deb49) — chain-health summary helper.
  `summarizeCoverageHealth(report, { fallthroughWarnPct = 25 })`
  -> `CoverageHealth { kind, text, dead, shadowed, zero,
  fallthrough, fallthroughPct }`. Four mutually-exclusive kinds
  with strict priority: `empty` (no samples) > `critical` (any
  dead rule) > `warn` (any shadowed / zero diagnostic OR
  fall-through STRICTLY greater than threshold) > `healthy`. The
  `kind` tag drives chip color in the UI without re-deriving
  classification in Svelte. Pluralisation contract pinned: "1
  dead rule" / "3 dead rules", "1 rule is partially shadowed" /
  "2 rules are partially shadowed" (verb agreement on the
  shadowed branch is the only English-grammar gotcha). 32 inline
  tests covering empty state, healthy, every diagnostic kind in
  singular + plural, shadowed-beats-zero precedence,
  exactly-25%-stays-healthy threshold pin (strictly greater
  triggers warn), tuneable threshold, dead-beats-high-fallthrough
  precedence.

- **Slice 127** (4765bdf) — coverage panel Export menu + Health
  chip. Demo-able payoff. Coverage panel gains the
  three-state chain-health chip (neutral healthy / warm warn /
  danger critical) inline beside the existing routed-percentage
  summary line — `coverageHealth` is `$derived.by` so a rule edit
  + 400ms-debounced refresh repaints the chip the moment the
  report lands. Empty kind filtered upstream so the chip never
  renders for "no samples yet" (cov-summary's "Loading…" /
  "No recent runs" copy carries that state instead). Export…
  popover in cov-actions row with two menu items (CSV / JSON)
  mirroring the drilldown popover Export… affordance for
  cross-surface consistency. `exportCoverage(format)` handler
  mirrors `exportDrilldown` shape exactly — same in-flight gate,
  shared toast cell, same in-state-snapshot semantics.
  `coverageExportMenuOpen` toggle dismisses on Escape (highest
  priority in the chain — Notion-style stacked-overlay
  dismissal). Scoped CSS for `.cov-health` + `.cov-export-anchor`
  + `.cov-export-menu` + `.cov-export-toast` with fade-in
  animation (key name `cov-export-toast-fade-in` for collision-
  freedom).

## Process notes

- Same canonical 5-layer cadence as rounds 19-25: backend CSV
  primitive -> backend JSON envelope primitive -> Tauri commands
  + TS client + filename helper -> pure-helper composer
  (summarizeCoverageHealth — the "consume the envelope's
  classification in chip form" piece) -> demo-able UI slice.
  Round 26 differs from the install-log family arcs in that the
  fourth slice is a pure TS helper rather than a backend driver
  (the coverage report has no driver to rewrite — the analyzer
  was already complete from rounds 14/15).
- Shadowed-beats-zero precedence in both the CSV/JSON serialisers
  and the chain-health classifier — every consumer of the diagnostic
  fields uses the SAME priority chain (dead > zero > shadowed >
  healthy). A consumer reading the CSV's "diagnostic" column and a
  consumer reading the envelope's `*_rule_count` totals get the
  same classification.
- The chain-health chip's `empty` kind is filtered out at the
  template level so the cov-summary copy carries the no-samples
  state alone — preventing two chrome elements from both saying
  "no data" in slightly different words. Same principle as the
  retention-overrides empty-state copy.
- 25% fall-through threshold for the warn kind is the "1 in 4
  files = chain is under-specified" heuristic. STRICTLY greater
  (not `>=`) so exactly 25% stays healthy — pinned by a dedicated
  test. Tuneable via opts.fallthroughWarnPct for future surfaces
  (compliance audit chains want stricter; sandbox watches want
  looser).
- The shadowed-noun pluralisation contract ("1 rule is partially
  shadowed" / "2 rules are partially shadowed") requires the verb
  to agree with the noun — the only English-grammar gotcha in the
  copy. The dead + zero branches sidestep this because their
  copies use imperatives ("reorder or tighten the shadowing
  rules") that read fine either way.
