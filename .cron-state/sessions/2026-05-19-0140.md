## Key design decisions documented in the plan

1. **No manifest capability gate for storage.** Per-plugin sqlite
   scoping IS the security boundary — there's no inter-plugin
   namespace a gate would meaningfully protect. Quotas matter more
   than gates here.
2. **No actor round-trip for the JS API.** Sqlite k/v ops are
   microsecond-scale; running them synchronously inside `Mutex::lock()`
   and wrapping the result in `Promise.resolve(...)` keeps the JS API
   shape consistent with `slab.fetch` while massively simplifying
   the implementation. Forward-compatible — we can switch to actor
   bridging later without breaking the public API.
3. **Compile-time const_assert! invariants** between quota constants
   (single-value cap ≤ plugin cap; plugin cap is a clean multiple of
   value cap). If a future change breaks these, the crate fails to
   build — not just a test.
