### Backend
- Schema v10 -> v11: nullable `description` column on `library_tags`.
  Every pre-v11 tag picks up NULL with no rewrite or defaulting.
- `registry::set_tag_description(tag_id, Option<&str>)`:
  - trims the input; trimmed-empty is equivalent to None and clears
    the column back to NULL (so the column only ever holds "real"
    notes — no empty strings persisted).
  - cap is `MAX_TAG_DESCRIPTION_LEN = 500` *Unicode scalars*, not
    bytes, so emoji and CJK each count as one and get a sane budget.
  - `valid_tag_description()` length guard runs BEFORE the UPDATE so
    a rejected oversize leaves the existing description untouched.
  - unknown id errors; success returns the updated TagRecord.
- `TagRecord` widened: new `description: Option<String>` field.
  Every SELECT that returns a tag row was widened to include
  `t.description` so the field travels: `find_tag_by_name`,
  `find_tag_by_id`, `list_tags`, `tags_for_document`,
  `recently_used_tags`, and the `query_documents` tag join.
- One new Tauri command (`slab_library_set_tag_description`) emits
  `library-changed` on success — the rail self-heals via the
  existing `refreshAll` path, no bespoke optimistic plumbing.
- 13 new tests (252 -> 265):
  - v11 schema column test (with the `>=` version-pin convention
    so the next migration doesn't trip an equality assert — the
    trap that bit v3.39 -> bulk-tag).
  - `set_tag_description`: add starts with no description, update
    returns row, trims whitespace, empty/None clears to NULL,
    accepts max length, rejects oversized with row untouched,
    counts chars not bytes (multibyte CJK fits at MAX scalars),
    unknown id errors.
  - Column-drift coverage: persists across `list_tags`,
    `recently_used_tags`, and `tags_for_document`; `rename_tag` and
    `set_tag_color` both preserve description (catches a regression
    if a neighbouring update clobbers the column).

### TS client (bundled with backend per convention)
- `TagRecord` interface gains `description: string | null`.
- New `setTagDescription(tagId, description)` wraps the command,
  same semantics: pass null or empty to clear.

### UI (LibraryPanel.svelte)
- Rail row: new paragraph-glyph button beside pencil/dot/x. The
  `.has-notes` class tints the glyph muted (text-2) by default and
  accent on hover when the tag actually carries a note — so a
  glance at the rail tells you which tags have lore behind them.
- The tag rail row's `title` attribute surfaces the description as
  a tooltip on hover.
- Every per-doc tag chip also gets `title={t.description ?? undefined}`
  so hovering a chip on a doc card shows the same note. Cheap
  because TagRecord already travels with both surfaces.
- Edit-notes modal:
  - Reuses the existing `modal-backdrop` / `modal` chrome so it
    inherits the dark-first look + Escape/click-outside dismissal.
  - Header shows the tag's color dot + name.
  - Textarea bound to the draft, seeded from the current
    description (empty string when unset; backend treats empty as
    "clear" so no sentinel needed).
  - `maxlength` mirrors the 500-char backend cap; a character
    counter sits below and tints red as the user nears the limit.
  - Cmd/Ctrl+Enter submits.
  - Button label flips between "Save" and "Clear" based on whether
    the trimmed draft is empty — makes the destructive action
    explicit instead of silent.
  - On success: swap the updated TagRecord into the rail AND every
    doc card that carries it (no refetch).
  - On rejection (e.g. oversize): keep the modal open, surface the
    backend reason inline, leave the textarea in error state so
    the user can trim and retry — mirrors the rename pattern.
- State: `editDescTag` (null = closed), `editDescDraft`,
  `editDescBusy`, `editDescError`. All $state, scoped to the modal.
