## Process notes worth retaining

- **Same-content-hash test trap**: the embedding index keys by SHA256
  of file contents. Two model buckets seeded in the same test with
  identical filenames produced colliding hashes, so the second model's
  `write_pdf` REPLACED the first (per the pre-existing
  `write_pdf_is_idempotent_replaces_rows` semantics) — the bucket test
  collapsed to one row. Fix: fold `embed_model` into the seeded byte
  stream so distinct models always produce distinct hashes. Caught by
  the batch gate run before unwinding into per-slice commits.
- **Cmd+Shift+B is already taken** (`+page.svelte` line ~592 binds it
  to the Bates panel). Slab convention is to route real keyboard
  shortcuts through `src-tauri/src/keymap/`; ad-hoc letter shortcuts
  inside per-panel handlers collide. Deferred the shortcut and used
  the palette entry + library-changed auto-refresh instead.
- **Snapshot-and-unwind pattern reaffirmed**: build the whole batch
  first for one gate cycle, snapshot final files to /tmp/bc-final,
  reset to HEAD, then re-apply each slice via targeted patches with
  per-slice gate checks before committing. Time cost ~10 min vs one
  mega-commit; revertibility win is worth it. Rounds 5, 6, and 7 have
  all used this pattern successfully.
- **TS module split**: kept the new client in `src/lib/beaconCache.ts`
  rather than appending to `library.ts` because the embedding index
  lives in a different DB file (beacon-index.sqlite vs
  library.sqlite). Cleaner namespaces; mirrors the Rust split between
  `ai::embedding_index` and `pdf::library`.
