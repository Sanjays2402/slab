## Backend (registry.rs)
`merge_tags(source_id, target_id) -> TagRecord`, one transaction:
1. For docs carrying BOTH tags, lift the target link's applied_at to the
   NULL-aware max of the two: `max(coalesce(s,t), coalesce(t,s))` — returns
   the larger when both real, the real one when exactly one NULL, NULL only
   when both NULL. (SQLite scalar max(X,Y) returns NULL if ANY arg is NULL,
   hence the coalesce pair.)
2. `UPDATE OR IGNORE` re-point source-only links onto the target (keeps their
   own stamp; both-tag collisions on the (doc,tag) PK are skipped — already
   handled in step 1).
3. DELETE leftover source links + the orphaned source tag row.
Both ids validated before any mutation, so unknown-id / merge-into-self error
without touching a row. Returns the surviving target.

- "Merge tag" modal: names the source, lists every other tag as a target

  recently-used chips reloaded (target may inherit source's recency).
- Rejected merge keeps the modal open with the backend reason inline.
