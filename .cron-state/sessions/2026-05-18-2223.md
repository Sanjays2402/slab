## Slice 6.5 — Real actor runtime body (BIG)

Replaced the placeholder `run_actor` drain with a full Runtime+Context worker loop:

1. Build `rquickjs::Runtime` + `Context::full(&rt)` on the spawn thread.
2. Install console + `slab.*` global with `lifecycle/active_doc: Some(..)` — `slab.document.*` now live for the first time.
3. Top-level `ctx.eval` under wall-clock interrupt; init handshake via `sync_channel(1)`.
4. Event loop: dispatch each `Persistent<Function>` callback inside fresh `ctx.with` + fresh deadline.
5. `active_doc` set BEFORE OnOpen dispatch, cleared BEFORE OnClose dispatch (handler-intuitive semantics).
6. **Drop order** strictly enforced: `lifecycle.clear()` → `drop(ctx)` → `drop(rt)` on both happy and error paths.

### Key design call-outs
- `ActorSharedState` only carries Send-safe state (registrations + logs). `SharedLifecycle`/`SharedActiveDoc` are worker-thread-local because `rquickjs::Persistent` wraps `*mut JSRuntime` (`!Send`). Plugin code interacts with both via `slab.document.*` on the same thread.
- Per-callback try/catch in `dispatch_lifecycle` — one buggy handler doesn't poison the batch.
- Snapshot `Vec<Persistent>` under the lock, drop the lock, then call — avoids reentrancy deadlock when a callback re-registers via `slab.document.onOpen`.
- `WorkerHandle::shared_state()` exposes `Arc<ActorSharedState>` so Slice 6.7 commands can read registrations after spawn.
