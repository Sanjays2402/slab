### UI (LibraryPanel.svelte)
- New "Saved views" rail section between Folders and Tags.
- "Save filter" affordance in the section head shows ONLY when some
  filter dimension is non-default ($derived `filterIsNonDefault`:
  folder != "all" || any tag selected || untagged || query.trim() ||
  sort != "added_desc"). Saving an empty filter would just be "show
  everything" — not worth a button.
- Save opens an inline name input (Enter commits / Escape cancels)
  seeded from the obvious anchor (folder short name / lone selected tag
  name / "Untagged") so 80% of saves are a one-keystroke confirm.
- Each saved view = rail row with a diamond glyph, the saved name, and
  an x-delete button.
- ONE CLICK on a view restores the entire filter (folder + tags + match
  mode + untagged toggle + sort + search query) in a single batch so the
  existing reactive `$effect` re-queries exactly once. No manual refresh.
- Active-row highlight self-heals: a cheap structural `$effect` compares
  the live rail state to the saved snapshot and clears the highlight as
  soon as the user diverges from any dimension.
- `buildCurrentFilter()` mirrors `refreshDocs()`'s two-branch shape so
  what we save is what gets queried on restore: clause tree when
  `untaggedOnly`, flat folder/tag/title otherwise.
- `restoreSavedView()` reads either shape back into the rail $state
  cells, ignoring exotic clauses the UI can't author so forward-compat
  is automatic.
- UNIQUE name collisions on save surface inline; the form stays open
  with the backend reason so the user can retype + retry.
- Delete confirms with the view name and notes that the underlying
  docs are not affected.
