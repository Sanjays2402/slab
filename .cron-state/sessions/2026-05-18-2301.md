## Slice 6.7 — backend + enable wiring

- New Tauri commands `slab_plugins_document_opened/closed(path, registry)`
  call `PluginRuntimeRegistry::broadcast(RuntimeCmd::Document{Opened,Closed}(ev))`
  where `ev = DocumentEvent::from_path(path)`. Best-effort + async from
  the host's POV.
- `slab_plugins_set_enabled` extended to accept `runtime_reg: State<PluginRuntimeRegistry>`:
  - on enable: if the plugin has `manifest.runtime + script_bytes`, spawn
    a `PluginActor` with the current grants (from `~/.slab/plugin-grants.toml`,
    deny-all default), insert into the registry.
  - on disable: `registry.remove(id)` — drops the `LiveEntry`,
    `WorkerHandle::Drop` Shutdowns + joins the worker thread.
  - declarative-only plugins: no-op spawn path (unchanged behavior).
- 5 new integration tests in `runtime_registry.rs` confirm:
  - broadcast `_opened` reaches 2-plugin onOpen handlers
  - broadcast `_closed` reaches 2-plugin onClose handlers
  - removed plugin is skipped on subsequent broadcasts
  - re-insert under same key cleanly shuts down old actor + only new
    actor receives next broadcast
  - open-then-close sequence fires both handlers in order

  `lastPluginPath` so close always pairs with the matching open.

## Why tearDownDoc fires close BEFORE clearing state

The actor's event loop clears `active_doc` BEFORE dispatching the
`onClose` callbacks (see `run_actor` in `src-tauri/src/plugins/runtime/actor.rs`).
Plugin handlers that call `slab.document.getActive()` inside `onClose`
observe `null` — matching what a plugin author intuitively expects.
The frontend mirrors that ordering.
