## End-to-end capability ready to ship

`pdf::hopper::pipeline::process_one()` is wired end-to-end TODAY against
synthetic inputs:

1. Resolves recipe via injected loader (real loader: Task 5).
2. Calls `pdf::atelier::run::run_recipe` (existing primitive).
3. Asks `TitleProvider` for an AI title (NullProvider for "off",
   Ollama-backed provider wires in lib.rs::setup() in Task 5).
4. Applies rename pattern (`{date}_{ai_title}.pdf`).
5. Atomically moves staged file into `output_dir`, handling
   cross-device renames via copy+remove fallback.
6. Records a `RunRecord` (success/failed/skipped + duration_ms +
   ai_title) into the sqlite log.

Three units verify the loop:
- Smoke: no recipe / no AI → file ends up at `out/Acme_NDA.pdf`.
- AI flow: canned provider returns "NDA Acme Corp" → output ends
  with `_NDA_Acme_Corp.pdf`.
- Collision: pre-existing `Acme_NDA.pdf` → output becomes
  `Acme_NDA (1).pdf` and original is untouched.
