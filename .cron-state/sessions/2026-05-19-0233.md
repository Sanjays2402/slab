## Bugs surfaced and fixed in flight

1. **`resolve_now` was using `Promise.resolve(value)` via the Promise global** —
   rquickjs 0.11 tuple-arg marshalling treated the call as "not an object"
   somewhere in the path. Switched to `Promise::new(&ctx)` + immediate
   `resolve.call((value,))?` — same idiom fetch uses.

2. **Actor never pumped microtasks after the initial `ctx.eval`.** Plugin
   scripts using the canonical `(async () => { ... })()` IIFE idiom would
   suspend on the first `await` and never wake. Fix: after eval succeeds,
   drain `execute_pending_job` to completion (outside `ctx.with` to avoid
   nested-borrow panic in rquickjs's `safe_ref` guard). The fetch path
   continues to pump after each `dispatch_fetch` for out-of-band settlements.
   The initial pump now catches eval-time-settled Promises.

3. **`make_storage_set` was using `Coerced<String>` for the value arg.**
   Doesn't compose with `Function::new` multi-arg deserializer in
   non-leading positions in rquickjs 0.11. Plain `String` works. Comment
   added explaining the diff vs `localStorage` browser semantics.
