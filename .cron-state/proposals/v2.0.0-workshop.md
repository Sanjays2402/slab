# v2.0.0 "Workshop" — TypeScript Plugins Spec

> **Status**: proposal (not promoted to plan yet). Authored by Cake (cron) 2026-05-18 to satisfy STATE.md's pre-flight requirement.

## TL;DR

Slab's plugin system today is **declarative** — plugins ship a `slab-plugin.toml` manifest contributing AI providers, command-palette entries, panel registrations, themes, language packs. The plugin can't *execute code*; everything it does is config-driven.

Workshop changes that. v2.0.0 introduces a **sandboxed JavaScript runtime** (QuickJS via the `rquickjs` crate) so plugins can ship a `script.js` file alongside their manifest and run actual logic — listen to events, transform documents, render custom UI fragments, talk to user-supplied AI providers, contribute new Beacon tools.

This is the inflection where Slab becomes a **platform**, not just an app with config-toggleable features.

## Why this is v2.0.0 (not v1.10)

- **Breaking-ish surface area.** Plugins now have a runtime ABI (`SlabPluginContext`). Manifest schema gains a `runtime` field. Backward compat is preserved (manifests without `runtime` = pure-declarative, same as v1.x) but new plugins must opt into the runtime explicitly, and the contract is permanent — anything we ship in 2.0.0 we're stuck with for the 2.x line.
- **Security model is new.** Plugins now get capabilities (filesystem, network, DOM-fragment rendering). The capability prompt UI is user-visible — first time we ask permission *at install time, not feature-use time*.
- **It's the right marketing beat.** v1.9.2 ships Voice Mode polish; v2.0.0 ships Plugins. A version like 1.10 would underplay the magnitude of the shift.
- **It's what Sanjay parked.** STATE.md `POST-v1.9 ROADMAP REMINDERS` line: "Option A — v2.0.0 'TypeScript Plugins'". This proposal is that.

## Architecture

### Runtime choice: QuickJS via `rquickjs` (0.10+)

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| **QuickJS (rquickjs)** | 200 KB binary delta, no JIT (predictable perf), pure ES2020+, easy sandboxing — drops into Tauri cleanly | No TypeScript runtime — TS is compile-time only (we ship a transpiler in the plugin author SDK, not at runtime) | ✅ Pick this |
| V8 (rusty_v8) | Mature, JIT speed, Node-like ergonomics | 30+ MB binary delta, JIT means more attack surface, complex sandboxing | Reject — too heavy for what we need |
| Wasm (wasmtime) | Language-agnostic (TS, Rust, Go all compile to Wasm), best-in-class sandbox | Plugin authors must learn a Wasm toolchain; Slab plugins shouldn't be that hard to write | Reject — wrong audience |
| Tauri webview (untrusted iframe) | Free, already in the binary | Too much DOM access; sandbox escape risk; not really "plugin code", more "embedded site" | Reject — wrong primitive |

QuickJS wins because plugin authors get the **JavaScript ergonomics they expect** (async/await, modules, JSON) without paying a 30 MB tax or dealing with JIT-side-channel concerns. Plugin TypeScript compiles to ES2020+ JS at plugin-build time using a published `@slab/plugin-sdk` package.

### Plugin lifecycle

```
1. discover_plugin(path)
     → read manifest.toml
     → if `runtime.entry` present:
         load script.js bytes
         compute SHA-256 (pinned in manifest)
         verify against manifest.runtime.sha256

2. spawn_plugin_vm(plugin_id)
     → new rquickjs::Context
     → install globals: console, slab, fetch (gated)
     → eval(script.js)
     → call default_export.init(ctx) if present

3. plugin runtime can:
     → subscribe to events: ctx.on('document.opened', handler)
     → register tools: ctx.registerTool({name, schema, handler})
     → register panels: ctx.registerPanel({id, title, render})
     → call providers: ctx.beacon.ask({prompt})

4. teardown:
     → ctx.dispose() drops the QuickJS context
     → all handlers / panels / tools deregistered
```

### Capability model

Plugins declare capabilities in manifest; user grants on install:

```toml
[runtime]
entry = "script.js"
sha256 = "abcdef..."

[runtime.capabilities]
fs = "none" | "read" | "read-write"      # default: none
fs.allow_paths = ["~/Documents/**"]       # narrowed scope
net = "none" | "specific" | "any"         # default: none
net.allow_hosts = ["api.openai.com"]      # narrowed scope
ui = "none" | "panel" | "tool" | "both"   # default: none
beacon = "none" | "tool-provider" | "ai-provider" | "both"
```

The capability prompt is rendered in the Plugin Cabinet on install, blocking until user accepts. Capabilities cannot be expanded post-install without re-prompting. **Default-deny is the law.**

### Host API surface (the `slab` global)

```typescript
// Stub of @slab/plugin-sdk d.ts (shipped to plugin authors)

interface SlabContext {
  // Events
  on<K extends keyof Events>(event: K, handler: (e: Events[K]) => void): Disposable;

  // Beacon (AI) integration
  beacon: {
    ask(opts: { prompt: string; provider?: string }): Promise<string>;
    registerTool(tool: BeaconTool): Disposable;
    registerProvider(provider: AiProvider): Disposable;  // for user-supplied LLMs
  };

  // UI
  ui: {
    registerPanel(panel: PanelContrib): Disposable;
    registerCommandPaletteEntry(entry: CommandEntry): Disposable;
    notify(opts: { kind: 'info' | 'warn' | 'error'; message: string }): void;
  };

  // Document
  document: {
    getActive(): Promise<DocumentHandle | null>;
    getText(handle: DocumentHandle, opts?: { page?: number }): Promise<string>;
    annotate(handle: DocumentHandle, ann: Annotation): Promise<void>;
  };

  // Storage (per-plugin sqlite namespace)
  storage: {
    get<T>(key: string): Promise<T | null>;
    set(key: string, value: unknown): Promise<void>;
    delete(key: string): Promise<void>;
  };

  // Net (gated by capabilities)
  fetch(input: string, init?: RequestInit): Promise<Response>;
}

interface Events {
  'document.opened': { docId: string; path: string };
  'document.closed': { docId: string };
  'document.page-changed': { docId: string; page: number };
  'beacon.message-sent': { docId: string; text: string };
  'selection.changed': { docId: string; text: string; bbox: BBox };
}
```

These types ship as `@slab/plugin-sdk` on npm. Plugin authors write TypeScript, transpile to ES2020, ship `script.js` + manifest.

## Implementation slices

### Slice 1 — QuickJS embedding + sandboxed `console.log`

**Goal:** Get rquickjs compiling into slab-app; prove we can eval a string and read `console.log` output back into Rust logs.

- Dep: `rquickjs = "0.10"`.
- New module: `src-tauri/src/plugins/runtime_vm.rs` — `struct PluginVm { rt: rquickjs::Runtime, ctx: rquickjs::Context }`.
- Install a `console` global that calls back into `tracing::info!`.
- New IPC `slab_plugin_runtime_eval(plugin_id: String, code: String) -> Result<String>` — dev-mode-only command for quick iteration.
- Unit tests: eval `console.log('hello')` and assert the log buffer caught it.

**Estimated commits:** 4-5. **Test count delta:** +6.

### Slice 2 — Plugin manifest schema bump + script load

**Goal:** Manifest gains `[runtime]` section; loader picks up `script.js`, hashes it, verifies against pinned hash.

- Modify: `src-tauri/src/plugins/manifest.rs` — add `RuntimeManifest { entry: PathBuf, sha256: String, capabilities: Capabilities }`.
- Modify: `src-tauri/src/plugins/loader.rs` — read script bytes, verify sha256, attach to `LoadedPlugin`.
- Backward compat: manifests without `[runtime]` continue to load as v1.x declarative-only.
- Tests: load plugin with `[runtime]`; assert sha256 mismatch is a hard failure (TOFU + pinning).

**Estimated commits:** 3. **Test count delta:** +5.

### Slice 3 — Capability model + grant prompt

**Goal:** First time a runtime-using plugin is enabled, user sees a "this plugin wants: filesystem read, network to api.openai.com" prompt. Denial keeps the plugin loaded but its capabilities are zero.

- New: `Capabilities` struct with serde.
- New: `~/.slab/plugin-grants.toml` — pinned per-plugin-id capability grants.
- Modify: `Cabinet.svelte` — capability prompt modal on first enable.
- Tests: grant persists across restarts; revoke clears it.

**Estimated commits:** 4. **Test count delta:** +6.

### Slice 4 — `slab` global skeleton + lifecycle

**Goal:** Plugin VM spawns on plugin enable; `slab.on(...)` + `slab.ui.notify(...)` work end-to-end.

- Build `SlabContext` wrapper exposed as the global `slab`.
- Wire `ui.notify` to existing toast system.
- Wire `on('document.opened')` to existing event bus.
- Tests: eval a plugin that subscribes to `document.opened`, simulate the event, assert handler ran (use a sync flag accessible from Rust).

**Estimated commits:** 5. **Test count delta:** +8.

### Slice 5 — Beacon tool registration

**Goal:** Plugin can `slab.beacon.registerTool({...})` and that tool becomes available in Beacon's chat mode.

- Existing Beacon tool surface is in `src-tauri/src/beacon/tools/`. Currently hardcoded list; v2.0 makes it a registry.
- Plugin-contributed tools get a `source: 'plugin:<id>'` marker so they're identifiable in logs.
- Capability-gated: tool registration requires `beacon = "tool-provider"` or `both`.
- Tests: register a tool from a plugin script, invoke via Beacon's tool dispatcher, assert plugin handler ran.

**Estimated commits:** 5. **Test count delta:** +7.

### Slice 6 — Panel registration (the hard one)

**Goal:** Plugin can `slab.ui.registerPanel({...})` and Slab renders a custom Svelte-shaped panel using the plugin-supplied render function.

- Approach: plugins return DOM-fragment specs (declarative: `{ kind: 'vbox', children: [...] }`), **not** raw HTML. This keeps the trust boundary clean — no innerHTML escapes.
- New Svelte component `PluginPanel.svelte` walks the declarative tree.
- Limited primitive set (v2.0.0): text, button, input, vbox, hbox, scrollable. Expand in 2.1.x based on plugin author feedback.
- Tests: register a panel, mount, assert DOM matches.

**Estimated commits:** 6. **Test count delta:** +5 + Svelte tests.

### Slice 7 — Network capability + fetch shim

**Goal:** `slab.fetch(url)` works for hosts in the allowlist, returns 403-equivalent for everything else.

- Use `reqwest` on Rust side; expose async via rquickjs promise interop.
- Allowlist enforcement at request time (not just declare time — defense in depth).
- Tests: allowed host returns response; disallowed host throws.

**Estimated commits:** 4. **Test count delta:** +6.

### Slice 8 — Storage namespace + plugin sqlite slice

**Goal:** Each plugin gets its own table in `~/.slab/plugin-store.db`; `slab.storage.{get,set,delete}` works.

- One sqlite file, table-per-plugin (`plugin_<id>_kv`).
- Quotas: 5 MB per plugin to start.
- Tests: get/set/delete roundtrip; quota enforcement.

**Estimated commits:** 3. **Test count delta:** +5.

### Slice 9 — Plugin SDK package (`@slab/plugin-sdk`)

**Goal:** Publish a public npm package with the d.ts shims + a `slab-plugin build` CLI that transpiles TS → ES2020 + computes the manifest sha256.

- New: `packages/plugin-sdk/` directory in monorepo.
- Author flow: `pnpm create slab-plugin my-thing` scaffolds a TS project.
- CLI does ESBuild → single-file ES2020 bundle.

**Estimated commits:** 4. **Test count delta:** +0 (separate package, separate tests).

### Slice 10 — Hello-Workshop sample plugin + docs

**Goal:** Ship a reference plugin in `docs/sample-plugins/hello-workshop/` that demonstrates all the major hooks (event, panel, tool, storage). Documentation page added.

**Estimated commits:** 3. **Test count delta:** integration tests +4.

### Slice 11 — AI provider registration (closes parked v1.3.x item)

**Goal:** Plugins can `slab.beacon.registerProvider({...})` — finally close the long-parked TODO from v1.3.x where plugin-contributed AI providers showed up in the palette but weren't selectable in chat.

### Slice 12 — Release: docs, sample plugin, release notes, version bump

**Goal:** v2.0.0 ships.

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| QuickJS sandbox escape via prototype pollution | Low | rquickjs maintains strict isolation; no shared globals across plugin VMs. Capability-default-deny means even an escape can't reach FS/net without grant. |
| Plugin perf hogs (infinite loop in event handler) | Medium | rquickjs has interrupt callbacks — set a 100 ms hard limit per event handler, log + kill the offending plugin. |
| Plugin author shoots themselves in the foot with sha256 mismatch | High | CLI computes hash automatically at build time. Manual hash maintenance is not a flow. |
| Backwards-compat regression (v1.x plugin breaks on v2.0) | Low | Declarative loader path is untouched. Manifest schema is additive. |
| Capability prompt fatigue | Medium | One prompt per plugin install, not per feature use. Defaults are conservative. |
| Plugin npm package squatters | Low | We don't host npm; authors publish their own. Slab plugins are discovered through the curated index (Foundry), not npm. |

## Estimated total effort

**12 slices × ~4 commits/slice = ~48 commits.** That's roughly 8-12 cron ticks at the current pace (4-6 commits per tick), or 4-6 ticks if we're aggressive (one big slice per tick, 2 slices per "double tick"). Realistic ship window: 2-3 weeks of focused work.

**Test count delta:** +70 backend tests, +integration tests, +SDK tests.

## Open questions (resolve before slice 1)

1. **Plugin signature?** Should `script.js` be signed by the author (Forge precursor) or just hash-pinned (TOFU)? Recommendation: **TOFU for v2.0**, Forge in v2.1.
2. **Hot reload during plugin dev?** rquickjs makes this easy. Yes — ship a `slab-plugin dev` watch mode.
3. **Plugin telemetry?** No telemetry, period. Slab's "private by default" promise is sacred.
4. **Multi-document plugins?** Yes — events emit `docId` so plugins can scope per-doc.

## Ship gate

v2.0.0 doesn't ship until:
- All 12 slices complete + tested
- At least the Hello-Workshop sample plugin works end-to-end
- One real-world third-party plugin (Sanjay or a friend writes one) works
- No clippy/svelte-check warnings
- All 800+ tests passing

## Why ship this

Slab is a great PDF tool with great AI. v2.0.0 makes Slab a **platform** where the long tail of weird, specific, niche workflows can be solved by community plugins instead of waiting for Sanjay to ship them. The PDF tool ecosystem is overdue for this. Obsidian did it for notes, VS Code did it for editing — Slab should do it for documents.
