# v1.3.0 "Foundry" 🛠 — Plugin API

**Goal:** Make Slab community-extensible. Users can drop plugins into
`~/.slab/plugins/<name>/` and Slab will pick them up at startup: custom
commands, custom AI providers, custom themes, custom locales, custom PDF
actions that wrap an external CLI.

**Why "Foundry":** A foundry is where you cast new shapes. Glass II gave
us a11y + i18n + Vim as primitives. Foundry lets the community cast new
shapes from those primitives.

**Architecture (one paragraph):** Plugins are *declarative*, not arbitrary
Rust/JS. A plugin is a directory `~/.slab/plugins/<name>/` containing a
`plugin.toml` manifest plus optional asset files (themes/, locales/,
icons/). At boot Slab scans the dir, validates each manifest against a
strict schema, then merges the plugin's contributions into the running
state — themes register as CSS variable sets, locales extend i18n bundles,
PDF-action plugins register Tauri commands that shell out to an external
CLI, AI-provider plugins inject an entry into the AiProvider registry,
custom-command plugins register palette + keymap entries.

**Sandbox:** None for v1. Plugins declare `permissions = ["fs", "net",
"spawn"]` in their manifest and the user is prompted on first enable. We
don't sandbox the spawned CLIs — same trust model as VS Code extensions.

## Pillars

### Pillar 1 — Plugin format & loader (Slices 1-3)
- `plugin.toml` schema (manifest, contributions, permissions)
- Strict parser with helpful errors
- Discovery loop: scan `~/.slab/plugins/*/plugin.toml`
- Registry held in a Tauri `State` so all backend commands can query it
- Tauri commands for list/enable/disable/reload

### Pillar 2 — Contribution kinds (Slices 4-8)
- **Themes** — CSS variable sets injected at runtime
- **Locales** — extend the i18n bundle map
- **PDF actions** — wrap external CLI (`qpdf`, `gs`, custom scripts) with
  input/output file convention, tempfile handling, timeout
- **Custom commands** — palette + keymap-eligible entries that fire a
  shell command or open a URL
- **AI providers** — declarative OpenAI-compatible endpoint entries

### Pillar 3 — UX & docs (Slices 9-11)
- Plugin panel: list / enable / disable / reload / open dir
- Permission prompt on first enable
- Example-plugins repo (`slab-plugins-examples`) with one of each kind
- `docs/PLUGINS.md` developer guide

### Pillar 4 — Release (Slice 12)
- Lockstep version bump, release notes, merge, tag, push.
