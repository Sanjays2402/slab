# v1.4.0 "Bench" 🪑 — Plugin Marketplace + Signed Manifests

**Goal:** Complete the Foundry story. Users can now *discover* and
*install* plugins from a curated index (not just hand-author them),
with a signature verification step that makes one-click install safe
enough to ship to non-developers.

**Why "Bench":** Plugins are tools; a bench is where you keep your
tools at arm's length. v1.3 gave us the foundry — v1.4 gives us the
bench.

**Architecture (one paragraph):** A first-party plugin index lives at
`https://raw.githubusercontent.com/Sanjays2402/slab-plugins/main/index.json`
(a hand-curated JSON list of `{id, name, version, description,
download_url, manifest_sha256, signature}`). Slab fetches the index,
verifies each entry's `signature` against a hard-coded Ed25519 public
key compiled into the binary, then offers one-click install which:
downloads the tarball, verifies its sha256 matches `manifest_sha256`,
extracts to `~/.slab/plugins/<id>/`, and triggers a registry reload.
Result: every installed plugin from the gallery has provenance back to
the Slab maintainer's signing key. The whole feature reuses every
piece of Foundry (registry, contribution kinds, panel) — the only new
moving parts are an HTTP client, a sig-verify helper, and a
Marketplace tab on the existing PluginsPanel.

**Trust model:** We sign the *index entry*, not the tarball contents.
The index entry binds a plugin ID + version + tarball sha256 to the
maintainer's signature. As long as the public key in the Slab binary
is correct, the user can trust that the tarball they get is the one
the maintainer published. We do *not* sandbox what's inside —
that's the same trust model as Foundry. Bench just adds provenance.

## Pillars

### Pillar 1 — Index format & signature scheme (Slices 1-2)
- `index.json` schema: `{schema_version, signing_key_id, plugins: [...]}`
- Ed25519 signature over each plugin entry's canonical JSON
- Signing tooling in `tools/sign-plugin/` (off-tree, for the maintainer)
- Verifier in `src-tauri/src/marketplace/verify.rs`

### Pillar 2 — Backend marketplace runtime (Slices 3-5)
- `marketplace/fetch.rs` — HTTP GET the index, cache to
  `~/.slab/marketplace-cache.json` for offline
- `marketplace/install.rs` — download tarball, verify sha256,
  extract to `~/.slab/plugins/<id>/`, error-stage on bad sig/hash
- Tauri commands: `slab_marketplace_index`,
  `slab_marketplace_install`, `slab_marketplace_uninstall`,
  `slab_marketplace_check_updates`

### Pillar 3 — UX (Slices 6-8)
- New tab on PluginsPanel: **Browse** (installed | marketplace)
- Marketplace card per plugin: icon, name, version, description,
  author, install button
- Install progress modal + outcome toast
- "Update available" badge on installed plugins when the index has a
  newer version
- Uninstall button on the installed-plugin row

### Pillar 4 — Docs + first index (Slices 9-10)
- `docs/MARKETPLACE.md` — how to submit a plugin to the index
- Seed the `slab-plugins` repo with at least 3 example plugins
  (hello-slab, qpdf-tools, theme-pack)
- Update `docs/PLUGINS.md` to reference the marketplace

### Pillar 5 — Release (Slice 11)
- Lockstep version bump 1.3.1 → 1.4.0, release notes, merge, tag, push

## Slice list (11 slices, each ≤ 5 commits)

1. **Marketplace index schema + Ed25519 verifier** (pure Rust, no HTTP)
   — `marketplace/index.rs` + `marketplace/verify.rs` + unit tests
   against a fixture index signed with a test key
2. **Maintainer signing tool** — `tools/sign-plugin/src/main.rs` CLI
   that takes a plugin tarball + private key file and emits a JSON
   entry ready to paste into `index.json`
3. **Marketplace fetch + cache** — `marketplace/fetch.rs` HTTP client
   that fetches the index and caches it; surfaces stale-cache mode on
   network failure
4. **Marketplace install** — `marketplace/install.rs` downloads tarball,
   verifies sha256, atomically extracts to `~/.slab/plugins/<id>/`,
   rolls back on failure
5. **Tauri commands wired up** — `slab_marketplace_*` in `lib.rs`,
   tied to the Bench state
6. **Frontend: marketplace store + adapter** — `src/lib/marketplace.ts`,
   mirrors of Rust types, snapshot store
7. **Frontend: Browse tab + plugin cards** — extend PluginsPanel with a
   tab strip (Installed / Browse) + card grid + install button
8. **Frontend: install modal + update badges** — progress UI, post-
   install reload, "Update available" pill
9. **Uninstall flow** — backend command + frontend confirmation
10. **Docs + seed `slab-plugins` repo** — `docs/MARKETPLACE.md`,
    submit 3 example plugins to the gh repo
11. **Release** — version bump, release notes, merge, tag, push

## Risks

- **Public key rotation:** We hard-code one public key in the binary
  for v1.4. Future rotation requires a `--signing-key-id` field in the
  index pointing to a different baked-in key. Out of scope for v1.
- **Tarball size:** Plugins are tiny (themes/locales) → < 50KB
  typical. Reject anything > 5MB in `install.rs` to avoid runaway
  downloads.
- **CRLF in cross-platform extracted manifests:** `tar` extraction in
  Rust crate `tar` preserves bytes; we don't text-mode anything. Should
  be fine.

---

## Out of scope

- TypeScript / JS plugins (V8/QuickJS sandbox). Tracked separately as
  a possible v1.5.
- Author-controlled signing (each plugin author signs their own
  releases). v1 keeps the maintainer as the single signer.
- In-app review / star ratings. Not until the index has > 20 plugins.
