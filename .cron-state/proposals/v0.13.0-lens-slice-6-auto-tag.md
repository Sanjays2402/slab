# v0.13.0 Lens — Slice 6: Auto-Tag on Import (Implementation Plan)

> **For Hermes:** Big vertical slice. Execute end-to-end in one tick.

**Goal:** When a document lands in the library (or on demand from the panel), call the
configured Beacon provider with the first few pages of extracted text and ask for
3-5 short, lower-case topic tags. Persist the suggested tags as real `library_tags`
rows and attach them to the doc via `set_doc_tags`. Surface a per-card "✨ Auto-tag"
action and a "✨ Auto-tag N selected" bulk action in `LibraryPanel`.

**Architecture:**
- New `ai::auto_tag` module — provider-agnostic, takes pre-extracted page text,
  returns `Vec<String>` (deduplicated, lower-case, length-clamped, max 5).
- A new `pdf::library::auto_tagger` orchestrator binds extraction → ai call →
  registry writes. No new schema migration needed — tags already exist.
- 2 new Tauri commands: `slab_library_auto_tag_one(doc_id, opts?)` and
  `slab_library_auto_tag_many(doc_ids[], opts?)`.
- TS bindings in `src/lib/library.ts`.
- `LibraryPanel.svelte` gains "✨ Auto-tag" per-card and a toolbar bulk-action that
  drains the registry-stored selection set.

**Tech Stack:** rust (existing `AiProvider`, `pdf::extract`, `pdf::library::registry`),
TypeScript (existing library.ts shape), Svelte 5.

**Prompt design:**
System: `"You are a precise PDF tag generator. You read documents and produce a short, comma-separated list of topical tags. Tags are lower-case, 1-3 words, and concrete. Do not explain. Do not number. Return ONLY the comma-separated list."`

User: built from `chat::build_context(pages, "Produce {N} tags for the document above.", max_chars)`. Temperature: 0.1. max_tokens 64.

**Tests (8):**

2. `parse_lowercases_and_trims` — `"  Finance ,  AI/ML \n"` → `["finance","ai/ml"]`.
3. `parse_dedupes_preserving_order` — `"a, b, a, c"` → `["a","b","c"]`.
4. `parse_drops_overlong` — entries > 32 chars dropped.
5. `parse_caps_at_max` — input has 8, max=3 → 3.
6. `parse_strips_bullets_quotes_numbers` — `'1. "law",  - tax, • compliance'` → 3 clean tags.
7. `parse_drops_empty_and_whitespace_only` — `", ,a"` → `["a"]`.
8. `auto_tag_emits_provider_response` — mock provider returns `"x,y,z"`; assert tags + model echoed + pages_used == pages.len().

**Surface:**
```rust
pub struct AutoTagRunResult {
    pub doc_id: i64,
    pub tags_assigned: Vec<String>,
    pub tag_ids: Vec<i64>,
    pub error: Option<String>,
}

/// Run auto-tag on a single doc.
/// - Extracts text via pdf::extract::extract_text
/// - Calls ai::auto_tag::auto_tag
/// - For each suggested tag: registry::add_tag(name, None) (idempotent)
/// - Calls registry::set_doc_tags with the union of existing + new tag ids
/// - Returns AutoTagRunResult
pub async fn run_one(
    db: &mut LibraryDb,
    provider: Arc<dyn AiProvider>,
    doc_id: i64,
    opts: &AutoTagOpts,
) -> AutoTagRunResult;

/// Run for many docs sequentially; continues past per-doc errors.
pub async fn run_many(
    db: &mut LibraryDb,
    provider: Arc<dyn AiProvider>,
    doc_ids: &[i64],
    opts: &AutoTagOpts,
) -> Vec<AutoTagRunResult>;
```

**Tauri commands:**
```rust
#[tauri::command]
async fn slab_library_auto_tag_one(doc_id: i64, opts: Option<AutoTagOpts>) -> CmdResult<AutoTagRunResult>;

#[tauri::command]
async fn slab_library_auto_tag_many(doc_ids: Vec<i64>, opts: Option<AutoTagOpts>) -> CmdResult<Vec<AutoTagRunResult>>;
```

Each opens the default library DB + loads the configured Beacon provider.

**TS bindings:**
```ts
export interface AutoTagOpts { max_tags?: number; max_context_chars?: number; }
export interface AutoTagRunResult { doc_id: number; tags_assigned: string[]; tag_ids: number[]; error: string | null; }
export async function autoTagOne(docId: number, opts?: AutoTagOpts): Promise<AutoTagRunResult>;
export async function autoTagMany(docIds: number[], opts?: AutoTagOpts): Promise<AutoTagRunResult[]>;
```

**Tests (6):**
1. `run_one_assigns_tags_to_existing_doc` — seed doc, mock provider returns "a,b"; verify 2 tag rows created + attached to doc.
2. `run_one_preserves_existing_tags` — pre-attach tag "X"; auto-tag adds "y"; final set = {X,y}.
3. `run_one_dedupes_existing_tag_by_name` — pre-attach "a"; provider returns "a,b"; final set = {a,b} (no duplicate).
4. `run_one_missing_doc_errors_via_result` — returns AutoTagRunResult with error set, doc unchanged.
5. `run_one_extract_failure_returns_error` — broken pdf path; error populated.
6. `run_many_continues_past_per_doc_failure` — 3 docs, middle one bad path; first + last succeed.

(Tests use `LibraryDb::open_in_memory` + a `MockProvider` like `summary.rs`.)
